# 系统节点手册

系统节点随软件安装，一共七个，分成系统 · 流程控制、系统 · 数据、系统 · 显示三组。它们不改变数据的内容：标记工作流的起点和终点、按条件选择走哪一条路、等待一段时间、给出一个固定值、把结果发布到数据管理面板，以及在画布上直接显示一段文本。从文件读数据、清洗、统计和导出由另一本手册里的节点负责，见[数据分析节点手册](nodes-analysis.md)。

## 节点面板与参数表怎么读

节点从左侧的「Workflow Node / 节点」停靠面板拖到画布上。面板按节点定义里写的分组字符串归类，本章的七个节点落在三个分组：系统 · 流程控制（源码里写作 `System / Flow Control`）、系统 · 数据（`System / Data`）、系统 · 显示（`System / Display`）。分组名随界面语言翻译，节点名始终是英文。

节点名保持英文，是因为它会写进工程文件。存盘时每个节点被记成「包名.类名_序号」的形式，比如 `DASystemNodes.TextViewer_1`，重新打开工程时按这个名字找节点。名字被翻译过，同一个工程换到另一种语言的软件里就对不上了。端口名、参数名同样保持英文。

面板上还有两个和分组有关的功能。右键任意节点选「Favorite / 收藏」，它会被放进「Favorite / 收藏」分组，再右键选「Remove Favorite / 取消收藏」可以移除。面板本身可以在工具箱和树两种显示方式之间切换。当前版本的面板没有搜索框，节点多的时候靠分组和收藏来缩短翻找。

把节点拖到画布之后选中它，右侧「Setting / 设置」面板会出现这个节点的页签，第一页是「Parameters / 参数」；双击节点也会切到这一页。参数值按节点保存，改动只影响当前这个节点，随工程一起存盘，工程存读的做法见[工程文件](../getting-started/project.md)。同一类节点可以在图上放很多个，参数各自独立；摆好第一个之后用复制粘贴，或者按住 Ctrl 拖动复制，可以省去重复填写，细节见[编辑器功能](editor.md)。鼠标停在节点面板的条目上会弹出提示气泡，里面是节点名称和一段英文说明，各小节里「用途」的写法就是这段说明的意思。

### 七个节点一览

下表把本章的节点按分组排开，最后一列是它们的输入输出规模，具体到每个端口的内容见后面各小节。

| 分组 | 节点 | 作用 | 输入端口 | 输出端口 |
|------|------|------|----------|----------|
| 系统 · 流程控制 | Start | 标记起点，送出触发信号 | 无 | 1 个 |
| 系统 · 流程控制 | End | 标记终点，收下上游数据 | 1 个 | 无 |
| 系统 · 流程控制 | If / Else | 按条件选一条路走 | 2 个 | 2 个 |
| 系统 · 流程控制 | Delay | 等待指定秒数 | 1 个 | 1 个 |
| 系统 · 数据 | Constant | 给出一个固定值 | 无 | 1 个 |
| 系统 · 数据 | Output to DataManager | 把数据发布到数据管理面板 | 1 个 | 无 |
| 系统 · 显示 | Text Viewer | 在节点上显示一段文本 | 1 个 | 无 |

### 参数表怎么读

参数表按五列排开，各列的含义固定：

| 列 | 内容 |
|----|------|
| 参数 | 界面「Parameters」页里的字段名，保持英文原样 |
| 类型 | 字段用哪种编辑器，决定能填什么 |
| 默认值 | 从面板拖出新节点时字段里的初值 |
| 取值 | 允许填的内容，枚举型和有范围的参数在这一列列出 |
| 作用 | 这个值会改变什么 |

类型这一列的取值与界面控件的对应关系如下，[数据分析节点手册](nodes-analysis.md)里的表用同一套写法。

| 类型 | 控件 | 填法 |
|------|------|------|
| `str` | 单行文本框 | 普通文本 |
| `int` | 整数框 | 整数，超出范围时框自己夹住 |
| `float` | 小数框 | 小数 |
| `bool` | 复选框 | 勾选为真，不勾选为假 |
| `enum` | 下拉框 | 只能从列出的项里选 |
| `file` | 路径框加浏览按钮 | 文件路径，可以手打，也可以点按钮选 |
| `font` | 字体选择控件 | 字体、字号、粗体、斜体、颜色 |
| `code` | 多行文本框 | 一段 Python 字面量 |

参数填好以后，节点主体上也会用「名称: 值」的形式把它们画一遍，最多画十行，超出时最后画一行省略号。自己接管了主体绘制的节点不画这些行，本章的文本显示节点属于这种情况。参数一改，节点主体上的显示值跟着更新。

数字框的范围由参数定义决定。参数没有规定上下限时，整数框接受 -9999 到 9999，小数框接受 -9999 到 9999 并保留 2 位小数；参数规定了范围的就以参数为准，比如 Delay 的 `seconds` 最小是 0。填超范围的值时，框会把值夹回边界，不会原样保留。

### 参数默认值一览

从面板拖出的新节点带着一组初值，下面把它们集中列出来，方便对照某个参数改没改过。没有列出的节点就是没有参数。

| 节点 | 参数 | 默认值 |
|------|------|--------|
| Delay | `seconds` | `1.0` 秒 |
| Constant | `value` | `1` |
| Output to DataManager | `data_name` | `workflow_output` |
| Text Viewer | `font` | Microsoft YaHei，9 号，不加粗，不倾斜，颜色 `#282828` |
| Text Viewer | `max_text_length` | `200` |
| Text Viewer | `wrap_text` | 勾选，按节点宽度折行 |
| Text Viewer | `log_to_console` | 不勾选，不打印 |

### 端口与连接

端口画在节点两侧，输入在左，输出在右。连线的操作是先点输出端口，再点目标输入端口，详细步骤见[工作流基础](basics.md)。端口只带一个数据类型标签，连接时不做检查，把数值接到需要 DataFrame 的端口上不会被拦住，问题会在运行时暴露出来。同一个输入端口可以接多条线，重复连接同一对端口会被拒绝。

本章的节点用到的标签有两个：`bool` 表示真或假，出现在 Start 的 `trigger` 和 If / Else 的 `condition` 上；`any` 表示什么数据都能过，出现在其余端口上。标签只是给连线的人看的约定，选节点时按它判断上下游能不能搭得上。

### 运行时的状态

运行工作流之后，节点按状态换颜色：还没有轮到的节点是浅黄色，正在执行的是浅绿色，执行成功的是深一点的绿色，执行失败的是红色，被跳过的是灰色，没有参与本次运行的保持原来的样子。这些颜色没有配套的进度条，界面上也不显示百分比，进度只能看节点一格格变色。每次开始运行之前，图上的节点会先统一复位成等待颜色，上一次运行留下的红色不会带到这一次。

执行顺序由连接决定：没有输入连线的节点先跑，有连线的节点等到上游把数据送齐了才执行。执行失败或者抛出异常的节点会变成红色，它下游的节点不会再被触发，同一张图上其它分支的节点照常执行到底。整次运行只要有一个节点失败，结果就算失败，日志里会留下每个失败节点的记录。当前版本没有重试，也没有跳过失败节点的开关，出问题的节点要靠改参数或者修数据来解决，然后整条流程重跑一遍。

整个执行过程在界面线程上同步完成，运行期间点击界面不会得到响应，Delay 节点带来的停顿也发生在这段时间里。点击「Run Workflow / 运行工作流」之前，工程必须已经保存过，没有保存时软件会先提示保存。

一次运行结束后要定位问题，就看红色的节点。日志文件里为每个失败的节点记了一行记录，格式是「Node '<节点 id>' execution exception: ...」，后面的部分是异常文本，前面的节点 id 就是画布上这个节点的存盘名字，比如 `DASystemNodes.TextViewer_1`，拿这个名字回到画布上找对应的节点即可。运行日志的查看方法见[常见故障](../reference/troubleshooting.md)。

## 系统 · 流程控制

这一组决定工作流的走向：从哪里开始、在哪里结束、走哪一条路、等多久。

### Start

Start（起点）标记工作流的入口，没有输入端口，运行时向下游送出一个布尔触发信号，值恒为 True。节点图标是一个细长条加三角形。

Start 没有参数，「Parameters」页是空的，也没有输入端口。

输出端口只有一个：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `trigger` | bool | 启动信号，值始终是 True |

这个值不依赖任何设置，每执行一次就送出一个 True。因为类型是布尔值，它可以直接接到 If / Else 的 `condition` 端口上，两者之间不用再插别的节点。`trigger` 也可以同时接给几个下游节点，一个输出端口引出多条连线是允许的。

一段固定周期的流程用 Start 开头，图面上能一眼看出入口在哪里。`trigger` 恒为真，接到 If / Else 上就得到一条永远走 `true` 分支的通路，将来需要改成按数据判断时，只换条件的来源，两条路都不用重画。

运行本身不要求有 Start 节点：没有输入连线的节点在执行时也会被当作起点跑起来，Start 的作用是把入口画清楚，并给下游一个统一的触发来源。一张图上放多个 Start 也可以，每个都会被当作起点执行。

### End

End（终点）接收上游数据作为完成信号，不产出任何输出，用来在图上标出工作流的终点。

End 没有参数。输入端口只有一个：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `done` | any | 必需 | 上游的完成信号，接任何类型的数据都可以，值本身不被使用 |

End 没有输出端口。接进来的数据在这里被丢弃，节点本身不做任何加工，所以它在或不在都不改变前面的计算结果。

产物已经发布到数据管理面板、或者已经写出文件之后，把最后一步的输出接到 End 上，图面上就有了明确的收尾位置，交接或者评审时容易看出流程到哪里算完整。交给它的内容是表、是计数、还是一段文本都无所谓，因为它只把「上游已经完成」这件事当作信号。

有两条线接进同一个 End 时，要两条线上都有数据送到，End 才会执行；其中一条路上的节点失败了，End 就一直停在等待状态，画布上不会出现流程走完的样子。用这一点可以把两条并排的流程收在一起。下面两条连接表示筛选这一路和导出这一路各自算完，才算整体结束。

```text
Data Filter --filtered--> End
Data Export --success--> End
```

`filtered` 是筛选结果，`success` 是导出是否成功的布尔值，End 都不使用它们的内容，只把它们当作「这条线走完了」的信号。这类收拢的写法适合一条流程同时产出表格和文件的情况：两个产物都完成，图上的 End 才变色。

### If / Else

If / Else（条件分支）按条件把输入的数据送到两条路中的一条，是工作流里唯一的选择结构。节点画成菱形，浅蓝底、蓝边，两处连接点也画成菱形，和矩形的处理节点区分得开。

参数：没有。条件是从端口送上来的，不填在参数里。

输入端口有两个：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `condition` | bool | 必需 | 判断条件。空字符串、0、空列表这类空对象按假处理，其余按真处理 |
| `data` | any | 不必需 | 要转发给下游的数据，一般接 DataFrame |

输出端口有两个，送出的内容都由 `data` 端口决定：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `true` | any | 条件为真时送出 `data`；条件为假时输出空值 |
| `false` | any | 条件为假时送出 `data`；条件为真时输出空值 |

判断规则沿用 Python 的真假转换：0、空字符串、空列表、空字典按假处理，其余按真处理。把 DataFrame 这类没有明确真假的对象接到 `condition` 上时，转换会失败，节点变成红色，这种情况需要在中间放一个能算出布尔值的节点。

「输出空值」的后果要说清楚。执行器只把不为空值的输出顺着连线往下传。没被选中的那一路输出的是空值，执行器不会顺着它继续，那条路上的节点这一次运行不会被触发，连状态都不会从等待变成运行。两条路都画在图上、都连好了线，每次运行只有一条路上的节点真的执行，分支选择就是这样实现的。

`data` 端口没接上游时，两个输出都是空值，下游一条也不会跑。要让它起到分流的作用，`data` 必须有数据来源。想用它单纯挡住一条路、不转发数据，在当前版本里做不到。

内置节点里能送出布尔值的只有两处：Start 的 `trigger`（恒为 True）和 Data Export 的 `success`（导出是否成功）。要让分支跟着数据内容变化，需要一个能按数据算出布尔值的节点，写法见[开发自定义节点](custom-node.md)。

处理一份数据、但不确定是发布到数据管理面板还是写成文件时，用 If / Else 把两条路都画出来。下面把一组连接写成四行，每行是一条连接，左端是输出端口，右端是输入端口。

```text
Start --trigger--> If / Else
Data Source --data--> If / Else
If / Else --true--> Output to DataManager
If / Else --false--> Data Export
```

这四条连接构成一条「发布还是存档」的流程。条件来自 Start 的 `trigger`，恒为真，所以每次运行数据都从 `true` 走，被发布到数据管理面板；`false` 那一侧的 Data Export 一次也不会执行，文件不会产生。把 `condition` 的来源换成别的布尔输出来源，同一条流程就改成按实际情况选路，两条路上的节点不用重画。

### Delay

Delay（延迟）在流程里插入一段等待，等满指定秒数后把输入原样交给下游，用来让前后两步错开时间。

参数只有一个：

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `seconds` | float | `1.0` | 不小于 0，步长 0.1，保留 2 位小数 | 等待的秒数 |

输入端口：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `trigger` | any | 必需 | 触发信号，接什么都可以，数据被原样转发 |

输出端口：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `done` | any | 等满之后把 `trigger` 收到的内容原样送出 |

外部程序定时写出文件，而流程要在两次写出之间空出一段时间时，把 Delay 插在需要隔开的两步中间，把 `seconds` 调成需要的时长。它原样转发输入，传给下游的数据格式不用跟着改。填 0 表示不等待，小数可以用，比如 `0.5` 表示半秒。

这个节点只加等待，不改数据，也不检查数据内容，任何类型的数据都能穿过它，因此它在流程里的位置可以随意调整。等待从 `trigger` 收到数据的那一刻开始计时，上游没送数据进来时它不会凭空开始等待，节点停在等待颜色。等待期间它在画布上显示为运行中的颜色，`done` 端口要等时间走完才把数据送出去，下游节点因此也会比平时晚开始。

等待时间由整个工作流承担。执行在界面线程上同步完成，`seconds` 填 60 就是界面停住 60 秒，设置等待时长前先确认这个代价可以接受。

## 系统 · 数据

这一组只有两个节点，一个给出数据，一个收下数据。

### Constant

Constant（常量）输出一个固定值，值用 Python 字面量的写法填写，适合给下游提供一份不随数据变化的内容。

参数只有一个：

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `value` | code | `1` | Python 字面量：`1`、`1.5`、`'hello'`、`[1, 2, 3]`、`{'a': 1}`、`True` | 要送出的值 |

求值用的是 Python 的字面量解析：数字写成 `1` 或 `1.5`，字符串带上引号写成 `'hello'`，列表、字典、布尔值按 Python 的写法写，内容可以占多行。解析不成功时整段内容按原样的字符串送出，所以不带引号直接写一段文字也能用。

字面量解析只认常量，不做运算。`value` 里写 `1 + 1` 得到的是文本 `1 + 1`，不是数字 2；想要算出来的结果，得在后面的节点里用表达式计算。列表少写一个方括号、字典漏掉一个引号，同样不会报错，整段内容会以文本形式送给下游，节点本身仍然是成功状态，这类写法问题要自己在文本显示节点上核对。

Constant 没有输入端口。输出端口只有一个：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `value` | any | 解析后的常量值 |

内置的数据分析节点，参数都在设置面板里填，端口只传数据，所以常量的典型用法是接到文本显示节点上，在画布上留一段固定的说明，比如流程版本号、数据来源、处理人；也可以给自定义节点当输入，把阈值、列名这类固定信息从代码里挪到图上。它的 `value` 会画在节点主体上，填了什么在画布上直接能读到。

同一张图上放多个常量互不影响，每个节点的 `value` 各自保存。常量没有输入端口，不会被上游触发，也不会因为下游断开连接而停止输出，每次执行都送出一份同样的值。

### Output to DataManager

Output to DataManager（输出到数据管理）把输入的数据发布到数据管理面板，成为一份有名字的数据集。工作流的最终结果通常停在这个节点上。

参数只有一个：

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `data_name` | str | `workflow_output` | 文本 | 数据集在数据管理面板里显示的名字 |

输入端口：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `data` | any | 必需 | 要发布的数据，一般是 DataFrame |

这个节点没有输出端口，成功与否只反映在节点的状态颜色上。要接着往下处理这批数据，得从上游那个节点另接一条线出去，不能从这个节点取数据。

发布之前先按名字在数据管理面板里查一遍，比较区分大小写。查到同名数据集时，直接把那份数据集的内容换成输入的数据，不新建条目；查不到时才新建一份，名字取 `data_name`。这是反复运行同一套流程却始终只有一份结果的原因：`data_name` 固定写 `clean_data`，每次运行刷新的都是 `clean_data` 这一份，已经打开的表格视图会收到变更通知并刷新，显示的就是本次运行的结果，不用关掉再重新打开。名字里的字母大小写不同会被当作两份数据，`Clean_data` 和 `clean_data` 会各占一条。`data_name` 留空时按默认名 `workflow_output` 处理。

覆盖的方向只有一个：运行工作流会刷新数据集，在表格视图里改动这份数据不会反过来影响工作流。在表格里手工改过的内容，下一次运行会被新的结果替换掉。

流程稳定下来以后把 `data_name` 定成一个好认的名字，之后调整前面的参数重新运行，都在数据管理面板的同一个位置看结果，比对两次运行的差别时省去翻找。名字也会出现在数据集的导出和删除操作里，取一个能说明内容的名字比默认值好用。数据集的查看和重命名见[数据管理面板](../data/manager.md)。

## 系统 · 显示

这一组只有一个节点，作用是把数据直接摆在画布上看。

### Text Viewer

Text Viewer（文本显示）把接进来的任何数据转成文本，显示在节点主体上，在流程中间检查一步的结果时用它，不用切到表格视图。

参数有四个：

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `font` | font | 字体 Microsoft YaHei，字号 9，不加粗，不倾斜，颜色 `#282828` | 字体、字号、粗体、斜体、颜色 | 节点上文字的字体设置 |
| `max_text_length` | int | `200` | 不小于 1 | 文字的最大字符数，从第 201 个字符起截掉，末尾补一个省略号 |
| `wrap_text` | bool | 勾选 | 勾选、不勾选 | 勾选时按节点体宽度折行；不勾选时只按文本里的换行符分行，超过节点宽度的部分被裁掉 |
| `log_to_console` | bool | 不勾选 | 勾选、不勾选 | 勾选时每次执行把这段文字打印到日志 |

`font` 是一个字体字典，键分别是 `family`（字体族）、`size`（字号）、`bold`（粗体）、`italic`（斜体）、`color`（颜色）。界面上的字体控件改的就是这几个键，`color` 接受 `#RRGGBB` 形式的颜色值。

截断发生在显示这一端，数据本身不动，只是画出来的文字在设定字符数处断开。把 `max_text_length` 调大能看到更多内容；文字总行数超过节点体高度时，下面几行不会被画出来。折行按像素宽度计算，一个汉字占的宽度比一个数字大，同样长度的中文和数字折行位置不一样。关闭 `wrap_text` 之后，只有文本里带的换行符会换行，长行超出节点体边界的部分被裁掉。

输入端口：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `value` | any | 必需 | 要显示的数据，任何类型都可以，内部先转成文本 |

这个节点没有输出端口。没有数据时节点上显示「(no data)」。接进来的是表时，先由 pandas 转成文本再按 `max_text_length` 截断，所以长表只会显示开头一段。数字、布尔值、列表这些也会各自按 Python 的文本形式画出来。

节点上这段文字会随工程保存。执行过一次以后，显示内容被写进工程文件，重新打开工程时不用再运行就能看到上次留下的文字；反过来，改了参数但没有重新运行，看到的仍然是上一次运行留下的内容。字体、字号、颜色这些参数随时改随时生效，只有文字本身要等下一次执行才更新。

这个节点自己接管了主体绘制，所以它不画「名称: 值」的参数行，节点本身的最小尺寸是 150 × 80 像素。内容看不全时，把节点拉大、调大 `max_text_length`、再关掉自动折行，几处配合起来能多显示一些。

某个中间步骤对不对，不必把结果发布到数据管理面板再打开表格，直接把上游节点的计数输出接到 Text Viewer 上，运行完就在画布上读到数字。下面两条连接把读进来的行数和筛掉的行数同时摆到画布上。

```text
Data Source --row_count--> Text Viewer
Data Filter --removed_count--> Text Viewer
```

`row_count` 是读进来的行数，`removed_count` 是筛选节点删掉的行数，两者都是整数，文本显示节点把它们转成文本画在各自的主体上，两个节点互不干扰。检查筛选结果时看一眼这两个数字，就能确认数据量对不对，再把结果发布出去。勾选 `log_to_console` 之后，每次执行还会把这段文字打印一次，内容进日志文件，不出现在「Log / 消息」面板里，适合与日志里其它节点的记录放在一起看。

## 把节点串起来

节点在画布上的摆放不决定执行顺序，决定顺序的是连线。下面几条规则在搭流程时会反复碰到。

数据只能从输出端口流向输入端口。Start、Constant 这类没有输入端口的节点只能作为流程的开头，它们放的个数不限，每个都会执行。End、Output to DataManager、Text Viewer 这类没有输出端口的节点是流程的末端，数据到它们为止，要接着处理就得从上游另引出线来。

一个节点的输出可以接给多个下游节点，同一份数据会沿每一条连接各送一次；同一个输入端口也能接多条线，这时端口里留下的是最后送到的那份数据，节点要等所有接进来的上游都送到之后才执行。

端口不做类型检查。把布尔值接到期待 DataFrame 的端口上不会被拦住，节点会在执行时报错变红，返回值、计数这类输出接到表格处理节点上也是同样的结果。

计数输出可以当普通数据往下传。行列数、删掉的行数、命中行数都可以接到文本显示节点上，运行时在画布上读。

连线画成环时，环上的节点会因为收不到足够的数据而一直停在等待颜色，执行不会绕回去把已经跑过的节点再跑一次。要重复处理同一批数据，把流程复制一份接在后面，不要靠回环。

参数在节点执行的那一刻读取。改完参数之后，画布上的节点主体会立刻显示新值，数据本身要等下一次运行才会按新参数重算；上一次运行发布出去的数据集、写出的文件都保持原样，直到重新运行把它们刷新。这一点在对比两套参数的效果时有用：改一处、跑一次、看结果，图上不会同时存在两份数据。

最小的一条流程可以只做「读文件、筛一遍、发布结果」三件事。下面四条连接画出了这样的流程，其中两条从同一个筛选节点引出。

```text
Constant --value--> Text Viewer
Data Source --data--> Data Filter
Data Filter --filtered--> Output to DataManager
Data Filter --removed_count--> Text Viewer
```

第一条连接给画布添一段固定说明，第二条把读进来的表交给筛选节点，第三条把筛完的结果发布到数据管理面板，第四条把筛掉的行数显示出来。运行时按「Run Workflow / 运行工作流」，先看到节点依次变色，结束后在数据管理面板里找发布出来的数据集。改一处参数再运行一次，发布出来的还是同一份数据集，内容换成新的结果。

### 搭这条流程的步骤

下面按顺序列出这条流程的搭建动作，每一步都对应界面上的一次操作。

1. 从「Workflow Node / 节点」面板把 Data Source、Data Filter、Output to DataManager、Text Viewer 依次拖到画布上，按数据由左向右的流向摆开。
2. 选中 Data Source，在「Parameters / 参数」页把 `file_path` 指到目标文件，`file_type` 改成和文件一致的格式。
3. 点一下 Data Source 的 `data` 输出端口，再点 Data Filter 的 `data` 输入端口，第一条线就连好了。
4. 选中 Data Filter，把 `condition` 填成筛选表达式。
5. 用同样的方法把 Data Filter 的 `filtered` 接到 Output to DataManager 的 `data`，再把这个节点的 `data_name` 改成好认的名字。
6. 把 Data Filter 的 `removed_count` 接到 Text Viewer 的 `value`。
7. 保存工程，点「Run Workflow / 运行工作流」。
8. 运行结束后在左侧「Data Manager / 数据管理」面板里找到这个名字，双击打开表格视图；Text Viewer 上显示这次筛掉了多少行。

连错线或者拖错节点可以撤销。节点的移动、连线的增删、复制粘贴都在撤销范围内，按 Ctrl+Z 退回上一步，细节见[工作流基础](basics.md)。

## 和数据分析节点的分工

本章的七个节点不改变数据内容：它们安排顺序、提供固定值、显示中间结果、把结果放进数据管理面板。表格处理在[数据分析节点手册](nodes-analysis.md)里，碰到下面这些需求时换那里的节点。

| 需求 | 节点 |
|------|------|
| 从 CSV、Excel、JSON、Parquet 文件读数据 | Data Source |
| 按条件筛行 | Data Filter、Query |
| 保留某一列的一段取值 | Filter By Column、Threshold Filter |
| 去重、补缺失值、处理异常值 | Drop Duplicates、Drop NA、Fill NA、Interpolate、Remove Outliers IQR、Remove Outliers Z-Score |
| 生成新列、整体变换 | Eval Expression、Data Transform、Transform Skewed |
| 汇总 | Describe、Pivot Table |
| 写出文件 | Data Export |
| 出一张快速预览图 | Data Plot |

两个包的节点可以放在同一张图上，用同一种方式连接，端口之间也没有额外的约束。

## 常见问题

### 运行之后节点变成红色

节点执行返回失败、或者执行过程中抛出异常时，画布上把它显示成出错颜色，这一路上的下游节点都不会执行。常见原因是 Data Source 的 `file_path` 没有填或者文件已经不在原位置，以及参数写法不符合要求。出错的具体信息记录在日志文件里，消息面板中不会出现。

### If / Else 两条路都接好了，为什么一条路上的节点都没跑

先看 `data` 端口有没有上游。两个输出送出去的都是 `data` 收到的内容，`data` 没接时两个输出都是空值，执行器不会顺着空值往下传，两条路上的节点都不会被触发。

### Delay 设了几十秒，界面一直没有反应

工作流在界面线程上同步执行，等待时间就是界面不响应的时间。等满设置的秒数后流程会继续往下走，不需要额外操作。

### 数据管理面板里出现了两条看起来同名的数据

名字比较区分大小写，`Data` 和 `data` 是两条。核对两处 `data_name` 的写法是否完全一致。

### 图上放了两个 Output to DataManager，它们能不能用同一个名字

可以，但两份数据会落在同一条数据集上：两次发布按执行顺序发生，后执行的那一次把前一次的内容换掉，最后看到的是后执行的那个节点的结果。想同时留下两份，把两处的 `data_name` 取成不同的名字。

### 一张图上能不能放几条互不相干的流程

可以。从数据来源节点开始各自铺开就行，几路数据靠连接区分，不靠位置。运行时每条路都会被走到，其中一条失败不影响另一条跑完，整次运行的结果仍然记为失败。

### Delay 的秒数填 0 会怎样

不等待，数据立刻往下传。填小数也可以，比如 `0.5` 表示半秒，界面上的框按 0.1 的步长增减。

### Constant 里写了一个算式，输出的是算好的值吗

输出的还是文本。Constant 只解析字面量，`1 + 1` 会以文本 `1 + 1` 的形式送出去；要算出来的值，把这一段内容接给 Eval Expression 之类的节点处理。节点不会因为内容看起来像算式就报错，它原样把文本送给下游，问题要到下游才暴露。

### 文本显示节点上看不到参数值

这个节点自己接管了主体绘制，参数不会以「名称: 值」的形式画在节点上。要改参数就选中节点，在右侧「Parameters / 参数」页里改。

### 运行结束了，为什么还有节点停在浅黄色

浅黄色表示等待中。停在等待颜色的节点通常是没收到数据：上游节点失败了，或者上游的这个输出本来就没有数据，比如 If / Else 没被选中的那一路。改好上游的参数重新运行一次，颜色会从头刷一遍。

### 节点面板里找不到某个节点

节点来自随软件安装的节点包，包在插件管理器里被停用之后，它的节点就不出现在面板里。插件管理器里的 Python 节点包分组标注了「changes take effect after restart / 重启后生效」，改过启用状态要重启软件。工作流正在使用某个包的节点时，插件管理器会拒绝把它停用。
