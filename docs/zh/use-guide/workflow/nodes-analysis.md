# 数据分析节点手册

这二十一个节点随软件安装，来自数据分析节点包，把 pandas 的常用操作包成节点：读文件、筛行、清洗、汇总、导出、出一张快速预览图。它们按数据分析、数据清洗、数据操作三组排在「Workflow Node / 节点」面板里，和工作流里的其它节点用同样的方式连接。表格上下文标签里那些清理对话框用的也是这一套实现，同样的操作在工作流里做一次，和在表格上点一次，算法一致。

工作流的两个数据通道都落在这里：读文件的入口只有 Data Source，别的节点都不能按名字去数据管理面板里取一份已经存在的数据集；写出结果的出口有两个，Data Export 落成文件，Output to DataManager 发布到数据管理面板。中间的处理节点把一个 DataFrame 加工成另一个 DataFrame。

## 读这些节点之前的约定

参数表的列、编辑器类型与界面的对应关系写在[系统节点手册](nodes-system.md)里，本章的表沿用同一套写法，参数名和默认值都按源码里的定义列出。

### 按需求选节点

下面这张表把这二十一个节点按使用目的排开，找不到方向时先在这里定位。

| 要做的事 | 用哪个节点 |
|----------|------------|
| 从文件读数据 | Data Source |
| 按条件筛行 | Data Filter、Query |
| 按一列的取值区间筛行 | Filter By Column、Threshold Filter |
| 在文本列里找出含特定文字的行 | Search |
| 删掉含空缺的行或列 | Drop NA |
| 把空缺补出来 | Fill NA、Interpolate |
| 删重复行 | Drop Duplicates |
| 处理异常值 | Remove Outliers IQR、Remove Outliers Z-Score |
| 替换某个取值 | Replace Values |
| 改列名、删列、填一列的空缺 | Data Transform |
| 把偏斜的分布调对称 | Transform Skewed |
| 生成新列 | Eval Expression |
| 排统计摘要 | Describe |
| 分组汇总 | Pivot Table |
| 排序 | Sort |
| 写成文件 | Data Export |
| 出一张快速预览图 | Data Plot |

### 输入与输出约定

除 Data Source 之外，本章每个节点都只有一路输入，端口名叫 `data`，数据类型标为 `DataFrame`，都是必需端口。接进一个整数或者一段文本时，节点在用到表结构的那一步会失败，画布上变红。输出端口的名字各不相同，接下游时要看清是哪一个：处理结果一般叫 `cleaned`、`filtered`、`filled`、`transformed`、`result`、`sorted` 这种带含义的名字，计数结果单独占一个端口。

计数类的输出和数据处理结果是两条并行的通道。`removed_count`、`replaced_count`、`match_count`、`row_count` 给出的都是整数，可以接到 Text Viewer 上在画布上读，也可以接到 If / Else 的 `data` 端口上参与分支，但拿它们当表格继续处理没有意义。

### 计数结果数的是什么

| 端口 | 出现的位置 | 数的是什么 |
|------|------------|------------|
| `row_count` | Data Source | 读进来的行数 |
| `row_count` | Query | 查询结果的行数 |
| `removed_count` | Data Filter、Drop NA、Remove Outliers IQR、Remove Outliers Z-Score、Threshold Filter、Filter By Column | 处理前后行数的差；Drop NA 在删列模式下是删掉的列数 |
| `replaced_count` | Replace Values | 被替换掉的单元格数量 |
| `match_count` | Search | 命中的行数 |

### 数据从哪来，结果去哪

读文件的入口只有 Data Source 一个节点，整个工作流里没有别的节点会去读磁盘或者按名字取数据管理面板里的数据集。已经在数据管理面板里、想拿进工作流继续处理的数据，先从面板上导出成文件，再用 Data Source 读进来，或者在流程开头重新从原始文件读一遍。

一个工程里的多个工作流互相独立，每个占一个标签页，节点和数据不会互相传递。两个工作流之间要交换中间结果，用 Data Export 写成文件，另一个工作流用 Data Source 读这个文件。

结果的去处有两个。Data Export 把表写成文件，交给别的软件或者留档；Output to DataManager 把表发布到数据管理面板，用软件的表格视图看、改、再导出成别的格式。流程里的中间结果不需要落到这两处，直接接下一个节点就行。

一个处理结果可以同时接给多个下游。下面两条连接把清洗结果一份发布到面板、一份写成文件，两条路用的是同一份数据。

```text
Remove Outliers IQR --cleaned--> Output to DataManager
Remove Outliers IQR --cleaned--> Data Export
```

发布那一路适合接着在软件里看和改，写文件那一路适合交给外部程序，两边的参数各自填写，互不影响。同一个端口接给三个以上的下游也是允许的。

### 六个筛行节点的分工

名称里带筛选、过滤、查找的节点有好几个，判断方式各不相同，混用时会得到意外的行数。下面的表把它们并排摆开。

| 节点 | 判断方式 | 与取值区间的关系 | 送出的结果 |
|------|----------|------------------|------------|
| Data Filter | pandas 查询表达式；表达式留空时按一列的非空值筛 | 区间写在表达式里 | `filtered`、`removed_count` |
| Query | pandas 查询表达式 | 区间写在表达式里 | `result`、`row_count` |
| Filter By Column | 一列的取值区间，两端包含 | 一次给出上下界，0 表示不限制 | `filtered`、`removed_count` |
| Threshold Filter | 一列和阈值的单次比较，成立的行被删掉 | 一条界线，区间要串两个节点 | `filtered`、`removed_count` |
| Search | 文本列上的正则匹配 | 与数值区间无关 | `result`、`match_count` |
| Drop NA | 空缺的位置和数量 | 与数值区间无关 | `cleaned`、`removed_count` |

条件复杂时用表达式，Data Filter 和 Query 都支持；区间固定、两端都不为 0 时用 Filter By Column 少写一段表达式；只卡一条界线时用 Threshold Filter；按文字内容找行用 Search；按空缺多少删行用 Drop NA。

### 参数改动的生效时机

参数在节点执行的那一刻读取。改完之后要重新运行工作流，数据才会按新参数重算；上一次运行发布出去的数据集、写出的文件在重新运行之前保持原样。

## 数据分析（Data Analysis）

这一组负责流程的两头：把文件读成表，把表写成文件，中间夹一个筛选和一个画图的节点。

### Data Source

Data Source（数据源）从文件读数据，是工作流里唯一能把磁盘上的文件变成 DataFrame 的节点，支持 CSV、Excel、JSON、Parquet 四种格式。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `file_path` | file | 空 | 文件路径 | 要读取的文件。浏览按钮的过滤器依次是 All Supported、CSV Files、Excel Files、JSON Files、Parquet Files、All Files |
| `file_type` | enum | `csv` | `csv`、`excel`、`json`、`parquet` | 用哪一种读取方式 |
| `encoding` | str | `utf-8` | 编码名 | 仅 CSV 生效，交给 pandas 的文件编码 |
| `separator` | str | `,` | 分隔符 | 仅 CSV 生效，字段分隔符 |
| `sheet_name` | str | `0` | 工作表名或序号 | 仅 Excel 生效，`0` 表示第一张工作表 |

五个参数里只有 `file_path` 和 `file_type` 对所有格式都生效。`file_type` 选 csv 时 `encoding` 和 `separator` 参与读取，选 excel 时 `sheet_name` 参与，选 json 和 parquet 时另外三个参数都用不到。读取方式只看 `file_type`，与文件后缀无关：把一个 xlsx 文件选成 csv，节点会当成纯文本去解析它，通常读不出想要的结果。

从别的软件导出的 CSV 常用 GBK 编码，读进来中文变成乱码时，把 `encoding` 改成 `gbk` 再运行。分隔符不是逗号的表格，把 `separator` 改成对应的字符。

Data Source 没有输入端口，它在图上只能是流程的开头。输出端口有三个：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `data` | DataFrame | 读进来的表 |
| `row_count` | int | 这张表的行数 |
| `file_type_out` | str | 本次实际使用的格式 |

`file_path` 留空、路径上的文件不存在、或者读取过程出错时，节点执行失败，画布上变红，下游的节点收不到数据。

`file_type_out` 是本次实际使用的格式，接到文本显示节点上就能看到。参数里的 `file_type` 和文件后缀不一致时，这个值会把它暴露出来，排查读不到数据的原因时先看它一眼。

要读文件的流程，开头都是 Data Source。读进来之后先用 Text Viewer 看一下 `row_count`，确认行数和文件对得上，再接后面的处理节点，可以省去从头排查一遍的时间。文件本身也可以先导入进来看看，导入方法和各格式的选项见[导入数据](../data/import.md)。

### Data Filter

Data Filter（数据筛选）用 pandas 的查询表达式筛掉不要的行，表达式留空时改按某一列的非空值筛。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 表达式留空时，用它筛出这一列不是空值的行 |
| `condition` | str | 空 | pandas 查询表达式 | 筛选条件，写法见下 |

两个参数按先后顺序生效。`condition` 有内容时用表达式筛行；`condition` 留空而 `column` 有内容时，保留这一列不是空值的行；两个都空时数据原样通过。

表达式是 pandas 的 query 语法，列名直接写，字符串值用引号包起来，多个条件用 `and`、`or` 连接。`amount > 1000`、`city == "北京"`、`amount > 1000 and city == "北京"` 都是合法写法。表达式里的列名不存在、运算符用得不合法时，节点执行失败，这时先检查列名是不是写成了别的名字。

输入端口：

| 端口 | 数据类型 | 是否必需 | 接收什么 |
|------|----------|----------|----------|
| `data` | DataFrame | 必需 | 待筛选的表 |

输出端口：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `filtered` | DataFrame | 筛选之后的表 |
| `removed_count` | int | 被筛掉的行数，等于输入行数减输出行数 |

读进来的订单表里只想留下金额超过 1000 的部分，并把结果发布到数据管理面板。下面两条连接就是这件事的全部配置，第二行把筛掉的行数接到文本显示节点上看。

```text
Data Source --data--> Data Filter --filtered--> Output to DataManager
Data Filter --removed_count--> Text Viewer
```

`condition` 填 `amount > 1000`，Output to DataManager 的 `data_name` 填一个固定的名字，比如 `orders_over_1000`。运行一次之后，这份数据集就在数据管理面板里了；改一改阈值再运行，刷新的是同一份数据集，已经打开的表格视图会跟着变。`removed_count` 那一路上，文本显示节点会告诉这次筛掉了多少行，阈值调得过严时会立刻看出来。

### Data Transform

Data Transform（数据变换）对某一列做三种小改动之一：改列名、删列、填这一列的空缺。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 操作的目标列。留空时数据原样输出 |
| `operation` | str | `rename` | `rename`、`drop`、`fillna` | 做哪一种操作 |
| `new_name` | str | 空 | 列名 | `rename` 用的新列名，留空时不改动 |
| `fill_value` | str | `0` | 任意值 | `fillna` 用的填充值，能转成数字的按数字填 |

三个操作共用一个节点，按 `operation` 的写法决定用哪些参数。`rename` 把 `column` 改名成 `new_name`；`drop` 删掉 `column` 列，另外两个参数用不到；`fillna` 用 `fill_value` 填 `column` 列的空缺。

`operation` 是文本框，要手打这三个词之一。写别的词时数据原样输出，节点仍然算执行成功，不会报错，填错了要自己在结果里核对。

输入端口同上一节，输出端口是 `transformed`，送出变换后的表。

列名是一长串中文或者带空格、括号时，后面写查询表达式和排序都很麻烦，先用 `rename` 把它们改成简短的名字，再往下接别的节点。清空某一列的空缺也可以用这里的 `fillna`，它只处理一列；要按不同规则填多列，用另一组清洗节点。

### Data Export

Data Export（数据导出）把表写成文件，支持 CSV、JSON、Excel、Parquet、Feather 五种格式。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `file_path` | file | 空 | 文件路径 | 导出到哪个文件。过滤器依次是 All Files、CSV Files、JSON Files、Excel Files、Parquet Files、Feather Files |
| `export_format` | enum | `csv` | `csv`、`json`、`excel`、`parquet`、`feather` | 写成哪一种格式 |

输出端口有两个：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `success` | bool | 导出是否成功 |
| `file_path_out` | str | 实际写出的文件路径 |

路径里的目录不存在时，节点会把目录建出来，不必提前手动创建。写成 CSV 和 Excel 时不写行号，Feather 会把行号一起存进去，JSON 里的中文不做转义，直接可读。写 Excel 需要 openpyxl，写 Parquet 和 Feather 需要 pyarrow，这两个库在项目根目录的 Python 依赖清单里列出。CSV 不带行号，所以写出的文件再用 Data Source 读回来时，行号会重新生成，列的顺序和内容不变。

`file_path` 留空、写出的过程出错时，节点执行失败，`success` 输出假值。把这个布尔值接到 If / Else 的 `condition` 上，可以做「导出成功才继续」的判断。

流程的产物要交给别的软件使用时，把路径定成一个固定的文件，每次运行覆盖它，对方只要读同一个路径就行；同时需要存档时，再单独接一个 Output to DataManager，把结果留在数据管理面板里。导出的选项和批量导出的做法见[导出数据](../data/export.md)。

### Data Plot

Data Plot（数据绘图）用 matplotlib 出一张柱状图、折线图或散点图，存成 PNG 图片。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 画哪一列，三种图型的用法不同 |
| `chart_type` | str | `bar` | `bar`、`line`、`scatter` | 图表类型 |

输出端口只有一个：

| 端口 | 数据类型 | 送出的内容 |
|------|----------|-----------|
| `figure_path` | str | 图片文件的完整路径 |

三种图型的画法不同。`bar` 统计 `column` 这一列各取值的出现次数，画成柱状图；`column` 留空或者不在表里时，把整张表的所有数值列各画一组柱子。`line` 把 `column` 这一列按行号连成折线；`column` 留空时画整张表。`scatter` 需要至少两个数值列，`column` 决定横轴，它不在数值列里时改用第一个数值列，纵轴取第二个数值列；数值列少于两个时图上只会出现一行提示文字。

图片固定写到系统临时目录，文件名按图型命名，分别是 `data_plot_bar.png`、`data_plot_line.png`、`data_plot_scatter.png`，分辨率是每英寸 150 点。同一种图型每次运行覆盖同一个文件，文件名里没有列名，换一列重画会覆盖上一次的图。图不显示在软件里，只写文件，看图的路径由 `figure_path` 带出来。

这个节点只在 matplotlib 能成功导入时存在。装不上 matplotlib 的环境里，节点面板中看不到它，这两个参数和这个输出端口也就不存在。

工作流跑完想立刻看一眼分布时，把绘图节点挂在流程末端，再把 `figure_path` 接到 Text Viewer 上，画布上就会显示图片的位置。下面这条流程把筛选后的数据画成柱状图，并在画布上给出文件路径。

```text
Data Source --> Data Filter --> Data Plot --> Text Viewer
```

这里 `Data Filter` 的 `filtered` 接给 `Data Plot` 的 `data`，`Data Plot` 的 `figure_path` 接到 `Text Viewer` 的 `value`。运行结束后打开那个 PNG 文件查看图形，工作流本身不渲染图片。要出论文级的图表，用绘图功能建出来的图表，它们可以反复调整样式并导出矢量图，做法见[创建图表](../chart/create.md)。

## 数据清洗（Data Cleaning）

这一组处理表里的重复、缺失和异常，共九个节点。它们都不改列的结构，除了删列的情形，行数和单元格内容会变。

### Drop Duplicates

Drop Duplicates（删除重复行）去掉表里重复的行，按整行比较或者按指定列组合比较。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `subset` | str | 空 | 列名，逗号分隔 | 用来判断重复的列；留空表示整行所有列都比较 |
| `keep` | str | `first` | `first`、`last`、`none` | 一组重复行里保留哪一条 |

`keep` 填 `first` 保留第一条，填 `last` 保留最后一条，填 `none` 表示一组重复行一条都不保留。这个参数在界面上是文本框，要手打这三个词之一；写别的词会被 pandas 拒绝，节点执行失败。`subset` 里的列名写错时节点同样失败。处理之后的行号会重新从 0 排，这一点和本章其它节点的惯例相反，去重结果的左侧行号是连续的。

输入端口是 `data`，输出端口有 `cleaned` 和 `removed_count`，后一个数的是删掉的行数。

几批数据前后拼接在一起、又可能有重叠时，先按业务上的唯一标识（比如订单号、样本编号）填 `subset`，这样只有这些列都相同才算重复。`subset` 填得越少判得越宽，不同记录可能因为少数几列相同被当成重复删掉；留空按整行比较最保守。

### Drop NA

Drop NA（删除缺失值）删掉含空缺的行，也可以删含空缺的列。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `how` | str | `any` | `any`、`all` | `any` 表示有任何空缺就删，`all` 表示整行或整列都是空缺才删 |
| `axis` | int | `0` | `0`、`1` | `0` 删行，`1` 删列 |
| `subset` | str | 空 | 列名，逗号分隔 | 只检查这些列；留空表示检查所有列 |
| `thresh` | int | `0` | 非负整数 | 一行里至少要有这么多非空值，否则删掉；`0` 表示不用这个规则 |

`how` 和 `thresh` 会互相盖过：`thresh` 填了大于 0 的数时，判断改成「非空值够不够」，`how` 不再起作用。`axis` 填 1 时删的是列，此时 `thresh` 数的是列里的非空值个数。`subset` 留空表示检查所有列，只想按关键列判断时在这里写列名；`subset` 里的列名写错时节点执行失败。

输入端口是 `data`，输出端口有 `cleaned` 和 `removed_count`。`removed_count` 的含义跟着 `axis` 走：`axis` 为 0 时是删掉的行数，为 1 时是删掉的列数。

关键字段为空的记录后续用不上，而描述性字段的空缺可以后面补，这时把 `subset` 填成关键字段那一列，`how` 用 `any`，先把不可用的行去掉，再对剩下的数据补空缺。整列都空的情况用 `axis` 填 1 一次清掉。

### Interpolate

Interpolate（插值）用相邻的数值把空缺补出来，适合按顺序采集的数据。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `method` | str | `linear` | `linear`、`polynomial`、`spline`、`time` | 插值算法 |
| `order` | int | `2` | 整数 | `polynomial` 和 `spline` 的阶数，其余方法用不到 |

`linear` 用一条直线连接空缺两端，`polynomial` 用多项式拟合，`spline` 用样条曲线，后两种的阶数由 `order` 决定。`time` 按行索引上的时间间隔插值，要求索引是时间类型，普通整数索引上会插不出结果。

这个节点只处理数值列，文本列原样保留。某一列插值失败时这一列保持原样，节点本身不会变红，所以补完以后要抽查一列，确认空缺真的被填上了。

输入端口是 `data`，输出端口是 `interpolated`。

按小时记录的传感器数据中间缺了几段，直接删行会丢掉前后的连续性，这时用 Interpolate 把中间补出来，`method` 用 `linear`。空缺跨得很长时，插出来的值是推算的，分析结论里要说明这一段是补的。

### Fill NA

Fill NA（填充缺失值）用一个固定的值或者这一列的统计量把空缺填上。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `method` | str | `value` | `value`、`constant`、`ffill`、`bfill`、`mean`、`median`、`mode` | 填充方法 |
| `value` | str | `0` | 任意值 | `value` 和 `constant` 两种方法用的填充值 |

`value` 和 `constant` 是同一种做法：把空缺改成 `value` 里的内容，能转成数字的值按数字填。`ffill` 用上一个非空的值填，`bfill` 用下一个非空的值填。`mean` 和 `median` 用这一列的均值和中间值填，只对数值列生效。`mode` 用这一列出现次数最多的值填，数值列和文本列都能用。`method` 里写了别的词时退回成填固定值。

输入端口是 `data`，输出端口是 `filled`。

问卷或者报表里的空缺大多有业务含义，填固定值之前先想清楚填什么：数值列用中位数比均值稳，因为均值会被极端值拉偏；按顺序记录的数据用 `ffill` 更贴近实际情况；分类字段填众数或者「未知」这类固定文本。要区分「空缺」和「填进去的值」，可以在填之前先复制一列做标记，或者用 Eval Expression 生成一个标记列。

### Remove Outliers IQR

Remove Outliers IQR（四分位距异常值处理）按四分位距删掉取值过大或过小的行。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 检查哪一列，必须是数值列 |
| `multiplier` | float | `1.5` | 小数 | 四分位距的倍数，越小判为异常的值越多 |

判断方式是先算这一列的四分位数，下界取第一四分位数减去 `multiplier` 倍四分位距，上界取第三四分位数加上同样的距离，落在这两条界线之外的行被删掉。倍数默认 1.5，调到 1 会删得更多，调到 3 只删极端值。

`column` 必填。留空或者列名写错时节点执行失败；列名写对但这一列不是数值列时，节点不做处理，输出和输入相同，`removed_count` 为 0。

输入端口是 `data`，输出端口有 `cleaned` 和 `removed_count`。

一份测量数据里偶尔出现的超量程读数会拉偏均值，做统计之前先把它们去掉。下面这条流程把清洗的常规顺序串起来，从读文件一直走到写出文件。

```text
Data Source --> Drop Duplicates --> Fill NA --> Remove Outliers IQR --> Data Export
```

四步各有分工：`Data Source` 的 `data` 接给 `Drop Duplicates`，去重后的 `cleaned` 接给 `Fill NA`，补齐后的 `filled` 接给 `Remove Outliers IQR`，清洗完的 `cleaned` 接给 `Data Export`。顺序不能随意调换：先去重再补空缺，补出来的值不会反过来制造重复；先补空缺再判异常值，界线是按补齐后的数据算的，插出来的值也参与判断。导出之前可以再接一个 Text Viewer 看 `removed_count`，确认每一步删掉的量在预期之内。

### Remove Outliers Z-Score

Remove Outliers Z-Score（Z 分数异常值处理）按偏离均值的标准差倍数删掉异常行。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 检查哪一列，必须是数值列 |
| `threshold` | float | `3.0` | 小数 | 标准差倍数阈值，超过就判为异常 |

判断方式是先算这一列的均值和标准差，再把每个值换算成偏离均值的标准差倍数，绝对值超过 `threshold` 的行被删掉。阈值默认 3，调到 2 会删得更多。

`column` 的必填规则和 Remove Outliers IQR 一样：留空或者列名写错时执行失败，列存在但类型不是数值时原样通过。

输入端口是 `data`，输出端口有 `cleaned` 和 `removed_count`。

数据本身带极端值时，均值和标准差会被这些值拉偏，界线跟着变宽或者变窄，判断不如四分位那一版稳；数据分布接近对称、极端值不多时，这一版的判断更贴合统计学上的常规做法。要对比两版删掉了哪些行，把两个节点并行接在同一份数据后面，各自接一个 Text Viewer 看 `removed_count`。

### Replace Values

Replace Values（替换值）把某一列里的一个取值换成另一个取值。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 在那一列里替换 |
| `old_value` | str | 空 | 任意值 | 要被换掉的值 |
| `new_value` | str | 空 | 任意值 | 换成什么 |

比较是整个单元格的值相等才算命中，单元格里含有一段相同文字不触发替换。区分大小写，`abc` 和 `ABC` 是两个不同的值。列是数值列时，`old_value` 会先当数字试着比较，比如填 `25` 能匹配到数值 25。`column` 留空或者列名写错时节点执行失败。

输入端口是 `data`，输出端口有 `replaced` 和 `replaced_count`。`replaced_count` 统计的是替换前与 `old_value` 相等的行数，字符串列上这个数字准确；数值列上界面里输入的 `old_value` 是文本，统计用的是文本和数字的比较，得到的结果可能是 0，这时看 `replaced` 端口里的内容更可靠。

导入的数据里用 `-`、`N/A`、`未知` 这类标记表示没填，统一换成空值或者统一的标记，后面按分类字段处理时就不会分裂成好几类。换完之后看 `replaced` 端口里的内容，确认这些标记都变成了统一的写法。

### Threshold Filter

Threshold Filter（阈值过滤）按列值和阈值的比较结果去掉一部分行。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 拿哪一列和阈值比 |
| `operator` | str | `>` | `>`、`>=`、`<`、`<=`、`==`、`!=` | 比较符号 |
| `threshold_value` | float | `0.0` | 小数 | 比较用的阈值 |

运算符描述的是被删掉的行满足的条件，比较成立的行整行删除，不成立的行进入结果。各符号的含义如下。

| 填写的符号 | 被删掉的行 |
|------------|------------|
| `>` | 值大于阈值的行 |
| `>=` | 值大于或等于阈值的行 |
| `<` | 值小于阈值的行 |
| `<=` | 值小于或等于阈值的行 |
| `==` | 值等于阈值的行 |
| `!=` | 值不等于阈值的行 |

填 `>` 和 25 时，这一列大于 25 的行被删除，小于或等于 25 的行留下。列里的空值不参与比较，会留在结果里。`operator` 在界面上是文本框，符号要手打进去。`column` 留空或者列名写错时节点执行失败。

输入端口是 `data`，输出端口有 `filtered` 和 `removed_count`。

设备日志里超过量程上限的读数要丢掉、只留正常范围内的记录时，需要两个方向各去掉一次：先用 `>` 和上限去掉过高的读数，再在结果后面接第二个 Threshold Filter，用 `<` 和下限去掉过低的读数，两步之后留下的就是区间内的行。区间的一个边界正好是 0 时也可以直接用这个节点。只想去掉一个方向的记录时，一个节点就够。

### Transform Skewed

Transform Skewed（偏态转换）把分布偏斜的数值列换成更接近对称的尺度。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 要转换的列，必须是数值列 |
| `method` | str | `log` | `log`、`sqrt`、`boxcox` | 转换方法 |

三种方法的效果不同。`log` 取自然对数，转换前先给每个值加 1，这样 0 也能算；`sqrt` 开平方，同样先加 1；`boxcox` 做 Box-Cox 变换，由 scipy 计算，加 1 之后仍然出现非正数的列会被跳过，scipy 不可用时这一列也保持原样。

`column` 留空或者列名写错时执行失败，列存在但不是数值列时输出与输入相同。这个节点内部固定使用「转换前加 1」，界面上没有开关。

输入端口是 `data`，输出端口是 `transformed`。

表格上下文标签的「Operate / 操作」页里，「Data Cleaning / 数据清洗」面板中也有一项「Transform Skewed / 转换偏态数据」，作用于当前选中的表格。那个对话框里的方法是下拉框，选项是对数、平方根、倒数、幂四种，还多一个幂指数参数和一个「转换前加 1」的开关；两边的方法并不重合：对话框里没有 Box-Cox，节点里没有倒数和幂。同一批数据要两种做法都试，先在表格上用对话框比较，确定方法之后再回到工作流里固定下来。

分布拖着一长条尾巴时，均值和标准差这类统计量反映不出主体的形态，取对数之后尾巴被压近主体，画图和比较都更好读。

## 数据操作（Data Operations）

这一组做汇总、计算、查找、排序和透视。

### Describe

Describe（描述统计）给出每个数值列的统计摘要。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `percentiles` | str | `0.25,0.5,0.75` | 0 到 1 之间的小数，逗号分隔 | 除了固定的统计量之外，额外算哪些百分位 |

结果是一张统计表：每一行是一个统计量，每一列是要统计的那个数值列。行依次是计数、均值、标准差、最小值、填入的各百分位、最大值。默认给出 0.25、0.5、0.75 三个百分位，也就是第一四分位数、中位数和第三四分位数。填入的百分位会和这三个一起出现在结果里，想多要几档就多写几个数，比如 `0.1,0.5,0.9`。数字要落在 0 到 1 之间，写到这个范围之外时节点执行失败。

这个节点只统计数值列，文本列不出现在结果里。

输入端口是 `data`，输出端口是 `stats_data`。结果本身是一张表，可以接给 Sort 排序，也可以接给 Output to DataManager 留着看。

刚导入一份数据、还不知道各列的量级和散布时，先接一个 Describe，看计数是否一致、极值的范围是否合理，再决定后面用哪种清洗。想按分组看统计量时，下面的 Pivot Table 更合适。

### Eval Expression

Eval Expression（表达式计算）用 pandas 的表达式在表上算出一个新列。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `expression` | str | 空 | pandas 表达式 | 按「新列名 = 算式」的写法填写，输入框占一整行 |

表达式写成 `新列名 = 算式` 的形式，比如 `C = A + B`、`total = price * qty`、`ratio = a / b`。旧列名直接写在算式里，已有的列都参与运算。列名里带空格时，pandas 的表达式语法要求用反引号把列名包起来。表达式留空、或者数据本身是空的时，节点执行失败。

输入端口是 `data`，输出端口是 `result`，送出带上新列的表。

单价乘数量、两个通道的读数相减、把克换算成千克，这类逐行的计算用它一次算完，不用先把数据导出到脚本里。算完之后新列就在表里，后面的筛选、排序、汇总都能直接用这一列。脚本里做同样的事情见[脚本工作区](../script/workspace.md)。

### Filter By Column

Filter By Column（按列取值过滤）按数值列的取值区间保留行，区间两端都包含在内。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 按哪一列判断 |
| `min_value` | float | `0.0` | 小数 | 下界；填 0 表示不限制下界 |
| `max_value` | float | `0.0` | 小数 | 上界；填 0 表示不限制上界 |

0 这个值在两个参数里都是「不限制」的意思，所以这个节点没法把 0 当成边界使用：想保留「小于等于 100」的值，`max_value` 填 100、`min_value` 留 0，结果里会带上负数。要卡住 0 这条线，用 Threshold Filter 串两次，或者在 Query 里写表达式。留了边界的那一侧，这一列取值为空的行不会留在结果里。`column` 留空或者列名写错时节点执行失败。

输入端口是 `data`，输出端口有 `filtered` 和 `removed_count`。

保留一段量程内的读数时，把上下界都填上；只想卡住上限时，`max_value` 填上限、`min_value` 留 0，这一侧就不设限制。区间包含边界，对照设备规格书里「不超过 100」这样的说法时正好合适。

### Pivot Table

Pivot Table（透视表）把明细表汇总成交叉表，行是一个字段的取值，列是另一个字段的取值，格子里是按第三个字段算出来的聚合值。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `index` | str | 空 | 列名，逗号分隔 | 行索引，至少填一列 |
| `columns` | str | 空 | 列名，逗号分隔 | 列索引，留空时只按行索引汇总 |
| `values` | str | 空 | 列名，逗号分隔 | 参与汇总的数值列，至少填一列 |
| `aggfunc` | str | `mean` | `mean`、`sum`、`count`、`min`、`max` | 聚合函数 |

`index` 和 `values` 都至少要有一个列名，缺一个节点就执行失败，这是这个节点最容易踩的一处。`columns` 可以留空，也可以填一列看更细的分组。三个参数都支持逗号分隔的多列，行索引填两列时会得到两层行标题。`aggfunc` 是文本框，要手打上面列出的五个词之一。`values` 里填了文本列时，均值、求和这类聚合算不出来，节点执行失败，参与汇总的列要先改成数值列。

输入端口是 `data`，输出端口是 `pivot`，送出汇总好的交叉表。

明细数据里每个样本一行，想把「不同处理、不同时间点」的平均值排成一张表格时，`index` 填处理，`columns` 填时间点，`values` 填测量值，`aggfunc` 用 `mean`。下面这条流程把透视表的结果直接发布到数据管理面板。

```text
Data Source --> Pivot Table --> Output to DataManager
```

运行之后在数据管理面板里双击这份数据集，看到的是一张行列都带标题的汇总表，行是处理，列是时间点。想换一种聚合方式，只改 `aggfunc` 再运行一次，发布出去的是同一份数据集，内容换成新的汇总结果。透视表的图形化做法见[描述统计与透视表](../analysis/statistics.md)。

### Query

Query（查询）用 pandas 的查询表达式筛行，并把结果的行数单独送出来。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `query_string` | str | 空 | pandas 查询表达式 | 筛选条件，比如 `age > 25 and name == "John"` |

表达式语法和 Data Filter 的 `condition` 一致。两个节点的分工不同：Query 送出结果本身和结果行数，Data Filter 送出结果和被删掉的行数，另外 Data Filter 在表达式留空时可以按某一列的非空值筛行，Query 没有这种用法。表达式留空或者写错时，节点执行失败。

输入端口是 `data`，输出端口有 `result` 和 `row_count`，后者是结果里的行数。

按条件取出一批记录、同时想知道取出来多少条时，用 Query 省去再挂一个节点。下面这条流程把查询、排序和统计串起来，`row_count` 单独接到文本显示节点上看。

```text
Data Source --> Query --> Sort --> Describe
Query --row_count--> Text Viewer
```

`query_string` 写成筛选条件，比如 `amount > 1000 and region == "华东"`；`Sort` 的 `columns` 填参与排序的列，`Describe` 把结果里各数值列的统计摘要算出来。`row_count` 那一路上，文本显示节点给出这次取出了多少行，条件收得太紧时会立刻看出来。

### Search

Search（查找）在文本列里按正则表达式找出匹配的行。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `column` | str | 空 | 列名 | 在哪一列里找，必须是文本列 |
| `pattern` | str | 空 | 正则表达式 | 匹配模式 |
| `case_sensitive` | bool | 不勾选 | 勾选、不勾选 | 勾选时区分大小写 |

匹配方式是包含匹配：单元格里有一段文字符合模式就算命中，不要求整格内容完全匹配。`pattern` 按正则表达式解析，`^A` 找出以 A 开头的，`\d{4}` 找出含四个连续数字的，普通文字直接写就是按字面找。不勾选 `case_sensitive` 时字母不分大小写。这一列里的空值不参与匹配。

`column`、`pattern` 留空或者列名写错时节点执行失败。列存在但类型不是文本（比如纯数值列）时，字符串匹配做不了，节点同样会失败。

输入端口是 `data`，输出端口有 `result` 和 `match_count`，后者是命中的行数。

备注或者编号字段里混着手写的说明，用一段模式把需要核对的记录挑出来，比人工翻表快得多。模式写得宽会把无关的记录也带进来，`match_count` 就是判断宽窄的依据，改一次模式运行一次，看这个数收敛到多少。

### Sort

Sort（排序）按一列或多列给整张表排序。

| 参数 | 类型 | 默认值 | 取值 | 作用 |
|------|------|--------|------|------|
| `columns` | str | 空 | 列名，逗号分隔 | 按这几列排序 |
| `ascending` | bool | 勾选 | 勾选、不勾选 | 勾选是升序，不勾选是降序 |

列名可以写多列，写的先后决定优先级：先按第一列排，第一列相同的行再按第二列排。方向只有一个，勾选时所有列一起升序，不勾选时所有列一起降序，不能给不同的列指定不同的方向。列名前后的空格会被去掉，写 `时间, 编号` 也可以。`columns` 留空或者列名写错时，节点执行失败。

输入端口是 `data`，输出端口是 `sorted`。

排序不重排行号，结果表左侧的行号跟着原来的位置走，看上去不是从 0 开始的连续数字；导出成 CSV 或 Excel 时不写行号，所以这一点不影响写出的文件。

导出给同事看的表格按时间或者编号排好，打开就能顺着读；做时序图之前也先排一次序，折线才不会来回跳。按多列排序时把主关键字写在前面，比如 `地区, 日期`。

一份每月更新一次、导出给外部程序读取的记录表，用三个节点就能固定下来。下面这条流程把排序和写出接在读文件后面。

```text
Data Source --> Sort --> Data Export
```

`Data Source` 的 `data` 接给 `Sort`，`columns` 填 `日期, 编号` 并保持升序；`Sort` 的 `sorted` 接给 `Data Export`，`file_path` 指向一个固定文件，`export_format` 用 excel。原始数据更新之后重新运行，同一个文件被新的排序结果覆盖，外部程序读的还是那个路径。

## 参数没填全会怎样

这二十一个节点的执行方式一致。需要的参数是空的时候，执行方法直接返回失败，不往下走。界面上看到的现象是节点变成红色，这一次运行里它的下游节点不会执行，日志文件里留下一条记录。常见的触发情形是 Data Source 的 `file_path` 没填、Remove Outliers IQR 的 `column` 写错、Pivot Table 只填了 `values` 没填 `index`、Sort 的列名和表里对不上。

需要填全的参数在每个节点的表里能看出来：是否必需由实现决定，判断标准是空值会让这个节点做不了事。比如 Drop Duplicates 的 `subset` 留空是合法用法，表示按整行比较，节点照样成功；Data Source 的 `file_path` 留空就无事可做，节点直接失败。

下面这张表列出各节点会直接失败的情形，遇到红色节点时先在这里对一遍。

| 节点 | 失败的情形 |
|------|------------|
| Data Source | `file_path` 留空、文件不存在、读取过程出错 |
| Data Filter | 表达式里的列名不存在或者语法不合法 |
| Data Transform | 不会失败；`operation` 写别的词时数据原样通过 |
| Data Export | `file_path` 留空、写出过程出错 |
| Drop Duplicates | `keep` 写了 `first`、`last`、`none` 之外的值，或者 `subset` 列名写错 |
| Drop NA | `subset` 列名写错 |
| Interpolate | 不会失败；某一列插不出来时这一列保持原样 |
| Fill NA | 不会失败；`method` 写别的词时退回填固定值 |
| Remove Outliers IQR、Remove Outliers Z-Score | `column` 留空或者列名写错 |
| Replace Values | `column` 留空或者列名写错 |
| Threshold Filter | `column` 留空或者列名写错 |
| Transform Skewed | `column` 留空或者列名写错 |
| Describe | `percentiles` 里出现 0 到 1 之外的值 |
| Eval Expression | `expression` 留空 |
| Filter By Column | `column` 留空或者列名写错 |
| Pivot Table | `index` 或 `values` 没填，或者 `values` 里是文本列 |
| Query | `query_string` 留空或者表达式不合法 |
| Search | `column`、`pattern` 留空，列名写错，或者这一列不是文本列 |
| Sort | `columns` 留空或者列名写错 |
| Data Plot | 收到空数据或者绘图过程出错；matplotlib 装不上时整个节点都不存在 |

日志里每条失败记录的形式是「Node '<节点 id>' execution exception: ...」，节点 id 就是画布上这个节点的存盘名字，据此可以定位到具体是哪一个节点出的问题。运行日志的查看方法见[常见故障](../reference/troubleshooting.md)。

## 常见问题

### 节点变红，说列名不存在

先清点表里真实的列名。导入的表格常带表头之外的空行、合并单元格拆出来的多余标题，列名和想象的不一样。把列名复制到参数里，或者先用 Data Transform 的 `rename` 把列名改成简短可靠的写法。

### 筛选之后一条数据都没有

多数是条件的写法把区间卡反了，或者字符串列上用了数值比较。把条件放宽到只剩一个判断，运行一次看结果行数，再逐步加上第二个条件。Query 的 `row_count` 和 Data Filter 的 `removed_count` 都能直接读到效果。

### 数值列上的替换没生效

Replace Values 比较的是整个单元格的值，区分大小写，数值列上还要按数字比较。填的 `old_value` 和表里的写法差一个空格、差一个全角字符都会匹配不上，`replaced_count` 为 0 就是没有命中的信号。

### 输出到数据管理面板的数据看起来没更新

同一份数据集被就地替换，表格视图的标题不会变，内容会变。确认用的是同一个 `data_name`，再确认这次运行没有节点失败：失败节点的下游不执行，发布节点可能根本没有被触发。

### 节点面板里找不到 Data Plot

这个节点只在 matplotlib 能成功导入时存在。检查随软件安装的 Python 环境里有没有 matplotlib，装好之后重启软件，节点会出现在数据分析分组里。

### 导出的 CSV 用别的软件打开是乱码

CSV 按 utf-8 写出，有些软件默认按本地编码打开这类文件，中文就会乱码。把 `export_format` 改成 excel 导出 xlsx，或者在那个软件里选对编码再打开。

### Filter By Column 填了 0 没有按预期生效

0 在这两个参数里表示不限制，不是边界值。要卡住 0 这条线，改用 Threshold Filter 串两次，或者在 Query 里写 `column >= 0 and column <= 上限` 这样的表达式。

### Pivot Table 报错，说没有可以聚合的列

`values` 里填的列是文本列，均值、求和这类聚合算不出来。先让这一列参与汇总的部分变成数值：用 Eval Expression 另算一列，或者在表格视图里改这一列的类型（见[表格视图](../data/table.md)），改完再回来做透视。

### 一条流程上挂了两个 Threshold Filter，第二个没有数据

前一个节点把行全部删光时，后一个节点收到一张空表，仍然会执行；如果前一个节点执行失败，后一个就不会被触发。先看前一个节点的颜色，再确认它的条件没有把区间卡反。
