# 工程文件

工程文件把一次工作的全部状态装进一个文件：工作流、数据集、绘图、表格样式、打开过的页面、智能体会话记录、脚本工作区。这一章讲这个文件里装了什么、保存和打开时程序做了哪些事、什么时候必须先保存，以及工程的脚本工作区落在磁盘的什么位置。界面上的保存按钮在哪里，见[主界面](main-window.md)的 Ribbon 标签页一节。

## 一个文件装下全部

工程文件的后缀是 `.dapro`，它实际是一个 ZIP 压缩包。用任何能打开压缩包的工具都能查看里面的成员，成员是一组 XML 文件加数据文件。保存时程序在后台逐项打包，界面上从状态栏能看到 `Saving project` / 正在保存工程 的进度文字；打开时同样逐项解包，状态栏显示 `Loading project` / 正在加载工程。

打开新工程之前，程序会先给当前工程做一份快照。新工程加载失败时会自动把旧工程恢复回来，状态栏提示 `Failed to load project, restored previous project` / 工程加载失败，已恢复之前的工程，这时工作内容不会丢。

## 压缩包里的成员

| 成员 | 内容 |
|------|------|
| `system.xml` | 写出这个工程时的系统与软件信息 |
| `workflow.xml` | 工作流的界面部分：图元的层级关系与渲染效果，以及工作流操作区内部标签页的停靠布局 |
| `workflow-data.xml` | 节点拓扑、节点参数值、端口之间的连接关系 |
| `data-manager.xml` | 数据集清单：名称、描述、类型、持久 id，以及数据本体在包内的路径 |
| `datas/<名称>` | 数据本体，每个 DataFrame 数据集一个文件 |
| `charts.xml` | 绘图与坐标系的信息 |
| `chart-data/` | 图表里每个图元的序列化数据，加一个 `chart-items.xml` 索引 |
| `table-styles.xml` | 单元格底色和字体，按 `data-manager.xml` 里记的 id 匹配数据集 |
| `data-operate.xml` | 数据操作区打开过哪些数据页，以及内部的停靠布局 |
| `agent_sessions/<id>.jsonl` | 这个工程里的智能体会话记录，一条消息一行 JSON |
| `workspace/` | 工程的脚本工作区，见下文 |

`workflow.xml` 和 `workflow-data.xml` 分开存两件事：前者是界面层面的图元排布，后者是节点与连线本身。两份分开之后，改动图元的渲染样式不会碰到节点逻辑。

`datas/<名称>` 里的数据是 Parquet 格式，数据集越大，这一部分占的体积越大。数据库表这类引用式数据集不写 `datas/`，只在 `data-manager.xml` 里记下连接方式和查询内容，数据本体留在外部数据源。想知道某个数据集是怎么进来的，看[导入数据](../data/import.md)。

`table-styles.xml` 用 id 而不是名称去匹配数据集，所以重命名数据集之后，已设的底色和字体不会串到别的数据集上。`agent_sessions/` 目录只在保存时有活跃会话才写入；工程里没有这个目录时，打开过程会正常跳过。

## 新建、打开、保存、另存为

### 新建

界面上没有「新建工程」这一项。程序每次启动都从一个空工程开始，里面已经有一个名为 `Untitled` / 未命名 的工作流标签页。要开始一份全新的工作，重新启动程序即可；要让当前窗口换成另一个工程，用打开功能。

### 打开

点击 `Open` / 打开 后弹出文件对话框，过滤器是 `Project File (*.dapro)` / 工程文件。当前工程有未保存改动时会先问一句 `The current project has unsaved changes. Do you want to save before opening another project?` / 当前工程有未保存的更改，是否在打开其他工程之前保存？，选保存就先保存再打开，选不保存直接打开，选取消则什么都不做。当前工程没有改动但已经有内容时，问的是 `Another project already exists. Do you want to replace it?` / 已存在其他工程，是否要替换？。

打开成功的工程会被记进 `Recent Files` / 最近打开的文件 列表，名单在应用菜单里，条数上限在设置的高级页改。启动命令里带上一个 `.dapro` 文件的路径（在文件管理器中用本程序打开该文件即属于这种情况），程序会直接打开它，效果和启动后点打开一样。

### 保存

`Save` / 保存 分两种情况。工程保存过一次之后，直接覆盖原文件，状态栏提示 `Project saved successfully` / 成功保存工程。还没有保存过的时候，弹出保存对话框，标题 `Save Project` / 保存工程，文件类型是 `Project Files (*.dapro)` / 工程文件，起始目录是桌面，文件名默认带 `.dapro` 后缀。

保存成功后窗口标题里的工程名变成文件名（去掉后缀），当前工作流标签页的名字也会跟着改成同一个名字，可以再手动改成别的。

### 另存为

`Save As` / 另存为 总是弹出保存对话框。目标文件已经存在时问一句 `Whether to overwrite the file: %1` / 是否覆盖文件:%1，确认后才覆盖。

另存为之后，脚本工作区的本地缓存目录按新路径重新计算，理由见工作区一节。

## 打开工程会恢复什么

打开一个保存过的工程，下面这些内容会按保存时的样子回来：

- 每个工作流标签页，连同标签页的名字和画布上的节点、连线、参数值，并自动选中保存时的那一个。
- 绘图和绘图里的坐标系、图表。
- 数据集，引用式数据集恢复到连接和查询信息，打开数据页时再向数据源取数。
- 数据操作区上一次打开过的数据页，以及这些页的排列。
- 表格的底色和字体设置。
- 这个工程里的智能体会话记录，导入会话列表后可以继续对话，见[会话与对话](../agent/session.md)。
- 脚本工作区里的文件，解压到本地缓存目录。

工作流标签页和数据页在各自操作区内部的排列跟着工程走，顶层窗口的大小、位置和面板排布不跟着工程走，那部分由程序的设置和 `.dawork-ui-state` 决定，见[主界面](main-window.md)的界面状态一节。

## 工程里的数据和外部文件的关系

导入一份 CSV 或 Excel 文件之后，数据内容会复制进工程，工程保存的是这份副本，与原来的磁盘文件不再有任何联系。删掉原文件不影响工程里的数据集，反过来，改了原文件也不会让工程里的数据跟着变。

要更新数据，重新导入一份。体积大的数据源改用引用式接入，数据本体留在数据源，工程里只记连接方式和查询，打开数据页时按需取数，见[数据管理面板](../data/manager.md)。

## 未保存标记

工程有改动未保存时，窗口标题上出现星号，保存之后消失。关闭窗口或打开另一个工程时如果还是这个状态，程序会弹窗询问是否保存，见[主界面](main-window.md)的窗口标题一节。

## 运行工作流之前必须先保存

工程没有保存过时点运行，程序弹出警告 `Before running the workflow, you need to save the project` / 在运行工作流之前，需要先保存工程，不执行任何节点。

这一步不能省。脚本工作区目录由工程文件的完整路径推算，规则见下文，工程没有保存过时算出来的目录是空的，工作流的脚本节点就没有可用的工作目录。保存一次之后，同一次运行的后续步骤不受影响。

## 自动保存

设置对话框高级页里的 `Auto-save interval` / 自动保存间隔 可以让程序按固定间隔自动保存。取值范围 0 到 1440，单位是分钟，填 0 时显示为 `Disabled` / 禁用，这也是初始值，也就是默认不自动保存。

到点之后程序只在工程有未保存改动时才动手，保存成功后在消息面板记一条 `Project auto-saved` / 工程已自动保存。工程还没有保存过时，自动保存会先弹出保存对话框要一个保存位置，所以要么先手动保存一次，要么在这一项上留出余量。

## 应用设置和工程里各存什么

工程文件只装这次工作的内容，程序自己的设置另存在配置保存路径里，两者互不影响。Windows 上配置保存路径在用户 AppData 目录下。

| 内容 | 存放位置 |
|------|----------|
| 界面偏好：主题、Ribbon 样式、语言、字体、日志级别、超时与自动保存间隔 | `dawork-config.xml` |
| 界面布局方案 | `dawork-layouts.json` |
| 界面状态的快照 | `.dawork-ui-state` |
| 模型供应商与运行参数 | `agent-config.json` |
| 权限模式与文件路径规则 | `agent-permissions.json` |
| 智能体的会话记录（不属于任何工程的部分） | 应用数据目录下的 `sessions/` |

每一项设置的具体位置、取值范围和默认值见[设置项说明](../reference/settings.md)。把工程拷到另一台机器上时，只有工程文件里的内容会跟着走，模型配置、界面布局这些需要在那边重新设一遍。

## 脚本工作区

工程的脚本工作区是一组普通文件和目录，放在压缩包的 `workspace/` 里，随工程一起保存。脚本节点、智能体的 `run_script` 工具都从这里取脚本文件，用法见[脚本工作区](../script/workspace.md)。

程序不直接在这个压缩包成员上工作，而是打开工程时把它解压到本地缓存目录，脚本运行时看到的是本地缓存目录。缓存目录的位置按下面的规则算出来：

- 根目录取自设置对话框高级页的 `Workspace directory` / 工作区目录，留空时用系统临时目录。
- 目录名是 `<工程基名>_<工程完整路径的 sha1 前 8 位>`。

假设工作区目录设为 `D:/da-workspace`，工程文件是 `D:/proj/myproject.dapro`，缓存目录就是 `D:/da-workspace/myproject_` 加上那段哈希；哈希取自完整路径，所以工程改名、移动位置或者另存为之后，缓存目录会随之换成另一个。同一个工程在同一台机器上打开多次，用的是同一个缓存目录。

工作区目录这一项的改动在下次打开工程时生效，当前打开的工程仍然用旧的根目录。

## 打开工程时的工作区冲突

本地缓存目录里可能存在上一次留下的文件，与工程包内保存的版本不一致时，程序在开始加载之前弹一个对话框，标题 `Script Workspace Conflict` / 脚本工作区冲突，正文说明本工程的本地脚本工作区与工程文件内保存的版本不一致，需要选择保留哪一边，下面还显示本地缓存目录的完整路径。三个按钮的后果如下。

| 按钮 | 后果 |
|------|------|
| `Keep Local` / 保留本地 | 跳过解压，本地文件原样保留；工程随之被标记为有未保存改动，下次保存时把本地版本写回包内 |
| `Overwrite With Project Version` / 用工程内版本覆盖 | 先清空本地缓存目录，再按包内版本解压 |
| `Cancel` / 取消 | 不启动加载，工程保持打开之前的状态 |

两边内容逐文件比对下来完全一致时不会弹窗，直接按包内版本解压。这份比对按文件内容算，与文件的修改时间无关。

默认行为是每次都问。想少点一次，可以改配置文件里的策略项 `workspace-overwrite-policy`，它在 `dawork-config.xml` 的 `<configs>` 下，形状如下。

```xml
<prop key="workspace-overwrite-policy">
  <value class="QVariant" type="QString">ask</value>
</prop>
```

`key` 是策略项的名字，`<value>` 里的文字是取值：`ask` 表示每次都弹窗询问，也是初始值；`always-local` 表示直接保留本地版本，不再询问；`always-zip` 表示直接用工程内版本覆盖本地，不再询问。改这一项需要先关闭程序，改完重新启动。设置对话框里目前没有这一项的入口。

## 常见问题

打开工程时提示脚本工作区冲突，但本地没有做过任何改动。本地缓存目录里的文件被外部程序改过，或者上一次是在别的路径下打开过同名工程。确认本地没有要保留的改动时，选 `Overwrite With Project Version` / 用工程内版本覆盖。

工程文件体积很大。数据本体在包内的 `datas/` 下，体积随数据集增长。数据来自数据库这类外部数据源时不会写进包内，可以优先用这种接入方式，见[数据管理面板](../data/manager.md)。

工程在另一台机器上打开后，脚本目录是空的。工程的 `workspace/` 随工程文件一起走，正常情况下不会丢。检查是否在打开时选过 `Keep Local` / 保留本地，以及本地缓存根目录是否指向了一个不可写的目录。

自动保存没有生效。高级页里的间隔是 0，界面显示为 `Disabled` / 禁用。改成一个大于 0 的分钟数。
