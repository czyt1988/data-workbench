# 数据管理面板

数据管理面板列出当前工程里所有的数据集，是打开表格、改名、删除、看清一列是什么类型的入口。导入的文件、脚本构造的数据框、工作流输出到数据管理器的结果，都会出现在这里。这一章讲面板的每一栏、树上每级条目的含义，以及改名与删除的各种限制。

## 面板的位置

面板是左侧区域的停靠面板，标题为「Data Manager / 数据管理」，与「Workflow Node / 节点」、「Charts Manager / 绘图管理」同处一个标签组，点标签切换这三个面板。面板不能关闭，被其它标签挡住时，用 Ribbon 的「View / 视图」标签页、「Display / 视图显示」面板里的「Show Data Manager / 数据管理视图」把它抬到前面；「Show Table Area / 数据操作区域」抬的是表格区域，见[表格视图](./table.md)。

面板顶部有三个控件：左边两个按钮分别是展开全部和收起全部，右边是搜索框。

## 数据怎样进入面板

面板里的条目来源有四种，它们除了名字和描述不同，在面板上完全一样。

- 导入文件，见[导入数据](./import.md)。名字取文件名，描述是文件路径。
- 脚本里构造数据集并加入管理器，名字由脚本指定，描述可以留空，见[脚本工作区](../script/workspace.md)。
- 工作流里输出到数据管理器的 Output to DataManager 节点：同名数据集已存在时原地更新，否则新建一条，见[数据分析节点手册](../workflow/nodes-analysis.md)。
- 直接对表格做的分析动作，比如数据描述与数据透视表，它们会把结果作为新数据集加进来，名字在原数据集名后面加后缀，见[描述统计与透视表](../analysis/statistics.md)。

数据集加入时会按重名规则处理：名字已存在就在后面补 `_1`、`_2`，脚本新建的数据集不会互相覆盖。

## 两栏与树结构

表格头有两栏，第一栏「Name / 名称」，第二栏「Properties / 属性」。

树的一级条目是一个数据集。它的名称栏显示数据集名字，带一个数据框图标；属性栏显示这份数据的尺寸，写成 `[行数 × 列数]`；鼠标停上去的提示气泡是数据集描述，导入得到的数据集描述就是文件路径。

属性栏只在数据能报出形状时才有内容：数据框和一等列（Series）能报出行列数，一般 Python 对象这类没有形状的数据集留空。

数据集条目可以展开，展开后每一列是一条子条目，名称是列名，属性栏留空。列子条目的提示气泡按「数据集名.列名,size:长度」的格式拼出，中文界面写作「数据集名.列名,长度:长度」，长度是该列的行数。每个列子条目还带一个按列类型选出来的图标：整数与布尔用同一个图标，浮点、日期时间、字符串、其它对象各有自己的图标，bytes 一类没有对应图标的类型不显示图标。

面板顶部的展开全部与收起全部按钮一次处理整个树，列多的工程里用它们省去逐个点开。展开状态只是显示状态，与数据无关；搜索框里有内容时树会自动展开，清空搜索框后保持当时展开的样子。

条目在面板里的顺序是加入顺序。批量导出按这个顺序逐个写文件，所以导出的先后与列表从上到下的次序一致。

## 软件里的数据类型

属性栏以外的第二处类型信息是每个数据集的内部类型。软件把数据分成下面几种，脚本里加进来的对象也会归到其中之一；工程文件按表里的字符串记录类型。

| 类型标识 | 含义 |
|-----------|------|
| `None` | 空对象，没有任何数据 |
| `Package` | 数据包 |
| `Object` | 一般 Python 对象 |
| `DataFrame` | pandas 数据框，能打开成表格、能导出 |
| `Series` | pandas 的一列 |
| `InnerData` | 软件内部使用的数据 |

面板里的这一串类型与表格里的列类型不是一回事。前者描述整个数据集被包装成什么，后者是 pandas 的列类型（整数、浮点、日期时间、文本等），列类型看的是列子条目上的图标和表格里「Type / 类型」面板的下拉框，见[表格视图](./table.md)。

绘图不是数据类型，也不在这个面板里。绘图由「Charts Manager / 绘图管理」面板单独管理，随工程一起保存，见[绘图与坐标系](../chart/figure.md)。展开数据框得到的列子条目是数据框内部的列视图，不是独立的数据集，不会单独出现在一级条目里。

脚本里加入的一等列（Series）会作为一级条目出现，属性栏显示它的行列数，形如 `[100 × 1]`。它没有图形化的表格视图，能打开表格的仍然是数据框类型的数据集。

## 单击、双击与右键

- 单击一级条目：选中数据集，Ribbon 上的删除、导出等动作都以这个选中状态为对象。
- 双击一级条目：在「Data Operate / 数据操作」面板里打开它，得到一个表格标签页。
- 单击列子条目：选中这一列，部分对话框会拾取它作为数据来源。
- 双击列子条目：打开表格，并把这一列滚动到可见位置、整列选中。
- 右键一级条目：菜单里有「Rename Data / 重命名数据」、「Remove Data / 移除数据」，以及「Export / 导出」子菜单，子菜单四项与数据标签页导出面板的格式一致，见[导出数据](./export.md)。
- 右键列子条目：菜单与表格的表头右键菜单相同，包括重命名此列、删除列、复制列名、跳转到最大值、跳转到最小值、显示统计信息。如果这个数据集还没有打开表格，软件会先打开它再弹菜单。
- 拖动条目：把条目拖到绘图区域，软件带着数据打开建图向导；拖一个数据集条目等于给出整份数据框，拖列子条目会把列名一起带过去。数据管理面板本身不接收拖放，拖进来的文件不会导入。

菜单里能用的项与当前选中的条目类型有关：一级条目上看到的是数据集级的操作，列子条目上看到的是列级操作。选中列子条目后，Ribbon 上的删除只认一级条目，会提示需要先选中数据集；重命名在这种状态下没有反应，因为列子条目不可编辑。

## 搜索

搜索框按输入的文本过滤树，匹配范围包括数据集名字和列名，不区分大小写，包含即算匹配。输入后大约 300 毫秒才执行过滤，连续打字不会每敲一个键刷新一次；有匹配项时树自动展开，便于直接看到命中的列。清空输入框恢复显示全部条目。

搜索框带补全列表，列表里是所有数据集名字和列名，输入时可以直接从列表里选。

搜索没有命中时树里什么都不显示，清空输入框即恢复全部条目。过滤只改变显示，不影响数据本身：数据集数量不变，导出、批量导出这些动作仍然按面板里的完整列表处理，搜索框里的内容不会缩小它们的范围。

## 面板之外哪些功能读它

数据管理面板既是列表，也是软件里挑数据集的地方，不少功能以面板里当前的选中项作为输入。

- 数据标签页的删除、重命名、导出动作，处理的是面板里选中的数据集。
- 数据分析插件里的「Export Individual Data / 导出单个数据」同样先看面板里的选中项。
- 批量导出的「Export Selected / 导出所选」按面板里的选中项决定导出哪些数据集。
- 建图向导和统计绘图的数据选择框列出面板里的数据集；把条目拖到绘图区域可以直接带着数据建图。
- 工作流节点里需要指定数据集的参数、智能体读取数据的工具，范围都是面板里的数据集，见[内置工具](../agent/tools.md)。

先选数据、再点动作，是这个软件里操作数据的固定顺序。反过来，面板里没有的数据，这些功能都取不到。

## 名字与描述

名字是面板里唯一能直接改的字段，改法与限制见下文的重命名一节。描述显示在条目的提示气泡里，导入产生的数据集由软件写入文件路径，脚本与工作流节点也可以写入；界面上没有编辑描述的入口，需要在新建数据集时一并给出，或者用脚本改，见[脚本工作区](../script/workspace.md)。

两个字段的作用范围不同：名字参与重名检查，也是导出时的默认文件名（批量导出直接拿它做文件名）；描述只是一段说明文字，不参与任何判断。

## 重命名数据集

两种方式：选中一级条目后按 F2，或者用 Ribbon 数据标签页、「Data Operation / 数据操作」面板里的「Rename Data / 重命名数据」，两个动作都是打开内联编辑框，改完回车提交。双击是打开表格，改名不要用双击。

提交时有两道检查，没通过就保持原名字，并在消息窗口给出提示。

| 情况 | 提示 |
|------|------|
| 名字为空 | `The dataset name cannot be empty` / 数据集名称不能为空 |
| 与已有数据集重名 | `The dataset name "%1" already exists` / 数据集名称"%1"已存在 |

改名成功后，打开着的表格标签页标题、绘图里对该数据集的引用都会跟着更新。名字只影响显示，表格样式这类内部记录跟的是数据集本身，见[表格样式](./style.md)。

## 删除数据集

选中一级条目后，用 Ribbon 的「Remove Data / 移除数据」，或者右键菜单里的同一项。删除时没有二次确认，删除动作压入数据管理器自己的撤销栈，主页标签页、「Clipboard / 剪切板」面板里的「Undo / 撤销」（快捷键 Ctrl+Z）可以把它恢复回来。恢复回来的不只是数据本身，与它关联的表格样式一并回来。这个栈和每个表格标签页各自的撤销栈是分开的两套：在表格里改过的单元格属于该标签页的栈，删除与新增数据集属于数据管理器的栈。

删除对象必须是一级条目。没有选中一级条目时，软件在消息窗口提示需要先选中要删除的条目，不执行删除。

如果被删除的数据集当时正打开着表格，那个标签页不会自动关掉，标题后面会加一段「`[deleted]`」标记（中文界面显示为「[已删除]」），表示它对应的数据集已经不在数据管理面板里。要恢复就撤销删除，要放弃就关闭这个标签页。

删除只影响软件里的数据集。源文件还是在磁盘上，重新导入可以再拿回一份；工程保存的是导入时的副本，见[工程文件](../getting-started/project.md)。

## 面板与表格标签页的对应

面板里的一级条目与「Data Operate / 数据操作」面板里的标签页一一对应：双击条目开出一个标签页，同一个条目再双击只把已有标签页提到前面。改名时标签页标题同步变化，删除数据集时标签页留下并带上「`[deleted]`」标记，详情见[表格视图](./table.md)。关掉表格标签页只是关掉视图，数据管理面板里的条目不受影响。

打开着哪些标签页、标签页怎么摆放，也会随工程保存：它们记录在工程的 `data-operate.xml` 里，下次打开工程时按原样恢复。数据管理面板本身的内容则来自 `data-manager.xml` 与 `datas/` 目录。

## 数据集的身份与工程文件

每份数据在加入管理器时拿到一个内部标识，这个标识在一个工程内不会重复，也会随工程一起保存。面板上看到的是名字，软件内部按标识认数据：表格样式按标识找数据集，所以改名不会让样式错位；表格标签页也用标识记录自己对应哪份数据，工程重新打开时据此把标签页接回去。

工程保存时，数据管理面板的内容分散写在工程压缩包的两个位置：`data-manager.xml` 记录数据集列表、标识、名字和描述，数据本身按名字存进 `datas/` 目录，见[工程文件](../getting-started/project.md)。打开工程后，面板里列的条目与保存时一致，打开的表格标签页也按原样恢复。

## 面板里的数据都在内存里

面板列出的数据集常驻内存，打开表格、绘图取数、脚本读取都直接取内存里的对象，不再回头读原始文件。工程打开时这些数据从工程压缩包里读回内存，所以工程的大小直接对应打开时需要装载的数据量。不需要的数据集及时删除，工程文件会相应变小，打开时需要装载的数据也少。

## 常见问题

- 面板里找不到绘图：绘图的列表在「Charts Manager / 绘图管理」面板，数据管理面板只放数据集。
- 展开数据集后找不到某列：列名按原样显示，先确认导入后的列名（数字列名会转成字符串），必要时用搜索框找。
- 删掉的是整个数据集：数据集级的删除只作用于一级条目；要删某一列，在表格的表头右键菜单里操作。
- 删除后发现表格标签页还在：标签页上带了「`[deleted]`」标记，撤销删除即可继续使用，或者把它关掉。
- 数据集被别处删掉了：脚本里调用删除接口也会移除数据集，删除后数据管理面板里不再列出它，打开着的表格标签页会带上「`[deleted]`」标记。
- 名字能不能带空格或中文：可以。软件对名字的限制只有两条，不能为空、不能与已有数据集重名，其它字符都不拦截。
- 一次能不能处理多个数据集：删除会一次移除所有选中的数据集（按住 Ctrl 或 Shift 多选），重命名只改当前的那一个。要一次导出多个，用批量导出的两种方式，见[导出数据](./export.md)。
- 想改描述：界面上没有这个入口。描述在导入时由软件写入，或者在脚本构造数据集时给出。
- 名字改了以后哪里会跟着变：表格标签页标题、绘图里的引用、导出的默认文件名都会跟着新名字走；表格样式按数据标识匹配，不受改名影响。
- 面板里的条目能拖到别处吗：能拖到绘图区域，会带着数据打开建图向导；拖到文本编辑器一类的程序没有效果，面板里没有从文件系统拖入的入口。
- 名称栏和属性栏都不显示列的类型：类型信息在每个列子条目的图标上，悬停在条目上能看到该列的行数。
