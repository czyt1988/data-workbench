# 导入数据

外部文件要参与软件里的处理，第一步是导入。导入完成后数据管理面板里多出一条数据集，它可以打开成表格、接进工作流，或者作为绘图的取数来源。这一章讲界面能读哪些格式、文本文件的导入向导里每个字段的含义、导入后数据集的名字和描述怎么定，以及脚本和命令行两条替代入口。

## 界面入口

导入按钮在 Ribbon 的数据标签页：「Data Operation / 数据操作」面板里的「Add Data / 添加数据」，按钮提示为「Add data to the table / 添加数据到表格」。主页标签页的「Create / 创建」面板里有同一个按钮，两处效果一致。

点击后打开文件对话框，一次只能选一个文件。对话框的过滤器由软件向 Python 侧查询得到，列表如下。

| 过滤器 | 对应内容 |
|--------|---------|
| `all support(*.txt *.csv *.xls *.xlsx *.parquet *.pkl)` | 所有可导入的格式 |
| `text (*.txt)` | 文本文件 |
| `csv (*.csv)` | 逗号分隔的文本 |
| `xls (*.xls),xlsx (*.xlsx)` | Excel 工作簿 |
| `parquet (*.parquet)` | Parquet 列式文件 |
| `pickle (*.pkl)` | pandas 的 pickle 文件 |
| `all(*.*)` | 全部文件 |

选定文件后，读取由 Python 侧完成，数据集直接进入数据管理面板，面板同时被抬到最前面。导入开始时会往消息窗口写一条「Begin importing file: %1 / 开始导入文件:%1」。

## 各种格式要注意什么

能读的格式由文件后缀决定，后缀不在表里的文件读不出来。

| 后缀 | 读取方式 | 要点 |
|------|---------|------|
| `.csv` | pandas 的 `read_csv` | 编码不在界面上指定，软件自己检测 |
| `.xls`、`.xlsx` | pandas 的 `read_excel` | 只读工作簿的第一个工作表 |
| `.txt` | pandas 的 `read_table` | 先弹导入向导，见下一节 |
| `.parquet` | pandas 的 `read_parquet` | 依赖 pyarrow |
| `.pkl` | pandas 的 `read_pickle` | 文件里存的应当是一个数据框对象 |

json 文件没有登记读取函数，导入过滤器里也没有它。要在软件里读 json，用工作流的 `Data Source` 节点，它支持 csv、excel、json、parquet 四种格式，还能指定工作表和分隔符，见[数据分析节点手册](../workflow/nodes-analysis.md)。

读取完成后数据还要过一遍统一整理，这一步对所有格式都生效。

- 列名全部转成字符串。原本是数字的列名 `0`、`1` 会变成文本 `"0"`、`"1"`。
- 日期列自动识别。对文本类型的列抽取最多 100 个非空值试着解析成日期，成功比例达到 80% 就把整列转成日期时间类型，其中解析不了的值变成缺失值。列本身已经是数字或日期类型时不做这一步。

各格式的取舍可以这样看。CSV 与 txt 是纯文本，任何软件都写得出来，代价是没有类型信息：读进来之后一列里混着数字和文字时整列会按文本处理，日期靠前面那条自动识别规则补救。Excel 工作簿本身带类型，也方便人工准备数据，代价是只有第一个工作表会被读到，其余工作表要先拆成单独的文件。Parquet 与 pkl 都是带类型的二进制格式，适合在软件之间来回搬运数据，两者的差别在读者：Parquet 是通用列式格式，Python、R、数据库工具都能读，pkl 只有 Python 能读，因为文件里存的是序列化后的 Python 对象。pkl 还有一个约束，文件里存的应当是一个数据框，存的是字典、列表一类的对象时导入会失败。

## 导入之后数据放在哪里

导入是把文件内容读成内存里的数据框，数据集与磁盘上的源文件之后互不影响：源文件改了、删了，已经导入的数据集不变；反过来在表格里改数据也不会写回源文件。要留下改动，用工程保存或者[导出数据](./export.md)。

工程保存时每个数据集的内容写进工程压缩包里的 `datas/` 目录，写出的格式是 Parquet，所以打开工程拿到的是一份副本，原文件不在身边也能继续用。

## 文本文件的导入向导

选择 `.txt` 文件后，软件先弹出「Txt Import / Txt导入」对话框，确认参数后才真正读文件。对话框分左右两栏，左边填参数，右边看预览。预览区有「Text / 文本」和「Data / 数据」两个标签页，前者显示文件开头的原文，后者显示按当前参数解析出来的表格。改动任何字段后按「Refresh / 刷新」重新解析，换文件路径会自动刷新。解析出错时错误文字显示在左栏底部，没有错误时那里是「No Error / 无异常」。

| 字段 | 默认值 | 取值范围 |
|------|--------|---------|
| `Text File Path` / 文本路径 | 随对话框带入的文件路径 | 无 |
| `encoding` / 编码 | UTF-8（Qt 5 构建下取系统本地编码） | 下拉框里的任一编码 |
| `delimiter` / 分隔 与 `Auto` / 自动 | 自动勾选 | 见下文 |
| `header row` / 表头行 | 不勾选，行号框从 1 起 | 1 到 999999999 |
| `skip rows` / 跳过行 | 0 | 0 到 999999999 |
| `skip footer` / 跳过尾 | 0 | 0 到 999999999 |
| `max rows` / 最大行数 | 不勾选 | 勾选后 1 到 999999999 |
| `skip blank lines` / 跳过空行 | 不勾选 | 无 |
| `preview max row:` / 预览行数: | 1000 | 1 到 100000，步进 100 |

分隔符一行的「Auto / 自动」勾选时，文本框不可用，列按连续的空白字符切分（正则 `\s+`），制表符和空格混排都能分开。取消勾选后可以从下拉框选逗号、空格、制表位、分号、下划线、横杠，也可以直接在框里输入别的字符。输入内容长度超过一个字符、又不等于 `\s+` 时按正则表达式处理，此时由 Python 解析引擎读取文件。

表头行的复选框决定有没有列名。勾选后填的行号作为列名来源，数据从这一行之后开始读取；行号从 1 开始数，软件在内部换算成从 0 计数的行号。不勾选时文件没有列名，软件按 0、1、2 依次编号，随后按前面说的规则转成字符串列名。

跳过行和跳过尾控制文件开头与末尾不参与读取的行数，注释行、单位行、结尾的统计行用这两个字段排除。最大行数只在想先导入前一部分时勾选，不勾选读取全部行。跳过空行勾选后空行直接跳过，不勾选时空行会被当成缺失值。

右侧预览的行数由「preview max row: / 预览行数:」控制，它只改变预览显示多少行，不影响实际导入的行数。文本标签页一次最多显示 100000 个字符，超出的部分不显示，这个上限也只是为了大文件打开时不把界面卡住。按 OK 导入时，用的是当前这套参数（预览行数除外）。

## 编码检测

CSV 文件不需要在界面上选编码。读取前软件用 chardet 抽样检测文件编码，检测置信度低于 0.5 或者根本检测不出编码时按 UTF-8 处理。之后按检测到的编码、UTF-8、gbk、gb2312、gb18030、utf-8-sig、latin1 的顺序逐个尝试，遇到解码错误就换下一个；全部失败时把最后一次的错误报出来，这一次导入不产生数据集。

txt 文件的编码来自向导里的编码下拉框，不做自动检测，所以中文 txt 在向导里选对编码就不会乱码。命令行导入没有编码选项，见下文。

## 工作流里读文件

除了界面上的 Add Data，工作流的 `Data Source` 节点也能把文件读进来，它的可选参数比导入对话框多，适合需要把读取规则固定下来的情况：`file_type` / 文件格式 可选 csv、excel、json、parquet，默认 csv；`encoding` / 文件编码 只在 csv 下有效，默认 utf-8；`separator` / 字段分隔符 也只在 csv 下有效，默认逗号；`sheet_name` / 工作表 只在 excel 下有效，默认填 `0`，也就是第一个工作表，填工作表名或序号都可以。节点读出的数据通过输出端口传给后面的节点，也可以接到输出到数据管理器的节点上让它出现在数据管理面板里。

节点参数与每个端口的含义见[数据分析节点手册](../workflow/nodes-analysis.md)。

## 数据集的名字与描述

导入产生的数据集有两个字段由文件路径决定。

- 名字取文件名去掉扩展名，`2024-sales.csv` 得到 `2024-sales`。
- 描述写的是传入的文件路径，从界面导入时是绝对路径。鼠标停在数据管理面板的条目上，提示气泡里显示的就是它。
- 名字重复时软件在后面补编号：已经存在 `sales` 时，再导入 `sales.csv` 得到 `sales_1`，再下一次得到 `sales_2`。

名字可以在数据管理面板里改，改法见[数据管理面板](./manager.md)；描述目前只能由导入或脚本写入，界面上没有编辑它的入口。

## 一次导入多个文件

Add Data 的文件对话框是单文件模式，连续导入多个文件就重复执行这个动作。命令行可以用多个 `--import-data` 参数一次写完。

## 命令行导入

启动参数 `--import-data` 后面跟一个文件路径，写几次就导入几个文件，程序按顺序逐个执行。下面这行启动软件并依次导入两个文件。

```powershell
& "C:\Program Files\Data Workbench\DAWorkBench.exe" --import-data D:\data\sales.csv --import-data D:\data\cost.xlsx
```

命令里的可执行文件路径按实际安装位置替换，两个 `--import-data` 各带一个文件路径，引号只在路径含空格时需要。命令行这种方式和界面导入有两点差别：它不弹文本文件的导入向导，txt 直接按制表符分隔、第一行作表头读取；txt 的编码没有选项，按默认编码处理，也就是没有界面向导里的编码选择。每个文件导入后同样按文件名起名、按路径写描述，分隔符或编码特殊的 txt 文件走界面导入更稳妥。其它启动参数见[命令行参数](../reference/command-line.md)。

`--import-data` 可以和工程文件参数一起写：第一个位置参数是要打开的工程，程序先打开工程，再把导入的数据加进去，最后才显示主窗口。这样导入的数据集属于这个工程，保存工程时一并写入。

## 用脚本构造数据集

脚本不必经过文件也能把数据放进数据管理面板。下面这段代码用 pandas 造一个小数据框，然后加进数据管理器。

```python
import pandas as pd
import da_app

manager = da_app.getCore().getDataManagerInterface()
df = pd.DataFrame({"x": [1, 2, 3], "y": [4.5, 5.5, 6.5]})
manager.addDataframe(df, "demo_data")
```

第一行导入 pandas，第二行导入软件的应用模块。第三行 `da_app.getCore()` 拿到应用核心，`getDataManagerInterface()` 从核心取出数据管理接口。第四行造一个两列三行的数据框。第五行 `manager.addDataframe(df, "demo_data")` 把数据框包成数据集直接插入，插入后数据管理面板里立刻出现 `demo_data`。

`addDataframe` 不压撤销栈，插入后不能用 Ctrl+Z 撤回。需要可撤销的插入时，用 `da_data.DAData(df)` 把数据框包一层、用 `setName` 起名，再调用 `manager.addData_`。无论用哪种方式，名字都受重名规则约束，重名时会自动补编号。

脚本里读写数据集、修改后通知界面刷新的完整约定见[脚本工作区](../script/workspace.md)。从数据库导入数据目前没有界面入口。

## 常见问题

- 表格里是乱码：CSV 先确认文件是不是 UTF-8 或 gbk 系列编码，检测不到编码时软件按 UTF-8 读，其它编码的文件容易出现这类问题（比如日文 Shift-JIS 编码的 CSV）；把文件另存为 UTF-8 再导入最保险。txt 文件重新用向导导入，在编码下拉框里换一种编码后按「Refresh / 刷新」看预览。
- Excel 文件只读到第一个工作表：导入只读第一个工作表。想读别的工作表，用工作流的 `Data Source` 节点指定工作表。
- txt 导入后只有一列：列没有被分开。检查分隔符，取消「Auto / 自动」后选实际使用的字符，或者在框里填自定义的分隔符。
- 预览里看到的内容比文件少：预览有两个上限，行数由「preview max row: / 预览行数:」限制（默认 1000 行），文本标签页一次最多显示 100000 个字符。两者都只影响预览，实际导入按对话框里的其它参数执行。
- 数据集名字后面多了 `_1`：说明已有同名数据集，软件自动补了编号，改名后再导入不会出现这个问题。
- 同一个文件导入两次：会得到两份互不相关的数据集，各自有名字（第二份带 `_1`），改动其中一份不影响另一份。
- 大文件导入时界面停住：读取在界面线程里同步做完，读到最后一个字节之前界面不响应，文件很大时留出这段时间。
- 消息窗口出现了「Begin importing file」，数据管理面板里却没有新条目：读取失败，文件本身有问题（编码、分隔符、损坏，或者 pkl 里存的不是数据框）。逐项排除后重新导入。
- 导入时提示 Python 相关的问题：读取由 Python 侧完成，解释器没配好时导入不会成功，先检查[设置项说明](../reference/settings.md)里的 Python 页面。
