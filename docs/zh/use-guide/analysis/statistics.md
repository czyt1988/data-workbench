# 描述统计与透视表

统计面板上有两个按钮。第一个把当前表的描述统计一次算出来，生成一份新的统计表；第二个把数据按分组的维度重新排成一张交叉表，也就是透视表。两个动作都不改动原来那张表，结果都是数据管理面板里新增的数据集，可以打开、画图、导出，也可以撤销掉。

统计面板上的两个按钮是整块的大图标按钮，「数据透视表」按钮有提示文字「Create Pivot Table」/ 创建数据透视表，「数据描述」按钮没有提示文字。面板本身只在打开数据表的上下文里出现，切到工作流窗口时整块面板随之隐藏。

面板在 Ribbon 的「DataFrame」上下文标签页、「Operate」/ 操作 分类下，标题是「Statistics」/ 数据统计。打开数据表之后才会出现。

## 两个按钮

| 按钮 | 对话框 | 生成的数据集 |
|---|---|---|
| 「Data Description」/ 数据描述 | 没有对话框，点一下直接执行 | 源数据集名加 `_Describe` 后缀 |
| 「Pivot Table」/ 数据透视表 | 「Pivot Table Guide」/ 数据透视表向导 | 源数据集名加 `_PivotTable` 后缀 |

两个动作都要求数据操作面板里有打开的表。没有打开表时点「数据描述」会收到一条提示，要求先打开要操作的数据表；数据不是表格类型时提示只支持 pandas DataFrame 格式的数据。

生成的数据集会出现在数据管理面板里，同时数据操作面板被抬到前面并把新表打开成一个标签页，工程的未保存标记随之置上。新数据集名的后缀会按界面语言变化：英文界面下是 `_Describe` 和 `_PivotTable`，中文界面下是 `_描述` 和 `_数据透视表`。目标名字已经被占用时，软件自动在末尾加 `_1`、`_2`，不会覆盖已有的数据集。

两个动作都通过数据管理器的撤销命令添加数据集，按 `Ctrl+Z` 可以把刚生成的表去掉，原来的表不受影响。

两个按钮处理的是同一批数据的不同问题：数据描述回答「这一列的数大概在什么范围、集中在哪」，一行一行看趋势之外的总体情况；数据透视表回答「按某个维度分开看，各组的数是多少」，把数据从明细表折成一张交叉表。拿到的数据要不要先分组，是这两个入口的分界。

结果都在数据管理面板里，和导入的数据集并列排在一起，名字带后缀便于分辨。数据操作面板会同时被抬到前面，新表以标签页的形式打开，表格视图里可以直接看内容、改单元格、看列统计。

## Data Description / 数据描述

点这个按钮不弹对话框，直接用 pandas 的 `describe` 在当前表上算一遍，得到一张新表。新表里每一行是一个统计量，每一列是原表的一个数值列，横向对照就是「各列的各项统计量」。

数值列得到的统计量固定是这八项：

| 统计量 | 含义 |
|---|---|
| `count` | 非空取值的个数，空值不计入 |
| `mean` | 平均值 |
| `std` | 标准差，衡量取值围绕平均值散布的宽度 |
| `min` | 最小值 |
| `25%` | 下四分位数，即四分之一的数据不超过这个值 |
| `50%` | 中位数，一半的数据不超过这个值 |
| `75%` | 上四分位数，四分之三的数据不超过这个值 |
| `max` | 最大值 |

三个分位数按 pandas 的默认档位取，也就是 25%、50%、75%，界面上没有改分位数的入口。工作流的 Describe 节点带一个分位数参数，可以填别的档位，见[数据分析节点手册](../workflow/nodes-analysis.md)。

`count` 小于表的行数时，差额就是这一列的空值个数。清洗前后的对照可以只看这一项：填充之后 `count` 应该等于行数，删除缺失值之后行数减少而 `count` 保持等于行数。

拿一张六行的表当例子，两列分别是 temp 和 reading，reading 列第五行为空：

| 统计量 | temp | reading |
|---|---|---|
| `count` | 6 | 5 |
| `mean` | 23.250 | 24.400 |
| `std` | 2.877 | 13.164 |
| `min` | 19.500 | 8.000 |
| `25%` | 21.250 | 15.000 |
| `50%` | 23.250 | 26.000 |
| `75%` | 25.250 | 32.000 |
| `max` | 27.000 | 41.000 |

reading 列的 `count` 是 5 而 temp 列是 6，差额正好是那个空值。reading 列的 `std` 是 13.164，接近它平均值 24.4 的一半，说明这一列的波动很大；temp 列的 `std` 只有 2.877，取值集中在 19 到 27 之间。两列并排放在一张统计表里，哪一列更分散一眼可见。

### 结果怎么读

八项统计量分三组看。位置看 `mean` 和 `50%`：两者接近时分布大致对称，`mean` 明显大于 `50%` 说明右侧拖了长尾，反过来是左侧拖尾。散布看 `std` 和 `25%` 到 `75%` 这半个区间：标准差描述全部数据的波动幅度，容易受极端值影响，四分位区间只描述中间一半的数据。范围看 `min` 和 `max`，它们能暴露录入错误带来的离谱数值。

把 `max` 和 `75%` 比一比也能看出长尾：`max` 比 `75%` 大出很多倍时，这一列里存在远离主体的少数大值，画直方图或箱线图会看得更直观（见[统计绘图](stats-plots.md)）。这些判断不需要额外计算，横向比较生成出来的统计表就能得出。

表里一个数值列都没有时，pandas 转而对文本列做统计，给出的统计量是 `count`、`unique`（不同取值个数）、`top`（出现最多的取值）、`freq`（该取值的出现次数）。混合了数值列和文本列的表只统计数值列，文本列不出现在结果里。一批记录里 batch 列的取值是 A、B、A、A 时，统计结果是 `count` 4、`unique` 2、`top` A、`freq` 3：四条记录、两种取值、出现最多的是 A、A 出现三次。

一列全是空值时，这一列在统计表里的 `count` 是 0，其余七项都空，说明这一列没有任何有效取值，可以交给[数据清洗](cleaning.md)处理或直接删掉。

新数据集的描述文字写的是「Generate descriptive statistics that summarize the central tendency, dispersion and shape of the [源表名]'s distribution, excluding NaN values」/「生成描述性统计数据，总结[源表名]分布的集中趋势、离散度和形状，排除NaN值」，在数据管理面板里悬停或查看属性时能看到。

统计表和其它数据集一样可以编辑：单元格能改，列能删，能导出成 CSV、Excel 等格式，也能直接作为绘图的数据源。它记录的是某个时刻的统计结果，源表之后发生的变化不会自动反映到这张表上，需要重新生成一份。

什么时候用：拿到一份陌生的数据，想知道每一列的量级范围、中心位置和离散程度，这是最快的入口。平均值和中位数差得多，说明分布偏斜或者有极端值；标准差比平均值的绝对值还大，说明取值的波动范围很宽。做清洗之前先看一遍，清洗之后再生成一份对照，能看出填充和删除对分布的影响。

统计范围是整张表的全部行，不分时间也不分组。想按分组看统计量，用本章后面的透视表；想先排除一部分记录再统计，先用[条件筛选](query.md)把范围缩小，再点「Data Description」。清洗和筛选都做过之后再生成统计表，得到的数字才对应最终的数据。

结果里列的排列顺序跟随源表，源表里哪些列是数值列，统计表里就有对应的一列。数据列很多时统计表会很宽，横向对照各列的离散程度正是它的用处。

常见的误读是把统计表当成原表来用：「数据描述」生成的是统计结果，行数是统计量的个数（数值列存在时是 8 行），不是原始记录数。需要按记录继续计算的场合，回到原来的表。

## Pivot Table / 数据透视表

按两个维度把数据分组，再对每组算一个统计量，结果排成一张交叉表。对话框标题是「Pivot Table Guide」/ 数据透视表向导，主体是一张带勾选框的表格，下面三组设置，最后是「OK」和「Cancel」。

### 对话框的设置

勾选表有三列，每列表头是一类角色：

| 表头 | 含义 |
|---|---|
| 「Value」/ 值 | 被统计的那一列，比如读数、浓度 |
| 「Index」/ 索引 | 结果的行方向分组维度，每一行对应它的一个取值 |
| 「Columns」/ 列 | 结果的列方向分组维度，每一列对应它的一个取值 |

表里每一行是一个原表的列名，三个格子里各有一个勾选框，同一行只能勾一个：一个列名要么当值、要么当行分组、要么当列分组，不能同时兼任。每点一行都会同步勾选状态，勾上某一格时这一行另外两格自动取消。

勾选的操作方式：直接点击单元格，勾上的一格再点一次就是取消；某一格勾上之后，同一行另外两格变成不可点，取消之后恢复可选。想改一个列的角色，先取消原来的格子，再勾新的格子。表格按源表的列顺序排列，列多的时候靠滚动来找。

行分组可以勾多列，得到的表就是多级行索引，比如先按设备、同一设备内再按批次。列分组和值列一般各选一个；值列选空时按所有数值列分别统计，表里的文本列会让这一步报类型错误，稳妥做法是明确勾一列值。

下面两组设置跟在表格后面：

| 设置 | 默认 | 说明 |
|---|---|---|
| 「Aggregate function」/ 聚合函数 | mean | 每一组里用哪种统计量汇总 |
| 「Margins」/ 边缘汇总 | 不勾选 | 加上跨类别的合计行和合计列 |
| 合计名称输入框 | `All` | 合计行、合计列的表头名，勾选「Margins」之后才能编辑 |
| 「Sort」/ 数据排序 | 不勾选 | 结果的行列按键值排序，不勾选时按取值出现的先后排列 |

「Margins」的提示气泡写的是「特殊：所有列和行都会添加按行/列类别的部分分组聚合值」，也就是在表的右侧和下方各加一行一列，汇总跨类别之后的结果。合计名称在英文界面下默认 `All`，中文界面下显示为「全部」。

「Sort」的提示气泡是「指定结果是否需要排序」。

没有勾选任何「Index」行时点确定，操作直接结束，不生成任何数据集，也不出现提示。

### 十二种聚合函数

聚合函数决定每一组里把多个取值折成一个数的方式：

| 函数 | 中文 | 含义 |
|---|---|---|
| `mean` | 均值 | 组内取值的平均 |
| `sum` | 求和 | 组内取值相加 |
| `count` | 计数 | 组内非空的取值个数 |
| `size` | 大小 | 组内的行数，空值也计入 |
| `min` | 最小值 | 组内最小的取值 |
| `max` | 最大值 | 组内最大的取值 |
| `median` | 中位数 | 组内取值的中位数，比均值抗极端值 |
| `std` | 标准差 | 组内取值的标准差 |
| `var` | 方差 | 组内取值的方差，标准差的平方 |
| `first` | 第一个 | 组内出现的第一条记录 |
| `last` | 最后一个 | 组内出现的最后一条记录 |
| `prod` | 乘积 | 组内取值相乘 |

`count` 和 `size` 的差别在于空值：一组里有两个取值、其中一个为空时，`count` 给出 1，`size` 给出 2。核对某类记录是否齐全用 `size`，核对某个指标测了几个点用 `count`。

选择依据落在数据的性质上：读数、浓度这类连续量看平均或中位数；把不同批次的产量合并看求和；数一数各类记录有多少条看计数；要看某一类里的最大波动看最大值和标准差；比较批次之间下单时间的早晚看第一个和最后一个。中位数和均值的选择同清洗章节里一样，受极端值影响时用中位数。

### 组合不存在时的空单元格

分组维度交叉出来的组合在原表里没有数据时，结果里对应位置留空，不会补 0。空单元格和「这一组的值是 0」是两件事，解读时先分辨。

汇总时的空值处理还有一点：均值、中位数、求和、最大值这些函数在组内只算非空的取值，空值相当于不存在。一组的读数只有三个有效值时，均值就是这三个数的平均，不是三个数加一个零再除以四。只有「大小」把空值也算进行数，用来核对一天里到底记了几条。两个函数在同一个稀疏数据上给出的数字可以差得很远，先想清楚要回答的是「平均是多少」还是「记了几条」。

如果希望空值按 0 参与汇总，先用[数据清洗](cleaning.md)里的填充缺失值把 0 写进去，再生成透视表。

### 行分组和列分组的搭配

两种搭配覆盖大部分用法。只勾行分组时，结果是一列分组键加一列汇总值，形状像一张分组统计表：分组键有 m 个取值就是 m 行，一行一组，适合「按批次算出平均读数」这类只需一个分组维度的场合。行、列分组各勾一列时，结果是一张二维交叉表，两个维度取值组合起来看，适合「按批次和站点交叉对比」这类要同时看两个维度的场合。

只勾行分组时，「Margins」只在表的下方加一行合计；行、列都勾时，右侧和下方各加一行一列。合计行、列算的是明细数据的汇总，与各格数字的关系可以交叉核对。

### 生成的数据集

结果写成一份新的数据集，名字是源数据集名加 `_PivotTable`（中文界面下是 `_数据透视表`），描述文字为「生成[源表名]的数据透视表」。透视表在数据管理面板里就是一份普通的数据表，可以接着做筛选、画成颜色块形式的汇总图（见[统计绘图](stats-plots.md)热力图一节）、导出成文件；原来的表保持原样。

### 一个例子

一张三行三列的小表：

| batch | site | reading |
|---|---|---|
| A | S1 | 1.0 |
| A | S2 | 3.0 |
| B | S1 | 5.0 |

把 `reading` 勾成值、`batch` 勾成索引、`site` 勾成列，聚合函数用默认的均值，得到两行两列的表。A 行的 S1 是 1.0、S2 是 3.0；B 行只有 S1 是 5.0，S2 那一格留空。把「Margins」勾上，右侧多一列「全部」，给出每一行跨站点的均值；下方多一行「全部」，给出每个站点跨批次的均值，右下角是全部数据的均值。

| batch \ site | S1 | S2 | 全部 |
|---|---|---|---|
| A | 1.0 | 3.0 | 2.0 |
| B | 5.0 | 空 | 5.0 |
| 全部 | 3.0 | 3.0 | 3.0 |

A 行的「全部」是 1.0 和 3.0 的平均值 2.0，B 行只有一条记录所以「全部」仍是 5.0，右下角的 3.0 是三条记录的均值。同一张表把聚合函数换成「大小」，得到的是各组里的记录条数。

### 使用场合

三类问题适合直接用透视表回答。第一类是分组对比：不同设备、不同批次、不同处理条件下的平均读数是多少。第二类是分组计数：每个月、每个类别各有多少条记录，把聚合函数换成「大小」即可。第三类是把两张表的信息压成一张交叉表，比如样品编号做行、检测项目做列、结果做值，一眼看出哪些组合缺数据（空格子）。

分组维度超过两个时，透视表只能表达行、列两个方向，第三个维度的信息要靠多次执行或者先筛选出子集。

### 结果的形状

透视表结果的形状由分组维度的取值个数决定，和原表的行数没有直接关系。行分组有 m 个取值、列分组有 n 个取值时，结果最多是 m 行 n 列，加上「Margins」再多一行一列。原表有一万条记录、行分组只有三个取值时，结果只有三行；反过来，行分组勾了两列而每列取值很多时，结果的行数可能接近原表的行数，分组就失去了汇总的意义。

分辨分组维度选得是否合适，看结果的行数与分组取值的个数是否量级相当。行分组取值太多时，可以先在源表里用[条件筛选](query.md)缩小范围，或者把取值多的列移到列方向。

## 同样的统计量在另外三个地方

描述统计在软件里有四个入口，算的都是同一套 pandas 描述统计，数字一致，区别只在结果的形式与使用场合。

1. Ribbon 的「Data Description」按钮，本章上面一节，结果是数据管理面板里的一张新数据集。
2. 表格视图里在列标题上点右键，选「Show Statistics」/ 显示统计信息，弹出「Column Statistics」/ 列统计 对话框，显示「列：」和「类型：」两行信息，下面是一张「统计量」/「值」两列的小表。这一列是文本列时，表里给的是 `count`、`unique`、`top`、`freq`。入口位置和列标题菜单的其它项见[表格视图](../data/table.md)。
3. 工作流的 Describe 节点，参数里可以填分位数，结果接到其它节点继续处理，适合把描述统计固定成流程的一步，见[数据分析节点手册](../workflow/nodes-analysis.md)。
4. 智能体的 `get_column_stats` 工具，参数是数据集名和列名，返回这一列的描述统计，另外附带一个缺失值个数，供对话里直接引用，见[内置工具](../agent/tools.md)。

四个入口给的都是同一列（或同一批列）的描述统计量。看单个列用右键菜单，看整张表用面板按钮，要把统计结果继续参与计算用工作流节点，要在对话里问一句用智能体工具。

统计表拿到手之后，下一步通常是画图：一列数值的分布用直方图或核密度曲线，多列之间比高低用箱线图，透视表的结果想要颜色块形式见[统计绘图](stats-plots.md)里热力图一节的替代做法。图和数字互相印证，单看统计量看不出双峰、异常平台这类形状问题。

透视表的结果本身也是一份普通数据集，可以继续走后面几步：对它再做一次数据描述，看各组统计量的整体情况；把它作为「Add Cloud Map」/ 云图 的数据源，画成颜色块形式的汇总图（见[统计绘图](stats-plots.md)热力图一节）；导出成 CSV 或 Excel，贴进报告；也可以在原表上换一个聚合函数再生成一份，两张透视表对照着看。

统计结果不参与源表的后续计算。源表在清洗、筛选中变化之后，之前生成的统计表和透视表都停留在生成时的数字上，需要重新执行一次拿到新的结果。

## 软件里没有的分析功能

假设检验（t 检验、卡方检验、方差分析）、相关系数矩阵、聚类、主成分分析、时间序列模型在软件界面上都没有入口，按功能名在面板、菜单和对话框里找不会有结果。需要的读者可以在[脚本工作区](../script/workspace.md)里用 Python 现成的库自己算，或者把计算写进工作流的 Python 节点，结果再作为数据集放回数据管理面板。

## 常见问题

点了「Data Description」却没看到结果。结果是一份新的数据集，去数据管理面板找名字以 `_Describe`（中文界面下是 `_描述`）结尾的条目；数据操作面板同时会被抬到前面并打开这张新表。

统计结果里只有一列或只有几列。`describe` 默认只处理数值列，文本列不参与；表里一个数值列都没有时，结果变成文本列的四项统计。想统计某一列文本的取值分布，用列标题右键菜单里的「Show Statistics」。

`count` 比表里的行数少。差额就是空值的个数。需要把空值处理掉再看统计，先用[数据清洗](cleaning.md)里的填充或删除动作。

透视表里出现空单元格。分组维度交叉出的组合在原表里没有对应的记录，这种情况留空。想区分「没有记录」和「记录里这一项是空」，把聚合函数换成「大小」，有记录的组合会给出条数。

透视表的行数比预期多。勾了多列作为行索引时，结果的每一行对应这些列取值的组合，组合数会成倍增加。先把行索引缩到一列，确认结果的样子之后再增加维度。

生成的数据集不想要了。按 `Ctrl+Z` 撤销添加操作，数据集从数据管理面板移除。已经保存过工程的话，重新打开工程时以保存时的内容为准。

同一个源数据集上执行两次「Data Description」。第二次生成的名字会自动加后缀，出现 `_Describe` 与 `_Describe_1` 两份表。想比较清洗前后的统计量时这样用没有问题，注意别把两份表的名字看混。

透视表点确定后没有反应。检查「Index」列里是否勾了至少一行，一行都没勾时操作直接结束，也不给提示。

聚合函数选「大小」并勾上「Margins」。分组组合稀疏时，这一步在某些数据上会报错，结果不生成。先把「Margins」取消，拿到各组条数之后再单独算合计。

透视表结果里的数字和手算对不上。检查三处：这一组里有没有空值（均值跳过空值，大小不跳过）；「Margins」给出的合计是按明细数据算的还是按各组数字再平均（软件按明细数据算）；行分组勾了几列（多列组合会把明细拆得更细）。

数据描述的统计表和源表的数据对不上。统计表算完之后源表又被改过时会出现这种情况。源表一变，统计表就是旧数字，需要重新生成一份，或者按 `Ctrl+Z` 撤销后再执行。

统计表里出现了 `unique`、`top`、`freq` 这些没见过的行。说明源表里一个数值列都没有（或者选中的表整张都是文本），pandas 改成统计文本列，返回的就是这四项。把文本列改成数值列再执行，或者用列标题右键菜单看单列的文本取值情况。

合计行的名字不是「全部」。合计名称输入框里的文字直接写进结果，默认值随界面语言变化（英文 `All`、中文「全部」）。在输入框里改成别的名字，结果里合计行列的表头就是那个名字。

同一个分组维度勾成了行又勾列。同一个列名没法同时占两个角色，勾了行的格子之后，这一行的列格子变成不可点。需要同一维度在两个方向上都出现时，先复制一列（用[数值计算](query.md)把这一列赋给一个新名字，如 `site2 = site`），再分别勾这两个列名。复制出来的列与原来那一列取值完全一致，两个方向的分组结果可以对照。

先筛选再统计还是先统计再筛选。两者结果不同：先筛选是对留下来的记录算统计量，先统计是把全部记录算完再从统计表里挑行。要看子集的真实统计量，用先筛选再统计的顺序。
