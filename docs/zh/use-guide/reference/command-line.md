# 命令行参数

软件可以带参数从命令行启动，双击 `.dapro` 工程文件启动时用的是同一个入口。可用的参数一共五个：一个位置参数和四个选项，其中 `--help` 与 `--version` 是命令行解析器自带的标准选项。这一章逐个说明它们的写法、执行结果和看到的现象，最后按用户视角列出启动顺序。参数之外没有别的开关，界面上的功能都能在软件里点出来。

命令行里的可执行文件路径按实际安装位置替换。本章的示例统一写成 `DAWorkBench.exe`，装在 `C:\Program Files\DAWorkBench\` 下的机器上写成完整路径并加引号。

```bash
"C:\Program Files\DAWorkBench\DAWorkBench.exe" --version
```

路径里有空格时必须用引号包起来，没有空格时引号也可以省略。参数之间的顺序不影响结果，位置参数放在哪里都能被识别。

四个参数先列在一起，方便对照，各自的细节见下文各节。

| 参数 | 形式 | 作用 | 备注 |
|------|------|------|------|
| 工程文件路径 | 一个路径，不带前缀 | 启动后打开这个工程 | 最多一个，路径必须存在 |
| `--import-data` | `--import-data <路径>` | 启动时导入数据文件 | 可以出现多次，按顺序执行 |
| `--no-splash` | 开关，没有取值 | 本次启动不显示启动画面 | 还要看设置里的启动画面开关 |
| `--help` | 开关，没有取值 | 打印帮助文字后退出 | 短形式 `-h` |
| `--version` | 开关，没有取值 | 打印版本号后退出 | 短形式 `-v` |

## 工程文件路径

位置参数是一个工程文件路径。文件存在时，软件启动后直接打开这个工程，效果和启动之后点 `Open` / 打开 选择这个文件一样：工作流、数据集、绘图、打开过的数据页全部按保存时的样子恢复，见[工程文件](../getting-started/project.md)。

```bash
DAWorkBench.exe "D:\proj\exp1.dapro"
```

这条命令启动软件并打开 `exp1.dapro`。在文件管理器里双击一个 `.dapro` 文件，操作系统把文件路径作为位置参数传给软件，走的是同一条路径；先选中文件再选「打开方式」指向本程序，效果相同。

第一次双击工程文件时，系统可能弹出选择程序的对话框，选中本程序并勾选始终使用，之后双击就直接打开。系统里装了多个能处理 `.dapro` 的程序时，关联指向哪一个由系统的默认应用设置决定，表现为双击后打开了别的程序，把关联改回本程序即可。

位置参数的识别有两条规则：路径必须存在，且位置参数的个数必须正好是一个。给两个路径时软件不会打开其中任何一个，只按空工程启动；路径不存在时同样按空工程启动，不弹错误提示。工程打不开时先把路径单独跑一次确认拼写。

位置参数指向目录、指向非工程文件、或者给出的工程文件本身损坏时，都按打不开处理；工程文件损坏时软件会先给当前工程做一份快照再尝试加载，加载失败时把旧工程恢复回来并在状态栏提示，见[工程文件](../getting-started/project.md)。

路径可以写成绝对路径，也可以写成相对路径；相对路径按执行这条命令时的当前目录解析，而不是按软件安装目录。写批处理或快捷方式时用绝对路径，避免从别的目录执行时找不到文件。

工程打开成功后这个路径会被记进「Recent Files」/ 最近文件 列表，条数上限在设置的高级页调整。启动时的工作目录与工程位置无关，脚本里的相对路径相对脚本工作区，见[脚本工作区](../script/workspace.md)。

写错的选项名会让参数解析失败，软件给出错误提示后直接退出，不进入界面。核对拼写时以本章列出的参数为准。

## --import-data

`--import-data` 在启动时导入数据文件，参数是文件路径。这个选项可以出现多次，软件按出现顺序逐个导入，每个文件成为一个数据集；支持的后缀与界面导入一致，常见的是 `csv`、`xlsx`、`txt`、`pkl`，完整清单见[导入数据](../data/import.md)。

```bash
DAWorkBench.exe --import-data "D:\data\run1.csv" --import-data "D:\data\run2.xlsx"
```

这条命令启动软件，窗口显示之后依次导入两个文件。每导入一个，数据管理面板被抬到前面，数据集名称取文件名去掉后缀，描述写命令行里给出的那个路径；「Log」/ 消息 面板里出现 `Begin importing file: %1` / 开始导入文件:%1 的记录。导入成功后工程被标记为有未保存改动，窗口标题上出现星号。

与工程路径可以写在同一条命令里，软件先打开工程再导入数据，顺序固定。

```bash
DAWorkBench.exe "D:\proj\exp1.dapro" --import-data "D:\data\new.csv"
```

这条命令打开 `exp1.dapro`，再把 `new.csv` 加进这个工程的数据管理面板。数据不会自动存进工程文件，需要自己保存一次。

命令行导入与界面导入有两处差别。它不弹文本文件的导入向导，`.txt` 直接按制表符分隔、第一行作表头读取，分隔符或编码特殊的文本文件走界面的 `Add \nData` 更稳妥；编码没有选择项，按默认处理。另外，Python 解释器没有配好时导入不会成功，消息面板里出现 `Python scripts not initialized, cannot import file: %1` / Python脚本未初始化，无法导入文件:%1，处理办法见[常见故障](../reference/troubleshooting.md)。

不带工程路径运行时，导入落在启动时的空工程里，导入完成后同样要自己保存一次才能留下。一次要导入同一个目录下的一批文件时，用脚本拼出重复的选项比手写一长串更省事。

```powershell
$exe = "C:\Program Files\DAWorkBench\DAWorkBench.exe"
$opts = Get-ChildItem "D:\data\*.csv" | ForEach-Object { "--import-data"; $_.FullName }
& $exe @opts
```

这段 PowerShell 先取出 `D:\data` 下所有 CSV 文件的完整路径，再为每个文件生成一对 `--import-data` 和路径，最后一次性传给软件。`@opts` 的写法把数组展开成多个独立参数；文件名里有空格时，展开后的参数不需要额外引号。导入顺序与文件列举顺序一致，`Get-ChildItem` 的默认顺序按名称排序。

某一次导入失败（路径不存在、文件被占用、内容读不出来）不会中断后面的导入：那一次不产生数据集，其余文件照常导入，失败原因写在 Python 侧的日志文件里，见[常见故障](../reference/troubleshooting.md)。启动完成后核对导入结果，看数据管理面板里实际多出了几个数据集。

## --no-splash

`--no-splash` 关闭启动画面。启动画面是启动阶段显示的那个小窗口，上面依次显示「正在初始化」「正在初始化核心组件」「正在加载用户界面」这些进度文字。

```bash
DAWorkBench.exe --no-splash
```

这条命令启动时直接进入主窗口，不显示启动画面。适合调试时使用：启动画面会停留在屏幕上遮挡代码编辑器窗口。

启动画面还受设置对话框高级页的 `Show splash screen on startup` / 启动时显示启动画面 控制，两者是「与」的关系：配置项关掉之后，命令行不带这个参数也不显示；配置项打开时才由这个参数决定本次是否跳过。启动画面的背景图可以在可执行文件目录下放一张 `splash.png` 替换。

关掉启动画面只影响这个窗口本身，初始化流程和耗时不变，启动过程中软件照常读取配置、启动解释器、加载插件。平时用不到这个参数，它主要服务于调试和屏幕空间紧张的情况。

## --help 与 -h

`--help` 打印帮助文字，短形式是 `-h`。帮助里包含应用描述、位置参数和每个选项的说明文字。

```bash
"C:\Program Files\DAWorkBench\DAWorkBench.exe" --help > help.txt
```

这条命令把帮助文字写进 `help.txt` 再用编辑器打开查看。输出里的第一段是应用描述，形式是 `version:<版本号>,compile datetime:<编译时间>`，接着是用法行、位置参数 `[project]` 及说明 `The project file to open` / 要打开的工程文件，然后是 `--import-data <path>` 与 `--no-splash` 两项及各自的说明，最后是 `-h`、`-v` 这些标准选项。

帮助文字写到标准输出。在命令提示符里执行时如果看不到输出，用上面的重定向写法把内容存成文件；软件是窗口程序，终端不一定会显示它的标准输出。

`--help` 和短形式 `-h` 在创建主窗口之前处理，打印完帮助文字进程直接结束，不会出现软件窗口。想核对某个选项的官方说明（比如 `--import-data` 的取值名和格式清单）时用这个参数，比翻手册更快。

## --version 与 -v

`--version` 打印软件名称和版本号，短形式是 `-v`。

```bash
DAWorkBench.exe --version
```

这条命令输出的内容形如 `DAWorkbench 0.1.1`，数字是当前安装版本的版本号，随安装包变化。编译时间不在这一行里，它在 `--help` 的应用描述里显示。没有图形界面的机器上核对安装版本时用这个参数，短形式 `-v` 的输出相同。

在软件界面里也能看到版本号：主页「Config」/ 配置 面板里的 `About` 打开关于对话框，里面显示软件名称和版本。两种方式看到的是同一个版本号，命令行版本更适合写进脚本或安装检查。

短形式的用法与长形式完全一致，下面的命令输出同样的版本行。

```bash
DAWorkBench.exe -v
```

这一行适合放进安装脚本或启动前检查：读取输出里的版本号，与预期版本比较即可判断安装是否更新。和 `--help` 一样，这个参数处理完就退出进程，不进入界面。

## 启动顺序

从命令行启动到进入可用界面，软件按下面的顺序执行，知道这个顺序就能解释启动时看到的现象。

1. 早期加载程序配置，读取界面语言、字体、日志参数、启动画面开关、解释器路径这些启动阶段就要用的项。
2. 初始化日志，把日志写到用户 AppData 目录下的日志文件。
3. 启动 Python 解释器。解释器在窗口出现之前就要就绪，所以解释器缺失或路径错误的表现是启动阶段的提示，而不是某个按钮点下去没反应。
4. 建立应用对象并解析命令行参数，决定好这一次要打开的工程和要导入的文件。
5. 应用字体和界面语言，显示启动画面，启动画面上出现「正在初始化」「正在初始化核心组件」等文字。
6. 初始化核心功能与插件，建出主窗口，填充节点工具箱。
7. 打开位置参数指定的工程，启动画面上出现 `Opening project...` / 正在打开工程。
8. 逐个执行 `--import-data` 指定的导入，启动画面上出现 `Importing data...` / 正在导入数据。
9. 启动画面显示 `Ready` / 启动完成 后关闭，主窗口显示出来。

第 3 步在窗口出现之前，因此「系统里没有找到 Python」这类问题在界面上表现为启动时日志里的一行提示，之后所有依赖 Python 的功能不可用；第 7 步和第 8 步在插件和主窗口准备好之后，所以导入失败时窗口已经可见，提示落在「Log」/ 消息 面板里。

启动时收到的参数会逐条记进日志文件，排查「为什么没有打开工程」「为什么没有导入」这类问题时，日志里的参数列表能确认操作系统实际传进来的内容，日志文件的位置见[常见故障](../reference/troubleshooting.md)。

启动过程中任何一步失败都记进日志：解释器起不来、插件加载失败、工程打不开、导入失败都不会让程序崩溃，按日志里的提示逐项处理即可。
