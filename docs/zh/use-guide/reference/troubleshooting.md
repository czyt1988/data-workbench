# 常见故障

这一章按现象组织：每个小节先写看到的表现，再按可能性从高到低列出原因，最后给出确认和处理的步骤。多数问题在「Log」/ 消息 面板和日志文件里已经留下了提示，动手之前先把最近的提示读一遍。

## 排查之前先做四件事

第一，看「Log」/ 消息 面板。它是软件专门写给使用者看的消息出口，启动失败、加载失败、运行失败都会在这里留一行。面板被关掉时，到视图标签页的「Display」/ 视图显示 面板里点 `Show Information Window` / 信息窗口 找回来。

第二，判断问题是不是与 Python 有关。导入导出、数据分析面板、工作流里的 Python 节点、统计绘图的计算、智能体的全部工具都跑在同一个解释器上；这些功能一起失效、而界面本身正常时，直接按下面 Python 一节处理。

第三，保存工程并重启软件一次。插件、解释器、日志参数这类项在启动阶段读取，重启能排除一批「改了没生效」的情况；工作流与脚本的问题在重启后仍可复现时再往下查。

第四，用最小步骤复现一次。能用一个新开的空工程重复出同样的现象，说明与具体数据无关，问题在环境或设置上，按 Python、插件这类环境相关的小节查；只有在某个工程里才出现时，问题多半与这个工程的数据、脚本或工作区内容有关，从这份工程本身入手。判断现象是否可复现，也让后面收集的信息更有价值。

不确定从哪一节看起时，按现象查下表。

| 现象 | 小节 |
|------|------|
| 插件没出现，或 Ribbon 上少了按钮和面板 | 插件没有加载，或者从 Ribbon 上消失 |
| 启动画面长时间停在某一行 | 启动很慢，或者启动画面长时间不动 |
| 导入、分析按钮、工作流节点、智能体一起失效 | 提示找不到 Python 解释器 |
| 清洗、筛选、统计按钮点了没有对话框 | 数据分析的按钮点了没有反应 |
| 脚本报 `ModuleNotFoundError` | 脚本导入第三方包失败 |
| 点运行工作流被拦下 | 工作流拒绝运行 |
| 节点一直不动、不变色 | 工作流节点一直停在等待的黄色 |
| 节点变红、消息面板报工作流执行失败 | 工作流节点报错 |
| 跑完工作流但面板里没有新数据集 | 运行完工作流，数据管理面板里没有新数据集 |
| 热力图确认后图上空白 | 统计绘图的热力图确认之后图上没有内容 |
| 智能体不回复、提示未配置模型 | 智能体提示没有配置模型，或者连不上模型 |
| 审批卡片反复出现 | 智能体工具反复要求审批，或者被拒绝 |
| 换工程后旧会话还在跑 | 切换工程后旧工程的会话还在后台跑 |
| 脚本运行后窗口长时间无响应 | 脚本卡住或者超时 |
| 要看日志文件或转储文件 | 日志文件和崩溃转储在哪里 |
| 面板不见了、按钮换位置了 | 界面上的面板或按钮找不到了 |
| 工程打不开、打开后少东西 | 工程打不开，或者打开后内容不全 |
| 表格里粘贴没反应 | 表格里复制粘贴不按预期工作 |
| 画好的图找不到了 | 图上的图表不见了 |

## 启动很慢，或者启动画面长时间不动

症状是双击图标后很久才出现主窗口，或者启动画面停在一行文字上不再前进。

启动画面上的文字就是进度指示。「正在初始化」出现在启动画面刚亮起时；「正在初始化核心组件」对应初始化核心功能与加载插件；「正在加载用户界面」对应建主窗口、填充节点工具箱；「正在打开工程」与「正在导入数据」对应用位置参数与导入命令处理的部分，各阶段的完整顺序见[命令行参数](./command-line.md)的启动顺序一节。

启动后连启动画面都长时间不出现，说明停在更早的阶段（读配置、初始化日志、启动解释器）；停在「正在初始化核心组件」阶段多半是某个插件初始化慢或失败，按插件一节检查状态与错误提示；停在打开工程阶段时看工程文件是否很大，数据集与脚本工作区随工程保存，体积大的工程解压本身就要时间，体积来源见[工程文件](../getting-started/project.md)。

启动画面关掉之后看不到这些阶段文字，判断手段换成日志文件：日志按时间顺序记录启动过程，最后一条记录对应卡住的位置。启动画面本身不影响初始化耗时，关掉它只是少一个窗口。

## 插件没有加载，或者从 Ribbon 上消失

症状有三种：插件管理器里根本没有这一行；有这一行但状态不是已加载；状态正常而 Ribbon 上看不到它加的面板。

按可能性从高到低检查：

1. 文件没有放进扫描目录。C++ 插件要放在可执行文件目录下的 `plugins` 子目录，后缀在 Windows 上是 `dll`；Python 节点包要放在同级的 `pyplugins/<包名>`，目录里必须有 `__init__.py`。位置或后缀不对时管理器里不会出现这一行，日志和消息面板里留下一行「忽略无效文件」。核对插件目录的最快办法是从 Ribbon 主页的「Config」/ 配置 面板打开 `Plugin Config` / 插件设置，看列表里实际有哪些名字，再回到磁盘上对比。
2. 名字被写进了 `.pluginignore`。管理器中这一行的状态是 `Disabled` / 已禁用，勾选这一行再点 `Apply` / 应用 即可；C++ 插件当场载入，Python 节点包要重启软件，分组标题里直接写明了这一点。
3. 载入过程报错。状态显示 `Load Failed` / 加载失败，把鼠标停在状态列上读提示气泡里的错误文本；同样的文本也写进日志与消息面板。修好之后勾选并应用再试一次，仍然失败就重启，让启动阶段在干净状态下重新尝试。
4. Python 节点包根本没被扫描。解释器不可用时整套 Python 节点发现跳过，先处理下一节，再回头看这一包是否出现。
5. Ribbon 上少了内容但插件是加载状态。先确认看的是不是上下文标签页：按当前操作对象出现的标签页只在打开对应对象时出现，先用「Data Manager」/ 数据管理 面板双击打开一个数据表，再切回「DataFrame」/ 数据表 上下文页找插件加的面板。插件也可能在运行期主动隐藏过自己的面板。

插件目录、状态含义和启停规则的完整说明见[插件管理](../plugin/manager.md)。

## 提示找不到 Python 解释器

症状集中在依赖 Python 的功能上：导入数据失败、数据分析面板的按钮点了没有结果、工作流里的 Python 节点执行失败、智能体的工具全部不可用，界面其余部分正常。日志和消息面板里出现 `Python interpreter not initialized`、`Python scripts not initialized` 或 `Python node discovery failed` 一类的记录。

按顺序检查这些原因：

1. 系统里没有装 Python。按[安装与首次启动](../getting-started/install.md)的说明装一个受支持的解释器。
2. 装了但不在系统 PATH 里。在设置对话框 Python 页用 `Browse` 手工指向解释器文件。
3. 设置里保存的路径失效。Python 被卸载、升级或换了目录之后旧路径不再存在，用 `Auto Detect` / 自动检测 重新找，或者手工指定。
4. 解释器能启动但环境缺依赖包。表现为导入数据或节点执行失败，往这个解释器里安装依赖，方法见下一节。

处理入口是设置对话框的 Python 页：Ribbon 主页「Config」/ 配置 面板点 `Setting` / 设置，切到 Python 页。点 `Auto Detect` / 自动检测 让软件在 PATH 里找，或者用 `Browse` 指定解释器；点 `Test` / 测试 确认能启动，结果显示解释器版本，或者 `Please specify a Python interpreter path`、`File does not exist: %1`、`Failed to run: %1` 这类提示。路径改动在重启软件后生效。

解释器路径还有一个副本在可执行文件目录下的 `python-config.json` 里，点应用保存设置时会同步写入。软件启动时先读配置，再读这个文件，最后到 PATH 里找，三个都失败时整套 Python 功能不可用。

设置项的默认值与作用见[设置项说明](../reference/settings.md)，首次安装时的配置步骤见[安装与首次启动](../getting-started/install.md)。

## 数据分析的按钮点了没有反应

症状是 Ribbon 数据表上下文里的清洗、筛选、统计按钮点下去没有对话框，或者统计绘图的引导对话框确认后没有结果，`Data Description` / 数据描述 没有生成新数据集。

按可能性依次检查：

1. Python 解释器不可用。这一组按钮的参数表单与统计计算都由 Python 侧完成，解释器缺失时界面按钮还在但点不出结果，处理办法见上一节。
2. 数据分析插件被停用。到主页「Config」/ 配置 面板打开 `Plugin Config` / 插件设置，确认数据分析插件的行都是启用状态；它对应的 Python 节点包改动后要重启软件。
3. 没有打开数据表。这些按钮在「DataFrame」/ 数据表 上下文标签页里，没有打开任何数据表时整个标签页都不出现，先从「Data Manager」/ 数据管理 面板双击打开一个数据集；「Statistics」/ 统计 面板里的按钮作用于当前打开的那张表。
4. 参数没填全。统计绘图的引导对话框里没选数据列时对话框不会关闭，消息面板里给出要求先选列的提示；热力图和二维核密度需要两个方向的列，缺一个也会有同类提示。点 `OK` 之后图才画出来，只打开对话框不会有结果；这些图表画进当前坐标系，当前没有绘图时软件会先建一个绘图和一个坐标系。
5. 行数或有效值太少。核密度这类计算要求一列里至少有若干个不同的取值，数据量太少时计算失败，消息面板里的文字会指出是哪一列出的问题，先补齐数据再试。

九种统计图各自需要什么数据、参数怎么填见[统计绘图](../analysis/stats-plots.md)，清洗与筛选的操作见[数据清洗](../analysis/cleaning.md)与[筛选、计算与排序](../analysis/query.md)。

## 脚本导入第三方包失败

症状是脚本执行到 `import` 这一行停下，返回值里 `success` 为假，错误字段里是 `ModuleNotFoundError: No module named '...'`。

按可能性从高到低检查：

1. 包装在另一个 Python 环境里。机器上常装有两三个 Python，软件用的是设置里指定的那一个，命令行里直接敲 `pip` 装的却可能是另一个。确认软件实际使用的解释器路径（设置对话框 Python 页里显示的就是它），用完整路径安装：`<解释器路径> -m pip install <包名>`。
2. 包名拼写不对或版本过旧。装之前先确认包名；同名包在 pip 上有多个时按文档给出的名字装。
3. 包装在非标准目录里。把该目录加进 Python 页的 `Extra module search paths (sys.path)` 列表并重启，见[设置项说明](../reference/settings.md)。
4. 导入的是软件自己的模块。`da_app`、`da_interface`、`da_data`、`da_pyplot`、`da_figure` 只在软件进程里存在，把同一段代码放到系统里另装的 Python 上执行会失败，属于正常情况。

装完在脚本里 import 一次并 `print(__version__)` 验证，版本号打不出来说明装的还是另一个环境。软件的安装包里不带这些第三方包，仓库根目录的 `requirements.txt` 列出了常用的一组，完整清单与安装方法见[脚本工作区](../script/workspace.md)。

## 工作流拒绝运行

症状是点了「Run Workflow」/ 运行工作流 没有开始执行，或者弹出标题为「Warning」/ 警告 的提示框，内容是 `Before running the workflow, you need to save the project` / 在运行工作流之前，需要先保存工程。

按可能性依次检查：

1. 工程还没有保存过。脚本节点没有可用的工作目录，运行入口直接拦下；先保存工程一次，之后再改节点参数不需要每次重新保存，运行时用的是内存里的当前状态。
2. 找不到运行按钮。运行和停止在「Workflow」/ 工作流 上下文标签页的「Workflow Run」/ 工作流运行 页里，这个标签只在工作流区获得焦点时出现；点一下工作流画布把上下文标签切回来，标签页与面板的位置见[主界面](../getting-started/main-window.md)。
3. 节点类型来自被停用的插件。提供这个节点的插件或 Python 节点包被停用时节点不能执行，先把它启用并重启，启用状态见[插件管理](../plugin/manager.md)。
4. 点到的是别的运行按钮。绘图与数据区没有「运行」入口，功能相近的按钮名称见[工作流基础](../workflow/basics.md)的运行一节。

运行前的准备、运行过程与停止按钮的现状见[工作流基础](../workflow/basics.md)。

## 工作流节点一直停在等待的黄色

症状是运行结束后画布上仍有节点是黄色半透明边框，本次运行没有执行到它们。

按可能性依次检查：

1. 它上游有红色边框的节点。失败的节点不会向下游送数据，下游收不齐输入就停在等待状态，先按下一节修好上游。
2. 它上游是条件分支。`If / Else` 只有被选中的那一路有数据，另一路的节点每次都停在等待状态，两个分支一黄一绿是正常现象；两条路都没数据时看分支的条件表达式。
3. 连接接错了端口。输出端口和输入端口不对应时数据送不到，按端口名核对，见[工作流基础](../workflow/basics.md)的连线一节。
4. 节点需要多路输入都到齐。接到终点节点或需要两条上游数据的节点，只到了一条就不会执行；一个节点的多个输入端口要各自连上数据源。
5. 上游是延迟节点。等待时间没走完之前下游不会开始，画面上表现为运行中的绿色半透明边框停留较久，`Delay` 节点的参数含义见[系统节点手册](../workflow/nodes-system.md)。

确认本轮运行已经结束（按钮状态换回、消息面板里没有失败记录）之后，改参数或数据再点一次运行，所有节点先统一变成等待的黄色，再按新一轮的结果重新上色。上一轮留下的颜色不会自己消失，重新打开工程也会清掉。节点颜色与状态的一一对应见[工作流基础](../workflow/basics.md)。

## 工作流节点报错

症状是运行结束后某个节点是红色边框，消息面板里出现 `Workflow execution failed` / 工作流执行失败，画布上没有更多信息。

按下面的顺序定位原因：

1. 看画布上哪个节点是红色的，那是出错的位置；它下游的黄色节点是这一轮没有执行到的部分。
2. 打开「Log」/ 消息 面板确认失败记录，里面只有一行总体结果，细节在日志文件里。
3. 打开日志文件，在文件末尾附近搜 `Workflow error`，每条错误的格式是 `Node '<节点标识>' execution exception: <异常内容>`。节点标识是节点类型加序号，用它回到画布上找对应节点。
4. 异常来自节点内部的 Python 代码时（比如 pandas 报列名不存在），同一目录下的 Python 日志里有更完整的输出，文件位置见本章的日志一节。
5. 修好参数或数据之后重新运行，整张图从头再跑，失败的节点不保留上一轮的中间结果。

常见原因集中在参数上：文件路径不存在或写错、条件表达式里的列名与数据里的列名不一致、数值参数填成了文字、上游输出端口送来的数据类型与这一步的预期不符。两本节点手册给出每个参数的含义与常见错误，见[系统节点手册](../workflow/nodes-system.md)与[数据分析节点手册](../workflow/nodes-analysis.md)。参数填错不会在运行前被发现：运行入口不做前置检查，错误要等执行到那个节点时才暴露。

## 统计绘图的热力图确认之后图上没有内容

症状是在「Figure」/ 绘图 页的「Stats Plot」/ 统计绘图 面板里点 `Heatmap` / 热力图，在引导对话框里选好行列与数值列，点 `OK` 之后坐标系上没有任何东西。

这一项在当前版本里不会画到坐标系上：对话框里的行列选择没有传到绘图环节，点确认不产生图元。这不是操作错误，也不是参数没填对，重复尝试或换列都不会有结果。九种统计图里只有热力图有这个问题，其余八种正常。

确认这不是其它问题的连带表现：点其它统计图按钮（比如箱线图或柱状图）能正常出图，说明绘图这一套流程本身是通的；点任何图都没有结果时，按前面的 Python 一节处理。

需要热力图效果时用等效路线：先在[描述统计与透视表](../analysis/statistics.md)里用数据透视表把两列分类列交叉成一张矩阵数据集，再到「Figure」/ 绘图 页的「Add Chart」/ 添加绘图 面板里用 `Add Cloud Map` / 添加云图 建一张谱图，数据选这张透视表，行列标签和配色在[创建图表](../chart/create.md)的建图向导里设置。工作流的 `Data Plot` 节点与脚本里的 `da_pyplot` 也能画出同一张图，两条路线分别见[数据分析节点手册](../workflow/nodes-analysis.md)与[脚本工作区](../script/workspace.md)。

## 智能体提示没有配置模型，或者连不上模型

症状是发消息后收到 `LLM is not configured. Please configure LLM in settings first.`，会话状态栏的模型选择器显示 `No model`；或者消息一直等待、反复重试、最后报连接失败。

按可能性依次检查：

1. 没有配置供应商或没有选中模型。打开设置对话框的 Agent LLM Settings / Agent LLM 设置 页，在「Model Providers」/ 模型供应商 标签页里点 `Add Provider`，填名称、`Base URL` 和 `API Key`，用 `Fetch Available Models` 拉取模型或在模型表格里手工加一行，保存后回到会话，用状态栏中部的模型选择器选中要用的模型，完整流程见[配置模型](../agent/model-config.md)。
2. `Base URL` 写错。缺少接口前缀或多写了多余的层级时调用打到错误的地址，对照供应商文档核对，占位文字里给出的例子是 OpenAI 的写法。
3. 密钥无效或已过期。到供应商侧确认密钥状态，回到供应商对话框重新输入一次；密钥在本机按当前用户加密保存，换机器或换 Windows 账户后无法解密，需要重新填写。
4. 模型标识不在供应商的模型列表里。用 `Fetch Available Models` 重新拉取，或者按供应商文档手工添加正确的标识。
5. 网络到不了这个地址。公司网络与代理会拦下发往外部服务的调用，确认这台机器能不能访问该地址。
6. 超时偏短导致间歇性失败。把「Agent Settings」/ Agent 设置 标签页里的重试次数、重试间隔和调用超时调大，默认值见[设置项说明](../reference/settings.md)。

会话本身的状态（启动中、运行中、等待输入、出错）显示在标签页和会话管理器里，状态的含义与重试提示的读法见[会话与对话](../agent/session.md)。

## 智能体工具反复要求审批，或者被拒绝

症状有两种：几乎每个工具调用都弹审批卡片；点了 `Deny` 之后这一轮停下，或者同一个工具下次再问。

反复询问有三个常见原因：

1. 权限模式是每次询问。写文件与代码执行都会问，这是设计行为；想少打断就切到自动或全自动模式，模式的差别见[权限控制](../agent/permission.md)。
2. 模式是自动但没有配置判官模型。没有判官时代码执行每次都问，到设置对话框的 Agent Permission Settings / Agent 权限设置 页的「Code Judge (optional)」/ 代码判官 分组里指定一个判官模型。
3. 工具的风险级别是 unknown。未在内置分级表里的插件工具默认是 unknown，自动和每次询问模式下都会询问；在同一页的「Tool Tier Overrides」/ 工具分级覆盖 里给它指定一个级别。

同一个写文件操作批准之后还问，原因是「Approve & remember for this session」只对写文件级别生效，而且只记住当前会话；代码执行永远不记忆，每次都要批准。

被拒绝分两种情况。审批卡片上点 `Deny` 是使用者主动拒绝，想继续就在下一轮重新发起。工具被直接拒绝、卡片一闪而过时，多半命中了硬性拒绝或路径规则里的 deny：系统目录在任何模式下都拒绝，路径规则里第一条命中的行决定结果，到 Agent Permission Settings 页的「File Path Rules」/ 文件路径规则 分组里核对该路径命中了哪一条。判定的完整过程见[权限控制](../agent/permission.md)。

## 切换工程后旧工程的会话还在后台跑

症状是打开另一个工程之后，Agent 助手面板顶部出现提示条 `%1 session(s) from the previous project are still running in the background`，旧会话仍在消耗模型额度。

原会话没有被停止是主要原因。关闭会话标签页时弹出的三选对话框里，选择 `Keep Running in Background` 的会话会留在后台继续跑；切换或打开工程不会自动中止它们，这是当前的行为。

已经出现提示条时按下面处理：

1. 点击提示条，打开会话管理器的跨工程视图。
2. 找到状态为运行中或等待输入的会话，用右键菜单的 `Stop` 停止它；管理器里的按钮也能停止选中的会话。
3. 别的工程的会话不能切换过去，只能在列表里查看或停止，停止后从列表里消失。

避免的办法是在切换工程之前主动结束会话：用对话里的 `Stop` 按钮、标签页右键菜单的 `Stop Session`，或者关闭标签页时选 `Stop Session and Close`。停止会一并撤掉这个会话里等待回答的问题卡片和审批卡片。三种停止方式与会话管理器的用法见[会话与对话](../agent/session.md)。

## 脚本卡住或者超时

症状是执行脚本之后整个窗口长时间不响应；或者返回值里 `success` 为假，错误字段是 `script execution timed out after <秒数> seconds`；也可能是 `timeout fired but script swallowed KeyboardInterrupt`。

脚本在界面线程上同步执行，运行期间窗口不响应鼠标和键盘，这是正常的执行方式而不是死机。判断是否真的卡住按下面的顺序检查：

1. 看超时设置。设置对话框高级页的 `Script execution timeout` / 脚本执行超时 被改成 0 时显示为 `Disabled` / 禁用，表示不限时，此时脚本里有死循环就会一直卡着。
2. 看消息和日志里有没有超时或错误记录。有 `script execution timed out after <秒数> seconds` 说明超时机制生效并中断了脚本；有 `timeout fired but script swallowed KeyboardInterrupt` 说明脚本捕获了中断并继续跑完。
3. 检查脚本里有没有等待外部输入的调用。执行环境没有给交互输入的机会，这类调用会一直等到超时为止，要改成从文件或 `args` 参数取输入。
4. 检查循环与数据规模。写文件、遍历目录、逐行 `apply` 这类操作在数据量大时会跑很久，观察是不是每轮都在推进。

处理办法：把长计算分成几段，中间结果写成工作区里的文件；把超时值调到一个合理的上限；需要真正中止时只能停掉整轮智能体回复。中断过的脚本可能留下写了一半的输出文件，重新运行前检查输出目录。执行方式、超时注入与结果回传的细节见[脚本工作区](../script/workspace.md)。

## 工程打不开，或者打开后内容不全

症状有两种：打开工程时状态栏提示 `Failed to load project, restored previous project` / 工程加载失败，已恢复之前的工程；工程能打开，但记忆里有的内容没有出现在界面上。

加载失败时不慌，程序在打开新工程之前已经给当前工程做了一份快照，提示里的那行文字说明旧工程已经回来了，工作内容没有丢。接下来检查目标工程文件本身：文件是否完整、是否被其它程序占用、存放的盘符是否可访问。有备份时用备份文件重新打开；工程文件确实损坏时，里面的工作流和数据很难手工恢复，日常编辑中按[工程文件](../getting-started/project.md)的自动保存一节留好退路。

工程打开时弹出 `Script Workspace Conflict` / 脚本工作区冲突 对话框是另一类情况，不是损坏：本地脚本工作区与包内版本不一致，按对话框里的三个按钮选一边，规则与后果见[工程文件](../getting-started/project.md)。

内容不全时先看两个管理器面板，而不是认为数据丢了。数据集一定在「Data Manager」/ 数据管理 面板里，绘图一定在「Charts Manager」/ 绘图管理 面板里；打开工程时恢复的是保存那一刻打开着的标签页，没有打开的页留在面板里，双击即可重新打开，内容不会丢，见[数据管理面板](../data/manager.md)。

图表还有一条与数据不同的规则：图表存的是采样点，不引用数据管理面板里的数据集，所以删掉源数据集之后图仍然显示；反过来，源数据后来改了，已画出的图不会跟着重算，需要重新执行一次绘图动作。

打开或关闭工程时的询问框按提示作答即可：有未保存改动时关闭会问 `Do you need to save the project?`，切换工程时也有相应的保存询问，先保存再继续能避免误丢改动，见[工程文件](../getting-started/project.md)。

## 表格里复制粘贴不按预期工作

症状有几种：在表格里按 Ctrl+V 没有反应；粘贴之后内容少了一部分；粘贴时弹出提示；复制出去的数字带了多余的小数位。

按现象对应处理：

1. 按 Ctrl+V 没有反应是当前设计。表格的粘贴没有键盘快捷键，用主页「Clipboard」/ 剪贴板 面板里的「Paste」/ 粘贴 按钮，焦点在表格上时它作用在单元格上，见[快捷键](../reference/shortcuts.md)。
2. 粘贴的内容没有落满预期范围。粘贴从选区左上角开始，只填充当前选区，超出选区的部分被丢掉；先选好足够大的区域再粘贴。
3. 粘贴时提示内容与列的数据类型不符。剪贴板里是文字而目标列是数值或日期时会出现这类提示，先按[表格视图](../data/table.md)的改列类型与转换一节把列转好，或者把数据整理成对应格式。
4. 剪贴板为空。先复制一次再粘贴，复制用 Ctrl+C 或面板里的「Copy」/ 复制 按钮。
5. 复制出去的小数位与屏幕上一致但与自己想要的不同。复制的是显示格式处理后的文本，带几位小数由单元格的显示格式决定，想改先调整显示格式再复制。

单元格编辑里的回车与 Esc、行列表格的增删改这些操作见[表格视图](../data/table.md)。

撤销的表现在表格里也容易误判。每个表格标签页各有自己的撤销栈，切换标签页之后按 Ctrl+Z 撤回的是当前标签页上的操作，不会撤到另一张表上；关闭标签页再打开时撤销记录被清空，而已经生效的修改留在数据里，所以关掉再打开之后撤不回之前的改动，见[快捷键](../reference/shortcuts.md)。

## 图上的图表不见了

症状是打开绘图标签页后坐标系是空的，或者原本看到的图表找不到了。

按顺序检查：

1. 看的是不是正确的坐标系。一个绘图里可以放多个坐标系，图表加进当前激活的那一个；统计绘图与建图向导都遵循这条规则，多坐标系绘图里先点一下目标坐标系再画，或者到「Charts Manager」/ 绘图管理 面板里选中它。
2. 图元的可见性被切换过。绘图管理树的 `visible` 列双击可以切换某项的显示，被关掉的图表在图上不画出来，双击那一格恢复；右键菜单里也有 `Visible` 一项。
3. 绘图标签页被关掉了。视图标签页的「Display」/ 视图显示 面板里点 `Show Chart Area` 找回绘图操作区，绘图本身仍在「Charts Manager」/ 绘图管理 面板里，双击打开。
4. 画到了别的绘图里。新建绘图之后它成为当前绘图，之后画的图表落在它里面；到绘图管理树里逐个查看绘图节点，找到目标图表后打开对应的绘图标签页。

需要重新整理绘图与坐标系时，子图的创建、拖动和尺寸调整见[绘图与坐标系](../chart/figure.md)，各类图表需要什么数据见[创建图表](../chart/create.md)。

## 界面上的面板或按钮找不到了

症状是常用的停靠面板消失，Ribbon 上熟悉的按钮不在原位，或者界面布局被拖乱。

面板被关掉时从视图标签页找回：切到「View」/ 视图 标签页，「Display」/ 视图显示 面板里按面板名点对应的开关，工作流区、绘图区、数据区、数据管理、消息、Agent 助手各有自己的 `Show ...` 动作。想找的面板名字可以先看[主界面](../getting-started/main-window.md)的停靠面板一节，那里面有全部面板的清单与内容。

Ribbon 按钮不在原位时先看当前标签页。按钮分成常驻标签页和上下文标签页：常驻的「Main」/ 主页、「Data」/ 数据、「View」/ 视图、「Figure」/ 绘图、「AI Agent」/ AI智能体 一直在；「DataFrame」/ 数据表、「Workflow」/ 工作流、「Chart Operate」/ 绘图操作 只在对应的区域获得焦点或打开对象时出现，点一下对应区域或打开一个对象即可。同一项功能也可能在多个页面里有入口，按功能定位比按位置记忆可靠。

布局被改乱时用保存好的方案恢复：视图标签页的「Layout」/ 布局 面板里有 `Manage Layouts`，双击一个方案应用，`Reset Layout` / 重置布局 恢复默认布局。界面状态的记录开关在设置对话框的通用页，关掉之后关闭软件会删除状态文件，下次以默认布局启动，细节见[设置项说明](../reference/settings.md)与[主界面](../getting-started/main-window.md)。

Ribbon 的行数和按钮大小由通用页的 Ribbon 样式控制，切换样式之后按钮会重新排布，看起来像少了一排按钮属于正常现象，切回原来的样式即可。

## 运行完工作流，数据管理面板里没有新数据集

症状是工作流跑完，节点颜色正常，但「Data Manager」/ 数据管理 面板里没有出现预期的数据集。

工作流里的数据不会自动变成数据集，这是最容易误解的一点。要让结果进面板，需要在画布上放一个 `Output to DataManager` 节点，把产生结果的节点接到它的输入端口，并在它的 `data_name` 参数里填一个名称；运行时这个名称的数据集才出现在面板里。只跑到中间节点时结果停留在内存里，运行结束后不留下东西。

按顺序检查：

1. 结果节点有没有连到 `Output to DataManager`。输出侧没有连到它时不出数据集。
2. `data_name` 是不是空着。名称为空时节点没有可发布的目标。
3. 输出节点这一轮有没有真的执行到。上游失败或条件分支没有选中这一路时，输出节点停在等待颜色，数据集不会出现。
4. 数据集是不是用了已有的名字。同一名称的数据会被就地更新，不会多出一个条目；打开着的表格视图会自动刷新，所以看面板时先确认没有漏看被刷新过的那一行。

一个工作流里可以放多个 `Output to DataManager` 节点，填不同名称，一次运行发布多份数据集；结果的去向与命名规则见[工作流基础](../workflow/basics.md)与[系统节点手册](../workflow/nodes-system.md)。

## 日志文件和崩溃转储在哪里

先区分两个地方。「Log」/ 消息 面板显示的是软件写给使用者看的消息，按界面队列级别过滤、只保留最近若干条，面板上的「Clear」/ 清除 按钮只清显示不删文件；面板里的行可以选中后按 Ctrl+C 复制出来，方便贴进问题记录。日志文件记录的范围更大：开发诊断记录和第三方库的输出都在里面，也不受面板条数限制。界面上找不到线索时，日志文件是下一步。

Windows 上日志文件在用户 AppData 目录下的 `DAWorkBench\log` 里：主程序日志是 `da_log.log`，Python 侧的输出是 `da_pyscript.log`，两个文件在同一目录。日志的级别、轮转方式、单文件大小和保留个数在设置对话框的 Log / 日志 页调整，这几项影响文件里能查到多少内容；级别调到 `Warning` 以上时不再记录过程信息。

崩溃转储在相邻的 `dumps` 目录里，程序异常退出后由崩溃捕获模块写入。保留天数在设置对话框高级页的 `Crash dump retention days` / 崩溃转储保留天数 里设置，点应用时清理一次超龄文件，这项清理只在 Windows 的 MSVC 构建上执行。

按路径直接打开日志目录比在编辑器里逐级寻找快，下面的命令在 PowerShell 里列出日志文件并按修改时间排序。

```powershell
Get-ChildItem "$env:APPDATA\DAWorkBench\log" | Sort-Object LastWriteTime -Descending
```

输出里最新修改的那个文件就是当前这次运行正在写的日志，用文本编辑器打开，从文件末尾往前看最近的事件。日志里每一条都带 `[源文件:行号]` 字段：路径在 `src/` 下的是本项目代码，其它路径的是第三方库或 Qt 自身的记录，排查时按这个字段区分来源，不要把它们当成本项目的问题。

日志文件的路径不随工程变化，同一台机器上的所有工程写进同一份日志；定位某一次运行的记录时按时间顺序找，工程名、文件路径这些信息会出现在相关记录里。

在日志里搜下面的关键字可以快速定位到已知故障。

| 关键字 | 对应的问题 |
|--------|------------|
| `Workflow error` | 工作流节点执行异常，同一行里带着节点标识 |
| `execution exception` | 节点抛出的异常文本 |
| `cannot load plugin` | 插件载入失败，同一行里是文件路径 |
| `ignoring invalid file` | 插件目录里的文件被跳过 |
| `Python interpreter not initialized` | 解释器没有就绪，Python 功能整体不可用 |
| `Python node discovery failed` | Python 节点包发现失败 |
| `Cannot load config file` | 配置文件损坏，程序按初始值启动 |
| `Failed to load project` | 工程加载失败，已自动恢复之前的工程 |

读日志文件的顺序建议是：先看文件最后几十行，确认最近一次运行的时间点与现象是否对得上；再按上面的关键词往回搜；找到相关行以后注意 `[源文件:行号]` 字段，区分是本项目代码还是第三方库。要限定范围时按时间或关键字筛选，不要在几万行的文件里从头读。

崩溃转储文件只在程序异常退出时生成，用同目录布局的 `dumps` 目录查看，文件名带时间戳。报告崩溃问题时把转储文件与同一时间的日志一起提供；转储目录里的旧文件会按保留天数自动清理，不需要手工维护。

日志文件会按轮转设置生成多个历史文件，排查时先确认看的是最新修改的那一个：历史文件里的内容对应更早的运行，时间点对不上会误导判断。文件级别调到 `Warning` 以上之后，过程信息不再写入，滚动到出现异常的时间点附近可能只有一行结果，这种情况下把级别改回较低的值并复现一次，拿到完整记录再分析。

## 报告问题前准备哪些信息

先确认现象能在当前版本上重复出现，再收集下面这些内容。

- 软件版本：命令行执行 `--version` 的输出，或者主页「Config」/ 配置 面板里 `About` 显示的版本号，见[命令行参数](./command-line.md)。
- 操作系统版本，以及解释器路径和版本：设置对话框 Python 页里显示的路径与 `Test` 的输出。
- 复现步骤：从打开工程开始，按顺序写清点了哪个按钮、填了什么内容、出现什么结果。能用一个最小工程复现时，把工程文件一起留下。
- 提示原文：消息面板里的提示文字，以及弹出对话框的标题和正文。
- 日志：`da_log.log` 的尾部片段，涉及 Python 时再加 `da_pyscript.log`；崩溃问题时加上 `dumps` 目录里对应的转储文件。
- 插件状态：`Plugin Config` / 插件设置 对话框里两个分组的状态截图，涉及节点缺失时尤其需要。
- 智能体相关的问题：说明权限模式、是否配置了判官模型、用的模型供应商与模型标识；密钥不要贴出来。
- 工程相关的问题：工程文件本身的路径和大小，以及打开时是否出现过工作区冲突对话框。
- 升级相关的现象：是不是从旧版本升级后第一次启动，旧版本里是否正常；升级后设置文件会做一次迁移，迁移留下的 `.bak` 文件不要删除，它记录了旧值。
- 网络与代理：智能体连不上模型、文献检索工具超时这类问题要说明网络环境，以及是否通过代理访问外部服务。

这些内容准备齐之后，多数问题能凭日志定位到具体模块与函数，不需要来回补充信息。

描述现象时用界面上的原文：面板名、按钮名、提示文字都按界面上显示的样子写下来，中英文界面上同一个按钮的文字不同，照抄看到的那个版本更便于对照源码与翻译文件。
