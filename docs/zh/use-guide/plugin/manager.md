# 插件管理

插件是往软件里追加功能的独立单元，用动态库或 Python 包的形式放在可执行文件旁边的目录里。软件启动时扫描这些目录，把插件带来的工作流节点、Ribbon 面板、智能体工具等内容接进界面。这一章讲插件放在哪里、能带来哪些内容、启动时怎么被发现，以及插件管理器里每一项状态的含义和启用、停用时的保护规则。

软件自带的功能有一部分就是用插件实现的，比如数据分析插件带来的清洗、筛选、统计面板，智能体工具插件带来的数据与绘图工具。这些内置插件与后来加入的插件使用同一套加载和停用机制。

## 插件放在哪里

插件分两类，各有自己的目录，都在可执行文件目录下。

| 类型 | 目录 | 文件要求 |
|------|------|----------|
| C++ 插件 | `<可执行文件目录>/plugins` | 一个动态库文件，后缀 Windows 上是 `dll`，macOS 上是 `dylib` 或 `so`，其它平台是 `so` |
| Python 节点包 | `<可执行文件目录>/pyplugins/<包名>` | 一个目录，里面必须有 `__init__.py` |

`plugins` 目录在不存在时由软件自动创建；`pyplugins` 目录不会自动创建，软件发现它不存在时跳过 Python 节点扫描并在日志里留一条记录，所以装完软件后没有这个目录属于正常情况。Python 节点包的目录名就是包名，缺少 `__init__.py` 的子目录会被跳过。两类插件都随安装程序分发，手工加入时把文件或目录放进对应位置，重启软件即可被发现。

停用状态记录在插件目录下的 `.pluginignore` 文件里，两个目录各有一个：`plugins/.pluginignore` 和 `pyplugins/.pluginignore`。文件每行一个条目，写的是插件文件名去掉后缀（对 C++ 插件）或包目录名（对 Python 节点包），`#` 开头的行是注释。`plugins` 目录下这一份缺失时由软件自动生成一份带说明的模板，`pyplugins` 目录下这一份由插件管理器写入状态时生成。这个文件由插件管理器写入，也可以手工编辑，手工删掉某一行等于重新启用对应的插件。

判断这两个目录在哪，最快的办法是从软件里打开一次插件管理器：列表里出现的名字就来自这两个目录。用安装程序装的软件，目录已经放在可执行文件旁边；从源码自行构建的版本，安装步骤把插件放到同样的位置。

## 插件能带来什么

一个插件可以贡献下面任意几类内容，具体贡献哪些由插件自己的代码决定。

| 内容 | 出现在哪里 | 说明 |
|------|------------|------|
| 工作流节点 | 「Workflow Node」/ 节点 停靠面板 | 节点作为一类节点出现在工具箱里，可以拖到画布上使用 |
| Ribbon 标签页、面板和按钮 | 顶部 Ribbon | 可以新建标签页，也可以往已有的标签页里加面板和按钮 |
| 智能体工具与系统提示词 | 会话里智能体能调用的工具清单 | 插件注册的工具进入工具执行与审批流程 |
| 内置提示词条目 | 「AI Agent」/ AI智能体 页的提示词画廊 | 只在对应文件不存在时写入一次 |
| 内置子智能体 | 子 Agent 定义目录 | 同样只在缺失时写入，之后可以改或删 |
| 设置页 | 设置对话框 | 插件可以提供自己的设置页，追加在内置页面之后 |

节点和 Ribbon 面板是两类最常见的贡献：前者决定工作流里能拖出哪些处理步骤，后者决定界面上出现哪些可按的按钮。

节点插件需要实现创建节点工厂和销毁节点工厂两个回调，另有一个节点全部载入后的补充回调。它带来的节点元数据出现在节点面板里，按分组显示；插件在运行期被启停时，节点列表通过一个变更通知即时刷新，不用重启软件。自己怎么定义一个节点、怎么打包成插件，见[把节点打包成插件](../workflow/node-plugin.md)。

Ribbon 上的贡献通过界面接口完成。插件可以按对象名找到标签页和面板，往里面插入动作按钮，也可以新建自己的标签页或在不需要时隐藏已有的页。数据分析插件是一个例子：它按对象名找到数据表的上下文标签页，往里面加了「Data Cleaning」/ 数据清洗、「Data Filtering」/ 数据过滤、「Statistics」/ 统计 三个面板，同时往主程序的数据操作面板里插了三个导出动作。界面分区和对象名的约定见[主界面](../getting-started/main-window.md)。

智能体相关的贡献都走同一套注册表：注册工具、注册系统提示词、注册内置提示词条目、注册内置子智能体。内置提示词和子智能体写在可执行文件目录下的 `daAgent` 目录里，如果同名文件已经存在就不覆盖，所以使用者改过的提示词不会被插件升级冲掉。工具和系统提示词不落盘，插件停用时按提供方整体注销，见停用保护一节。各类工具的用途见[内置工具](../agent/tools.md)，提示词和子智能体见[提示词库](../agent/prompt-library.md)与[子智能体](../agent/subagent.md)。

设置页由插件提供，软件把它们追加在内置的六个页面之后。当前随软件分发的插件都没有提供自己的设置页，所以打开设置对话框看到的就是内置页面，见[设置项说明](../reference/settings.md)。

## 随软件分发的内容里哪些来自插件

插件管理器列表里的名字与界面上看到的功能对应关系如下。

| 插件 | 带来的内容 |
|------|------------|
| 数据分析插件 | 数据表上下文里的「Data Cleaning」/ 数据清洗、「Data Filtering」/ 数据过滤、「Statistics」/ 统计 三个面板，数据操作面板里的三个导出动作，以及二十一个数据分析节点 |
| 智能体工具插件 | 二十一个内置工具，加上两个教模型输出数据与绘图链接的系统提示词 |
| 论文撰写插件 | 「论文撰写助手」提示词条目，以及检索文献、核验 DOI（数字对象标识符）两个工具 |
| 系统节点包 | 起点、终点、条件分支、延迟、常量、文本显示、结果发布七个系统节点 |

系统节点包装在 `pyplugins` 里，属于 Python 节点包，它的启用状态重启后生效；其余三个是 C++ 插件，可以在管理器中立即启停。各部分的用法分散在对应章节：清洗与筛选见[数据清洗](../analysis/cleaning.md)和[筛选、计算与排序](../analysis/query.md)，两套节点见[系统节点手册](../workflow/nodes-system.md)与[数据分析节点手册](../workflow/nodes-analysis.md)，智能体工具见[内置工具](../agent/tools.md)。

## 启动时怎么找插件

启动阶段先加载 C++ 插件，再发现 Python 节点，两者互不阻塞。

C++ 插件目录的扫描按固定顺序跳过几种文件：点开头的文件、后缀不是动态库的文件、`.pluginignore` 里列出的名字、以及动态库格式检查不通过的文件。每加载一个插件发一次开始加载通知，加载失败的插件把文件名和错误文本记下来。扫描过程中的提示既写日志文件，也出现在「Log」/ 消息 面板里：

| 提示 | 出现时机 |
|------|----------|
| `plugin directory is: %1` / 插件目录为：%1 | 扫描开始，记录本次扫描的目录 |
| `No plugin files found in: %1` / 插件目录中未找到插件文件：%1 | 目录里没有可加载的文件 |
| `Plugin directory does not exist: %1` / 插件目录不存在：%1 | 目录缺失 |
| `ignoring plugin %1` / 忽略插件 %1 | 名字在 `.pluginignore` 里，按要求跳过 |
| `ignoring invalid file: %1` / 忽略无效文件：%1 | 点开头的文件或后缀不对的文件 |
| `cannot load plugin: %1` / 无法加载插件：%1 | 动态库载入或插件初始化失败 |
| `plugin %1 loaded at runtime` / 插件 %1 已在运行期加载 | 在管理器里勾选启用成功 |

插件对界面和数据结构的初始化在各自的初始化函数里完成。

Python 节点包的发现要求解释器已经初始化。软件把内置的 Python 脚本目录加进 `sys.path`，扫描 `pyplugins` 下含 `__init__.py` 的包并按 `.pluginignore` 过滤，再创建节点工厂扫描这些路径；解释器环境里注册了入口点组 `data_workbench.plugin` 的已安装包也会被一并发现。解释器没有就绪时日志里出现 `Python interpreter not initialized, skip Python node discovery`，发现失败时出现 `Python node discovery failed`，两种情况都不影响 C++ 插件和软件其余部分的加载。

一个插件加载失败不会让程序起不来：错误记进日志，界面照常显示，其余插件照常加载。失败插件的状态在插件管理器里显示为加载失败，错误文本放在状态的提示气泡里。

界面的初始化按下面的顺序推进：

1. 载入程序配置，注册图元工厂，准备好界面和数据结构需要的基础内容。
2. 加载插件，C++ 插件在这一步初始化。
3. 填充工作流节点工具箱，调用各个节点插件的补充回调；节点面板此时有了完整的节点清单。
4. 应用设置里的各项配置。
5. 把可用的模型列表推给智能体并做一次预热，让智能体拿到包含全部插件工具的工具清单。

顺序里的第 3 步和第 5 步说明了两个常见现象：节点面板里的内容在插件加载之后才齐；智能体在软件刚启动完时已经知道所有插件注册的工具。

## 插件管理器

打开插件管理器：Ribbon 主页的「Config」/ 配置 面板里点 `Plugin Config` / 插件设置，提示文字是 `Show the plugin manager`，弹出的对话框标题是 `Plugin Manager`。对话框里是一棵四列两组的树：

| 列 | 内容 |
|----|------|
| `Name` / 名称 | 已加载的插件显示插件自报的名称，未加载的显示文件名；Python 节点包显示包目录名 |
| `Version` / 版本 | 插件自报的版本；没有载入过的插件这一列为空 |
| `Status` / 状态 | 当前状态文字，见下 |
| `Description` / 描述 | 插件自报的一句话说明；没有载入过的插件为空 |

两组分别是 `C++ Plugins` / C++插件 和 `Python Node Packages (changes take effect after restart)` / Python节点包（变更重启后生效）。每行第一列的复选框表示启用与否，勾选表示要启用。列表打开时复选框与当前生效状态一致，改动的比对基准就是打开时的状态。

### 状态文字

C++ 插件组里每行的状态是下面的一种。

| 状态 | 含义 |
|------|------|
| `Loaded` / 已加载 | 插件已载入并完成初始化，功能可用 |
| `Not Loaded` / 未加载 | 目录里有这个文件、当前没有载入，也不在禁用名单里；典型情况是软件运行期间往插件目录里放进了新文件，勾选后可以立即加载 |
| `Disabled` / 已禁用 | 名字在 `.pluginignore` 里，本次启动不加载 |
| `Load Failed` / 加载失败 | 尝试载入时报错，错误文本在状态的提示气泡里 |
| `Inactive (restart to release library)` / 已停用（重启后释放库） | 已经停用并移出加载列表，但动态库文件还被占用，重启后完成释放 |

Python 节点包组只有两种状态：`Enabled` / 已启用 和 `Disabled` / 已禁用。这一组没有加载失败状态，解释器发现阶段的问题记在日志里，节点是否出现要看「Workflow Node」/ 节点 面板。

几种状态对应的处理办法不一样。`Loaded` / 已加载 与 `Enabled` / 已启用 不需要动作。`Not Loaded` / 未加载 时勾选并应用即可当场载入。`Disabled` / 已禁用 时勾选并应用，C++ 插件当场载入，Python 节点包要重启。`Load Failed` / 加载失败 时把鼠标停在状态列上读错误文本，修好之后勾选并应用再试一次，仍然失败就重启，让软件在启动阶段重新尝试。`Inactive (restart to release library)` / 已停用（重启后释放库）时功能已经撤掉，重启软件完成文件释放。

### 列表里的行从哪来

每次打开对话框，软件都重新扫描插件目录生成这份列表，所以列表里会出现没有载入的插件：被禁用的、加载失败的、运行期间新放进目录的，都各占一行。名称、版本、描述三项由插件自己提供，只有载入成功的插件才有完整的这三项；没有载入的行显示文件名，版本和描述留空。切换界面语言时列表会按新语言重建一次。

行的数量与目录里的文件数对应：一个动态库文件一行，一个合格的 Python 包目录一行。目录里的其它文件（说明文档、配置文件、`.pluginignore` 自己）不占行，也不会被加载。

### 应用变更

改完复选框后，点 `Apply` / 应用 执行变更且对话框不关闭，点 `ok` 执行变更并关闭，点 `cannel` / 取消 关闭且不执行；最后一个按钮的文字在界面上拼写有误，作用是取消。两组变更的处理方式和生效时间不同。

C++ 插件组的变更是立即执行的热插拔。勾选一个未加载的插件，软件按下面的顺序执行：

1. 在插件目录里按名字找到对应的文件，名字对不上或后缀不对时报 `Plugin file %1 is not found in the plugin directory`。
2. 把名字从 `.pluginignore` 里移出并回写文件。
3. 载入动态库并调用插件的初始化函数。
4. 重建插件与节点元数据列表，发出节点变更通知，节点工具箱立即刷新。
5. 调用节点插件的载入后回调，与启动时的顺序一致。

其中任何一步失败，启用状态保留、状态显示加载失败，错误文本在提示气泡里，重启之后可以再试。

取消勾选一个已加载的插件，软件按下面的顺序执行：

1. 检查这个插件的节点是否出现在打开的工作流里，正在使用就拒绝并给出提示。
2. 把该插件注册给智能体的工具与系统提示词按提供方注销，这一步在插件实例销毁之前完成，避免留下指向已卸载代码的引用。
3. 调用插件的清理函数；返回失败就取消这次停用，插件保持原样。
4. 卸载动态库并把名字写进 `.pluginignore`；库文件释放不掉时降级为「重启后释放库」，停用本身仍然算成功。
5. 重建节点元数据列表，节点工具箱里移除这个插件带来的节点。

Python 节点包组的变更只写记录，落盘到 `pyplugins/.pluginignore`，要重启软件才生效。这一组没有任何运行期装卸动作。改完这一组之后对话框里勾选状态已经变了，但节点面板里的内容要到重启后才跟着变。

一次应用里如果既有 C++ 插件的变更又有 Python 包或降级停用的插件，软件会汇总一条提示：`%1 plugin change(s) applied, some changes take effect after restart` / 已应用%1项插件变更，部分变更将在重启后生效。全部变更都当场生效时提示是 `%1 plugin change(s) applied` / 已应用%1项插件变更。两条提示都写在「Log」/ 消息 面板里。个别行执行失败时，该行保持原来的勾选状态，失败原因以警告写进同一面板。

启用失败留下的痕迹值得说明：勾选了一个加载不成功的插件时，启用状态会保留下来表示这次勾选的意图，状态显示加载失败，重启之后软件会再尝试一次。

### 停用之后重新启用

已经处于 `Disabled` / 已禁用 状态的插件重新勾选并应用即可恢复，不需要动配置文件。处于 `Inactive (restart to release library)` / 已停用（重启后释放库）状态的插件再勾选时，软件按与 `Not Loaded` / 未加载 相同的步骤把文件重新载入；上一次占用库文件的那份代码要等重启后才彻底释放。

启用和停用都只改 `.pluginignore` 和当前进程的加载列表，不删除、不移动插件文件。要彻底移除一个插件，从插件目录里删掉对应文件或目录即可，`.pluginignore` 里剩下的条目没有实际作用。

## 停用时的保护

取消勾选一个正在使用的插件会被拦下来，防止界面上的节点和面板引用到已经卸载的代码。按被拒绝的原因分几种情况。

最常遇到的是节点正在使用。插件的节点出现在打开的工作流里时，停用被拒绝，提示是 `Nodes of plugin %1 are in use by open workflows (%2), please close them first`，提示里点名插件和正在使用它的工作流，要求先关闭这些工作流。处理办法是关掉用到这个插件节点的工作流标签页再重试。

其余三种情况是：

- 要停用的插件本来就没在加载列表里，提示是 `Plugin %1 is not loaded` / 插件 %1 未加载，不需要再做别的动作。
- 插件的清理函数返回失败，软件取消这次停用，提示是 `Plugin %1 refused to finalize, disabling cancelled` / 插件 %1 拒绝清理，禁用已取消。软件不动这个插件，工作内容不受影响。
- 插件的清理已经完成、但动态库文件释放不掉，停用照算成功，状态退化为 `Inactive (restart to release library)` / 已停用（重启后释放库）。此时功能已经撤掉，文件占用要等重启软件才解除。

还有一条与启用有关的错误：勾选一个在插件目录里找不到对应文件的插件时，提示是 `Plugin file %1 is not found in the plugin directory` / 插件目录中未找到插件文件 %1；重复勾选已经载入的插件时提示 `Plugin %1 is already loaded` / 插件 %1 已加载。

这些检查都发生在一次应用之内：被拒绝的那一行保持原状，同一次应用里其它行的变更照常执行，失败信息随汇总提示一起写进「Log」/ 消息 面板。

## 停用之后界面上的变化

成功停用一个 C++ 插件后，界面上与它相关的内容按下面的方式处理：

- 它加在 Ribbon 上的面板和按钮由插件自己的清理逻辑撤掉，标签页里少一块或整页消失都属正常。
- 它带来的节点从「Workflow Node」/ 节点 面板里移除，节点列表在停用时即时刷新。
- 它注册给智能体的工具和系统提示词按提供方注销，之后的新对话里这些工具不再出现；之前对话里留下的工具调用记录不会消失。
- 工作流文件和工作流标签页本身不受影响，没有用到该插件节点的工作流照常运行。

停用保护在动作之前先检查打开的工作流里有没有这个插件的节点，检查不通过时不执行任何清理，界面保持原样。对 Python 节点包来说没有运行期的界面变化，启用状态在下次启动时决定节点是否出现在面板里。

## 两类插件的区别

C++ 插件是编译好的动态库，能力范围最大，可以往工作流、Ribbon、智能体和设置页里加内容。它在进程里按接口约定和主程序对接，载入和卸载都有明确的入口，所以可以在软件运行期间启用和停用，改完立刻能用。

Python 节点包是一份 Python 代码，主要贡献工作流节点。它写起来门槛低，改参数、加节点都快；代价是 Python 解释器一旦导入这个包，模块和节点类就留在解释器里，卸载不能保证干净。因此这类插件的启用与停用只写记录，重启软件后按记录重新发现，界面上也直接标注了「变更重启后生效」。

两类插件都不需要重新安装软件：放进目录、在管理器里启用、重启或当场生效即可。具体到自己写节点并打包成插件，见[把节点打包成插件](../workflow/node-plugin.md)。

两种形态的差别可以对照下面的表。

| 对比项 | C++ 插件 | Python 节点包 |
|--------|----------|----------------|
| 文件形态 | 一个动态库文件 | 一个含 `__init__.py` 的包目录 |
| 主要贡献 | 节点、Ribbon、智能体内容、设置页 | 工作流节点 |
| 写起来的门槛 | 需要编译环境，与主程序的接口约定固定 | 普通 Python 代码，改完即用 |
| 启用与停用 | 运行期完成，立即生效 | 写记录，重启后生效 |
| 停用时的风险 | 库文件可能释放不掉，降级到重启 | 无运行期动作，没有释放问题 |
| 出错范围 | 载入失败只影响这个插件 | 单个包导入失败被跳过，其余包继续发现 |

## 插件与 Python 环境

Python 节点包的发现依赖软件找到的那个解释器。解释器不可用时整套 Python 节点发现被跳过，日志和消息面板里出现 `Python interpreter not initialized, skip Python node discovery`，界面其余部分照常工作；解决办法是到设置对话框的 Python 页指定解释器，见[设置项说明](../reference/settings.md)的 Python 页。

单个包在导入阶段出错（少了依赖包、包里有语法错误）时，这个包被跳过，其余包照常发现，出错原因写进 Python 侧的日志文件。节点包本身依赖 pandas 这类第三方包，装包要用同一份解释器环境，做法见[脚本工作区](../script/workspace.md)的第三方包一节。

还有一种不用放进 `pyplugins` 的安装方式：包在解释器环境里注册了入口点组 `data_workbench.plugin`，软件启动时也会把它发现出来。这类包不出现在插件管理器的 Python 节点包分组里，启用与停用要靠卸载或禁用这个包本身。

## 手工管理 .pluginignore

`.pluginignore` 是纯文本文件，每行一个名字，名字的大小写不敏感，多余的空行被忽略，`#` 开头的行整行跳过。C++ 插件目录下写文件基本名，比如 `DataAnalysis`；Python 插件目录下写包目录名，比如 `DASystemNodes`。写入重复条目没有额外后果，列出一个不存在的名字也不会报错。

手工编辑时注意两点：文件要在软件关闭时改，运行期间软件可能按自己的状态回写；改动在下次启动时生效，本次运行中已经在用的插件不会因此被卸载。想一次恢复全部插件，把文件内容清空或删掉文件，下次启动就会全部加载，`plugins` 目录下那份缺失时还会重新生成模板。

## 哪些操作要重启软件

插件相关的动作生效时机不一样，对照下表安排操作，避免改完以为没生效。

| 动作 | 生效时机 |
|------|----------|
| 在管理器中启用或停用 C++ 插件 | 立即，节点工具箱同步刷新 |
| 在管理器中启用或停用 Python 节点包 | 重启软件 |
| 把新的动态库放进 `plugins` 目录 | 打开管理器刷新列表即可看到，勾选后立即载入 |
| 把新的 Python 包放进 `pyplugins` 目录 | 重启软件，包的发现只在启动阶段进行 |
| 手工编辑 `.pluginignore` | 重启软件 |
| 从插件目录里删除文件 | 管理器中刷新后不再显示；本次运行中已载入的库可能仍占用，重启后彻底消失 |
| 改设置对话框高级页的插件搜索路径、节点脚本搜索路径 | 不起作用，这两项当前没有被读取 |

需要重启时，先保存工程，再退出并重新启动，重启后到管理器里核对一次状态。

## 与插件有关的设置项

设置对话框高级页上有两个带「插件」字样的设置项：`Plugin search path` / 插件搜索路径，一个目录；`Node script search paths` / 节点脚本搜索路径，一个目录列表。这两项会被写进程序配置，当前版本的程序没有读取它们，插件仍从上面说的两个固定目录加载，节点仍从 `pyplugins` 和入口点发现。改动这两项不会改变插件的搜索位置。每一项的控件形式和默认值见[设置项说明](../reference/settings.md)。

与插件启用状态直接相关的是两处 `.pluginignore` 文件，见前文。插件自己需要保存运行期数据时写在别处，不受这两个设置项影响。

## 插件没有出现怎么排查

按下面的顺序检查，每一步都有明确的观察点。

1. 确认文件位置。C++ 插件要放在可执行文件目录下的 `plugins` 子目录，Python 节点包要放在同级的 `pyplugins/<包名>` 且目录里有 `__init__.py`。放错一级目录是最常见的原因；`pyplugins` 目录不存在时先手工建一个。
2. 确认文件后缀。C++ 插件在 Windows 上必须是 `dll`；后缀不对的文件在扫描阶段就被跳过，消息面板里留下一行「忽略无效文件」。
3. 打开插件管理器看状态。名称那一列没有这一行，说明文件不在扫描目录里或后缀不对；状态是 `Disabled` / 已禁用，表示名字在 `.pluginignore` 里，勾上再点应用；状态是 `Load Failed` / 加载失败，把鼠标停在状态上读提示气泡里的错误文本。
4. 查看「Log」/ 消息 面板里的扫描提示，对照前文那张提示对照表判断插件停在哪一步：是根本没被扫到，还是被忽略，还是载入失败。
5. 看日志文件补充细节。消息面板里的文本与日志文件一致，文件里还包含不进入界面的诊断记录，位置见[常见故障](../reference/troubleshooting.md)。
6. Python 节点包的项目，确认 Python 解释器可用。解释器没配好时整套 Python 节点发现都不会进行，日志里出现 `Python interpreter not initialized, skip Python node discovery`，设置位置见[设置项说明](../reference/settings.md)的 Python 页。
7. 改动过 Python 节点包的启用状态之后重启软件。这一组的状态在重启后才生效，管理器的分组标题里写明了这一点。
8. 插件已经加载但节点面板里找不到节点时，看节点面板的分组与搜索框，按[工作流基础](../workflow/basics.md)里的节点工具箱一节核对。
9. 以上都不成立时，用[把节点打包成插件](../workflow/node-plugin.md)里的最小示例插件放入目录做对照：它能出现说明环境正常，问题在目标插件本身；它也不出现说明是位置或解释器环境的问题。

## 常见问题

**插件已经加载，Ribbon 上却找不到它加的面板。** 面板可能被同一插件在运行期隐藏了，也可能加在按当前操作对象出现的上下文标签页里：先打开一个数据表或工作流，让对应的上下文标签出现。数据分析插件的三个面板就在数据表上下文里。

**取消勾选时被拒绝，工作流又不想关。** 先把这个工作流里用到该插件节点的部分另存或导出，替换成其它节点之后再停用。停用保护检查的是打开的工作流标签页，标签页关掉、工作流内容不再引用这些节点时就能通过。

**改过 Python 节点包的状态，重启后节点还是没有回来。** 回插件管理器看这一包的状态是否为已启用；已启用但节点仍缺失时，看日志里是不是解释器发现失败，按第 5 条检查解释器。

**插件带来的提示词或子智能体想改内容。** 内置内容只在文件缺失时写入一次，文件在可执行文件目录的 `daAgent` 下。直接编辑或删掉那个文件，插件下次启动不会覆盖已经存在的版本，删掉之后会重新写入一份默认内容。

**插件从列表里彻底消失了。** 检查文件是否还在插件目录里。文件被删掉或移走后，管理器里不会再出现这一行，`.pluginignore` 里的同名条目也不会报错。

**同一台机器上另一份安装的插件状态不同。** `.pluginignore` 在各自安装目录里，两份安装互不影响；配置目录里的设置（比如插件搜索路径）是共用的，但它不影响插件加载。

**插件启用后按钮出现了，点下去报错说找不到功能。** 这属于插件自身或它的节点包没准备完整：C++ 插件部分已加载，而它在 `pyplugins` 里的节点包被停用或导入失败时会出现这种半套状态。按管理器里 Python 组和日志里的发现记录核对，把缺的一半补上再重启。

**界面语言切换后插件列表里的状态文字没变。** 列表在语言切换时会重建，状态文字跟着新语言显示；如果只看到英文状态，说明这一条没有对应翻译，属于正常现象，逐字的含义仍以本章的状态表为准。

**在管理器里点应用之后没有任何提示。** 只有确实发生了变更时才有汇总提示；勾选状态与打开列表时一样时，应用不做任何动作，也不产生消息。

**想让某台机器上不加载随软件安装的插件。** 在管理器里取消勾选并重启即可，记录写在本机安装目录的 `.pluginignore` 里，不影响其它机器和别人的安装。软件自带的插件同样允许停用，界面对应的内容随之消失。

按症状逐项排查的完整清单见[常见故障](../reference/troubleshooting.md)。

## 插件在磁盘上留下的东西

把这一章提到的位置归到一起：

| 位置 | 内容 |
|------|------|
| `<可执行文件目录>/plugins` | C++ 插件动态库与 `.pluginignore` |
| `<可执行文件目录>/pyplugins` | Python 节点包目录与 `.pluginignore` |
| `<可执行文件目录>/daAgent` | 插件注入的内置提示词与子智能体定义文件 |
| 配置目录 | 程序设置，包含高级页上那两个与插件有关、当前未生效的路径项 |

前两个目录随安装目录走，把安装目录整体拷到另一台机器上时，启用状态跟着过去；配置目录中的设置是用户级的，拷安装目录不会带过去，位置见[设置项说明](../reference/settings.md)。

`daAgent` 目录下的文件名就是提示词或子智能体的名字，插件只在文件缺失时写默认内容。删掉某个文件之后，对应内容会从提示词库或子智能体列表里消失，插件下次启动会按内置版本重新写入一份。
