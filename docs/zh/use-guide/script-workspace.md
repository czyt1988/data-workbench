# 脚本工作区

脚本工作区为 AI 分析（agent 编程）与自定义脚本提供工程内的脚本存放与运行环境。工程文件（`.dapro`）内新增 `workspace/` 目录保存脚本及其产物；程序在打开工程时把它解压到本地缓存目录，保存工程时再打包回去。

## 基本概念

- **脚本工作区（工程内）**：工程文件中的 `workspace/` 目录，随工程保存/传播。建议（非强制）按 `scripts/`（脚本）与 `output/`（产物）分区组织。
- **本地缓存目录**：`workspace/` 解压后的本地工作副本，位于 `<工作区根目录>/<工程基名>_<路径哈希>/`。脚本实际在这里运行；其中"工作区根目录"由设置项 `workspace-dir` 决定（留空使用系统临时目录）。
- **共享命名空间**：所有脚本在同一持久命名空间中执行（类似 Jupyter kernel）。脚本中定义的变量在多次运行之间保留；工程关闭/切换时用户变量被清理。

## 数据访问

脚本访问工程数据**不经过文件**，直接读取内存中的 DataFrame——因此不存在"数据改了脚本没同步"的问题。推荐写法：

```python
# da_app / da_interface / da_data 已预导入，无需 import
dfs = da_app.getCore().getDataManagerInterface().getAllDataframes()
df = dfs["数据名称"]          # 得到 pandas.DataFrame

# 也可按索引取单个数据对象
data = da_app.getCore().getDataManagerInterface().getData(0)
df = data.toPyObject()
```

第三方库（numpy、pandas、scipy、matplotlib 等）请按需显式 `import`。

## Agent 工具

AI 分析 agent 提供两个脚本工具：

| 工具 | 说明 |
|------|------|
| `run_script` | 运行工作区内的 `.py` 文件（参数为工作区相对路径，如 `scripts/analyze.py`）；工程必须已保存 |
| `run_code` | 直接执行一段 Python 代码；无工程时也可用 |

两个工具共享同一持久命名空间，并支持可选 `args` 参数（在脚本内以 `args` 字典访问）。脚本可以把 `__result__` 变量设为返回值；`print` 输出会被捕获返回。

!!! warning "工具结果是文本，不是对象"
    工具返回的 `result` 字段是给 agent 阅读的**文本摘要**（DataFrame 显示 `head(100)` 与 shape，dict/list/标量尽量 JSON 序列化），**不是**可以继续运算的 Python 对象。多步分析应把中间结果存为命名空间变量（如 `df = ...`），后续步骤直接引用变量名。

!!! note "未保存的工程"
    新工程在首次保存之前没有脚本工作区（`run_script` 会返回"工程尚未保存"的错误），首次保存后即可使用。

## 设置项

在"工具 → 设置 → 高级"页的"脚本工作区"分组中配置：

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| 工作区目录 | 空（系统临时目录） | 本地缓存的根目录；修改后在**下次打开工程时**生效 |
| 脚本执行超时 | 300 秒 | 超时向脚本注入 `KeyboardInterrupt`；0=禁用（不建议） |
| 脚本结果最大字符数 | 10000 | 结果文本超长时截断 |

另有高级配置项 `workspace-overwrite-policy`（编辑配置文件 `dawork-config.xml`）：`ask`（默认，冲突时弹窗询问）/ `always-local`（总保留本地）/ `always-zip`（总用工程内版本覆盖）。

## 打开工程时的冲突处理

打开工程时，若本地缓存的工作区与工程内保存的版本**内容不一致**（例如上次打开后本地脚本被修改过且未保存），程序会弹窗询问：

- **保留本地**：以本地缓存为准，工程标记为未保存状态，下次保存时把本地内容打包回工程；
- **用工程内版本覆盖**：丢弃本地改动，重新解压工程内版本；
- **取消**：放弃打开该工程，当前工程保持原状。

本地与工程内版本一致时不会弹窗，静默覆盖解压。

## 使用注意事项

!!! warning "脚本执行期间界面会冻结"
    脚本在主线程同步执行，执行期间界面（UI）无响应。请避免运行长时间脚本；确有长任务时建议拆分为多个小步骤，并保留默认的超时保护（300 秒）。

- **不要在脚本里吞掉 `KeyboardInterrupt`**：超时机制通过注入 `KeyboardInterrupt` 实现，脚本若用裸 `except:` 或 `except KeyboardInterrupt: pass` 捕获它，超时将失效，脚本会继续运行到自然结束。
- **长时间 C 扩展运算无法被超时打断**：如 `pandas` 的大规模 `groupby().agg()` 等，只有控制权回到 Python 层时中断才会生效（Python 语言固有限制）。
- **脚本文件必须是 UTF-8 编码**：其他编码（如 GBK）在 Windows 下容易报错。
- **大产物不要放在工作区**：工作区整体打包进工程文件，导出的数据/图片等超过数 MB 的产物请放到工程外的目录，以免工程文件过度膨胀。
- **外部编辑要及时保存**：用外部编辑器修改了工作区内的脚本后，记得保存工程，否则改动不会进入工程文件；重新打开工程时可通过冲突弹窗找回本地改动。
- **工程改名/移动/另存为**会改变本地缓存目录：旧缓存目录不会被自动清理；改名/移动/另存为**之前**尚未保存进工程的本地改动会留在旧目录；另存为之后到重新打开之前，脚本工作区暂不可用。
- **跨工程切换后**，工作区内自定义模块（如自己写的 `utils.py`）会被自动清理缓存、重新导入；第三方库（numpy/pandas 等）不受影响。
- **`sys.stdout.fileno()` 不可用**：脚本执行期间标准输出被重定向捕获，依赖 `fileno()` 的库（部分进度条/终端检测库）会抛出 `UnsupportedOperation`，属已知限制。
- **工作区根目录会追加到 `sys.path` 末尾**：工作区内的模块可以被 `import`（跨脚本复用），但只有标准库和已安装包都没有同名模块时才会从工作区加载，避免意外覆盖。
- **所有 agent 会话共享同一命名空间**：一个会话定义的变量对另一个会话可见，这是设计意图而非缺陷。
