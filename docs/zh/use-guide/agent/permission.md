# 权限控制

智能体每调一次工具，软件都要先决定这次调用放不放行。决定依据四件事：当前处在哪种权限模式、这个工具属于哪一级风险、要写的文件落在哪条路径规则上、代码内容有没有命中危险模式。放行就执行，需要确认就在对话里弹一张审批卡片，拒绝就直接拦下并把原因告诉智能体。

这一章讲这套判断的全部规则，以及设置对话框里「Agent Permission Settings / Agent 权限设置」这一页的每一项。默认配置偏宽松，改之前先看清楚每一档放行什么。

## 判断顺序

一次工具调用的判断按固定顺序走：

1. 系统目录检查。要写的路径落在系统目录里，任何模式都直接拒绝，这一层不可配置。
2. 全自动模式。处在全自动时，没有命中第一层的调用全部放行，后面的规则不再看。
3. 会话记忆。文件写入类调用如果在本会话里被批准并勾选过记住，直接放行。
4. 按风险分级处理。读取类和应用内改动类看模式；文件写入类看路径规则；代码执行类看内容检查；没分级的工具按未分级处理。
5. 没命中任何放行条件的调用，按模式决定是问一次还是直接放行。

审批卡片会一直等答复，等待时间有上限，默认 600 秒，到时间按未批准处理。

被拒绝的调用不会静默消失：工具卡片上显示失败，原因一并带回给智能体，它通常会换个写法或者换个输出位置再试一次。拒绝两次之后如果智能体又提出同一个动作，说明它没有别的办法完成这件事，此时要么批准，要么换一个说法把要求交代清楚。

## 三种权限模式

模式在对话状态栏的权限模式选择器里切换，三个选项的名称和下面的表一致。

| 模式 | 读取类 | 应用内改动 | 文件写入 | 代码执行 | 未分级工具 |
|---|---|---|---|---|---|
| 全自动 `Full Auto` | 放行 | 放行 | 放行 | 放行 | 放行 |
| 自动 `Auto` | 放行 | 放行 | 按路径规则 | 有判官时按判定，无判官时每次都问 | 每次都问 |
| 每次询问 `Ask Every Time` | 放行 | 默认放行，打开一个开关后也问 | 每次都问 | 每次都问 | 每次都问 |

全自动是唯一会跳过后三类全部询问的一档，系统目录的拒绝在它上面照样生效。自动模式的思路是让只读和可撤销的操作直接过，把真正会落到磁盘和会执行代码的动作交给规则判定。每次询问模式最严格，适合把电脑借给别人临时用、或者在不熟悉的数据上试跑。

三个选项在状态栏上的提示文字分别是：全自动是「Run everything without asking (system directories still blocked)」，自动是「Reads and chart edits pass; file writes and code execution judged by rules」，每次询问是「File writes and code execution need approval every time」。

## 默认是全自动

没有任何配置时，软件按全自动运行。这条取值在源码里是默认值，配置文件里没有这一项或者写了一个不认识的值时，同样回退到全自动。

全自动的实际效果：智能体读数据、画图、导出文件、执行 Python 代码都不会停下来问，只有落在系统目录里的写入会被拒绝。第一次使用时不熟悉智能体要做什么的，先去设置页换成自动或每次询问。

一个具体的对照：在默认配置下让智能体「把每个月的数据分开导出成 CSV」，它会在工作区里连续创建十来个文件，一次也不会打断；同样的操作在每次询问模式下，每一个新路径都会弹一张卡片，第一次批准时勾上记住只对同一个路径有效，下一个路径继续问。批量产出用全自动省事，代价是文件会在没有被逐一看过的情况下落盘。

## 全自动的两张确认卡片

全自动只有用户明示选过之后才有确认环节，而且是两步确认。

软件启动时，如果上一次留在全自动这一档（明确选择过，而不是默认回退），对话里先出现一张卡片，英文文字是「The permission mode is Full Auto from last session. Code execution and file writes will run without asking. Keep Full Auto mode?」，中文界面对应显示为「上次的权限模式是全自动。代码执行与文件写入将在不询问的情况下运行。」两个按钮是「Keep Full Auto / 保持全自动」和「Switch to Auto / 切换为自动」。选保持就继续用全自动，选切换就落到自动。

在会话里把选择器切到全自动时，出现一张网页确认卡片，英文文字是「Switch to Full Auto mode? Code execution and file writes will no longer ask for confirmation.」，中文界面对应显示为「切换到全自动模式？代码执行与文件写入将不再征求确认。」按钮是「Switch / 切换」和「Cancel / 取消」。选切换才真的换过去。

这两张卡片都只负责把选择写进配置，选过一次之后不会再每次弹。

## 五级风险

每个工具归在一个风险级别里，级别决定它在自动和每次询问模式下走哪条判断。内置分级表里有二十个工具，其余工具按未分级处理。

| 级别 | 含义 | 工具 |
|---|---|---|
| `read` / 读取 | 只看不改 | `list_data`、`get_data_info`、`query_data`、`get_column_stats`、`list_figures`、`read_file` |
| `inapp_mutate` / 应用内改动 | 只改软件里的数据，不动磁盘 | `create_chart`、`create_subplots`、`add_curve`、`update_curve_style`、`set_axis`、`set_chart_style`、`remove_chart_item`、`add_annotation` |
| `file_write` / 文件写入 | 会在磁盘上留下文件 | `write_file`、`export_data`、`save_report`、`save_chart_image` |
| `code_exec` / 代码执行 | 执行 Python 代码 | `run_code`、`run_script` |
| `unknown` / 未分级 | 表里没有的工具 | 其它全部，包括插件带来的工具 |

分级的标准是出错的代价。读取级什么都不会改，放行的风险最低。应用内改动级改的是软件里的绘图和数据，改错了可以删掉重来，最坏情况是不保存工程就关闭。文件写入级会在磁盘上留下文件或者覆盖已有文件，覆盖之后原来的内容找不回来。代码执行级的能力最大，一段脚本可以读写文件、起网络连接、动进程，前面三级的限制它都能绕过，所以它单独看内容判定。未分级这一档在自动和每次询问模式下按最保守的方式处理，因为软件不知道它能做什么。

未分级的工具在自动和每次询问模式下都会弹审批，在全自动模式下放行。判断未分级工具时还有一条退化规则：工具参数里出现 `file_path`、`path`、`output_path`、`report_path` 中的任意一个，按文件写入级别处理。

`list_chart_items` 这个只读工具没有列在内置分级表里，参数里也没有上面那几个路径键，因此实际被当作未分级处理：在自动和每次询问模式下调用它会弹审批。这是当前分级表的实际行为，源码里没有说明它应当归在哪一级；在设置页的工具分级覆盖表里加一条 `list_chart_items` → `read` 就能让它安静通过。论文撰写插件带来的 `search_literature` 和 `verify_doi` 同样不在表里，参数是检索词和 DOI，因此也按未分级处理，除非加覆盖。

## 四类调用的判断过程

看几个具体例子，把顺序走一遍。

智能体调用 `query_data` 筛选数据。这个工具是读取级，任何模式下直接放行，不弹卡片。

智能体调用 `create_chart` 画图。应用内改动级。全自动和自动模式直接放行；每次询问模式下默认也放行，除非在设置里勾了「In manual mode, also ask before in-app chart edits」，勾上之后每次画图都弹卡片。

智能体调用 `export_data` 把数据集写到工作区里。文件写入级。全自动直接放行；自动模式查路径规则，默认规则里有一条 `export_data` + `${workspace}/**` + `allow`，写在工作区里命中这条，放行；写到工作区之外没有规则命中，弹卡片；写到 `c:/windows/**` 这类系统目录，被第一层的硬性拒绝拦下，卡片都不弹。

智能体调用 `run_code` 执行一段分析代码。代码执行级。全自动直接放行；每次询问模式每次都弹卡片；自动模式先做内容检查：代码里出现 `subprocess`、`os.system` 这类拒绝模式命中的内容，直接拒绝；命中 `socket.`、`requests.get` 这类升级模式的内容，交给判官裁决；判官没配置时按需要确认处理；没有命中任何模式的普通代码，配置了判官就放行，没配置判官就弹卡片。

## 审批卡片

需要确认的调用在对话里渲染成一张审批卡片。

卡片顶部是一个盾牌图标加一行标题「<工具名> needs your approval / <工具名> 需要批准」。由子智能体发起的调用在标题旁边多一行「From subagent: %1 / 来自子 Agent：%1」，用来区分这是谁在要权限。

卡片主体按这次调用的种类显示不同内容：

- 代码执行类：显示代码的前 15 行，超出部分用「%1 more lines」提示还有多少行没显示。
- 写文件类：显示要写的文件路径。
- 其它情况：显示参数的 JSON，过长时截断。

卡片底部最多三个按钮：「Approve / 批准」、「Deny / 拒绝」，写文件类调用还有第三个「Approve & remember for this session / 批准并本会话记住」。做出决定后卡片上显示结果文字，分别是「Approved / 已批准」、「Denied / 已拒绝」、「Approved (remembered for this session) / 已批准（本会话已记住）」，按钮随即禁用，重复点击被忽略。

记住的效力有两条边界：只在当前会话里有效，换一个会话重新问；只对文件写入类调用生效，代码执行的批准永远不会被记住。同一段代码在同一个会话里再跑一次，仍然会再问一次。

记住的粒度是「会话 + 工具 + 路径」三者的组合。勾了记住之后，同一个会话里再往同一个路径写同一个工具的结果，不再打扰；换一个输出路径仍然会问一次。批量导出到同一目录时，第一次批准并记住，后面的几次就安静通过。

拒绝一次不会留下记忆：被拒绝的调用下次再出现时照样会问，可以逐次判断。

## 没处理的卡片去哪了

还没有答复的审批卡片在下面几种情况下被移除：

- 这一轮被停止，包括对话里的 Stop 按钮、标签页右键菜单的停止和关闭对话框里的停止并关闭。
- 智能体子进程退出或崩溃。
- 会话被切走之后连接被回收。

卡片消失等于这次调用被放弃，不会在后台补执行。重新发起时智能体会再问一次，不会因为上一次没答复就停止发问。

## Agent 权限设置页

设置对话框里紧挨着模型设置的那一页，标题是「Agent Permission Settings / Agent 权限设置」。整页放在一个滚动区里，分成六个分组。

### 默认权限模式

分组标题「Default Permission Mode / 默认权限模式」，一个下拉框，三个选项：「Auto (rules + judge) / 自动（规则+判官）」、「Manual (ask every write/code) / 手动（写入/代码每次询问）」、「Full Auto (yolo) / 全自动（yolo）」。字段标签是「Mode: / 模式：」。

选中的值写进配置，作为后续会话的初始模式。这里是全自动时，启动确认卡片才会出现。

### 审批

分组标题「Approval / 审批」，两项：

| 字段 | 取值范围 | 默认值 |
|---|---|---|
| `Approval timeout:` / 审批超时 | 10 到 86400 秒 | 600 |
| `In manual mode, also ask before in-app chart edits` / 在手动模式下，应用内图表编辑也要询问 | 复选框 | 不勾选 |

审批超时是等待答复的最长时间，提示文字写着「Max wait for user approval on file writes / code execution」。超时之后按未批准处理，卡片失效。等待时间算进子任务的墙钟限制里，跑长任务时把这两个数字放在一起看。

复选框只在每次询问模式下起作用：勾上之后，应用内的图表改动也从放行变成每次都问，适合不放心任何自动改动的用法。

### 代码判官

分组标题「Code Judge (optional) / 代码判官（可选）」，两项：

| 字段 | 取值范围 | 默认值 |
|---|---|---|
| `Judge model:` / 判官模型 | 文本，占位文字「Leave empty to disable the judge」 | 空 |
| `Judge timeout:` / 判官超时 | 1 到 600 秒 | 30 |

判官是一段额外的判定：在自动模式下，代码执行类调用先过一遍静态规则，命中拒绝模式的直接拒绝，命中升级模式的交给判官模型判断。判它安全就放行，判不确定就弹审批。判官用当前连接的基础地址和密钥调用，模型标识填在这个字段里，填一个响应快的模型即可。

这个字段留空时判官不启用，后果写在分组内的说明文字里：未配置判官模型时，自动模式对代码执行仍会逐次询问，即使没有命中任何危险模式；配置判官之后，灰区代码可以自动放行或拒绝，没有命中模式的代码静默放行。

### 文件路径规则

分组标题「File Path Rules / 文件路径规则」，一张三列的表：

| 列 | 内容 |
|---|---|
| `Tool` / 工具 | 工具名，`*` 表示全部工具 |
| `Scope (glob)` / 范围（glob） | 用通配符写的路径，支持下面列出的变量 |
| `Action` / 动作 | `allow`、`deny`、`ask` 三者之一 |

两个按钮是「Add Rule / 新增规则」和「Remove Selected / 删除选中」。

分组说明写着规则按顺序求值、第一条命中的生效，没有命中任何规则的文件写入征求确认。可用变量有五个：

| 变量 | 指向 |
|---|---|
| `${workspace}` | 工程脚本工作区的根目录 |
| `${project}` | 工程文件所在的目录 |
| `${data}` | 应用数据目录 |
| `${exe}` | 软件可执行文件所在目录 |
| `${home}` | 当前用户的主目录 |

第一次打开这一页时表里已经有两组规则，都是软件预先写好的：

| 工具 | 范围 | 动作 |
|---|---|---|
| `write_file`、`export_data`、`save_report`、`save_chart_image` | `${workspace}/**` | `allow` |
| `*` | `c:/windows/**` | `deny` |
| `*` | `c:/program files/**` | `deny` |
| `*` | `c:/program files (x86)/**` | `deny` |
| `*` | `c:/programdata/**` | `deny` |

四条拒绝行覆盖 Windows 系统目录。凡是工具填 `*`、动作填 `deny` 的行都是硬性安全规则，单元格不可编辑，删不掉，鼠标停上去显示「Hard safety rule: cannot be edited or removed / 硬性安全规则：不可编辑或删除」。即使手工从配置文件里删掉，下次载入时也会被补回来。

写规则时把范围写得越具体，命中之后的行为越好预测。想让工程目录里的写入也一律放行，加一条 `write_file` + `${project}/**` + `allow`；想让某个目录只问不写，加一条更靠前的 `ask`；想禁止往某个目录写，加 `deny`。表里的顺序就是判断顺序，从上往下读，求值时按当前顺序逐条比对。新规则追加在末尾，要让它先于已有规则生效，需要把已有规则删掉重建，或者调整规则的范围写法。

### 代码危险模式

分组标题「Code Danger Patterns (Auto mode) / 代码危险模式（自动模式）」，两个多行文本框：

- 「Deny patterns (matched => reject): / 拒绝模式（命中即拒绝）：」。代码里出现匹配的内容就直接拒绝，不执行。
- 「Escalate patterns (matched => consult judge): / 升级模式（命中交判官裁决）：」。匹配的代码交给判官裁决。

两个框都是每行一条正则表达式，占位文字「One regex per line / 每行一条正则」，写法不合法的行被跳过。这组规则只在自动模式下生效，每次询问模式不看它们，全自动模式也不看。软件预置的清单是：

| 拒绝模式（命中即拒绝） | 拦下的东西 |
|---|---|
| `subprocess` | 起子进程 |
| `os\.system`、`os\.popen` | 交给系统 shell 执行命令 |
| `shutil\.rmtree`、`os\.remove\b`、`os\.unlink`、`os\.rmdir` | 删除文件和目录 |
| `ctypes` | 直接调系统库 |
| `pickle\.loads` | 反序列化来路不明的对象 |
| `sys\.exit` | 直接结束解释器进程 |

| 升级模式（交判官裁决） | 需要评估的东西 |
|---|---|
| `socket\.` | 建立网络连接 |
| `requests\.` | 发起网络访问，涵盖它下面的几个调用方法 |
| `urllib` | 发起网络访问 |
| `__import__`、`importlib` | 动态导入模块 |
| `\beval\s*\(`、`\bexec\s*\(` | 执行拼出来的字符串 |
| `open\s*\([^)]*['"][wa]\+?b?['"]`、`\.write_` | 打开文件写入 |
| `shutil\.` | 复制和搬移文件 |

匹配规则是正则表达式的部分匹配，不要求从行首开始，区分大小写。写 `os\.system` 会拦住 `os.system`，写 `os.system` 也能拦住，因为点号在这里恰好匹配一个任意字符；想精确匹配点号，照预置清单的写法加反斜杠。写法不合法的行在加载时被跳过，不会让判定出错。

分组说明写明了这套判定的性质：这是一层咨询性防线，不是安全边界，静态模式可以被混淆绕过（间接属性访问、从干净的入口脚本导入恶意模块、判定之后改写脚本等）。需要严格管控时用每次询问模式，别指望正则列表挡住所有东西。

### 工具分级覆盖

分组标题「Tool Tier Overrides / 工具分级覆盖」，一张两列的表：`Tool` / 工具、`Tier` / 分级，分级可选 `read`、`inapp_mutate`、`file_write`、`code_exec`、`unknown`。按钮是「Add Override / 新增覆盖」和「Remove Selected / 删除选中」。

表格默认是空的。分组说明写着：为工具显式指定风险分级，通常用于插件工具；没有列出的未知插件工具默认归入未分级，在自动和手动模式下会征求意见；可以按已知可逆的原则把图表类插件工具归入 `inapp_mutate`，让它安静通过。

常见的三条覆盖长这样：

| 工具 | 分级 | 目的 |
|---|---|---|
| `list_chart_items` | `read` | 这个只读工具不在内置表里，覆盖之后自动和每次询问模式都不再问 |
| `search_literature` | `read` | 只做网络检索，不改本地内容，覆盖之后不再问 |
| 某个绘图类插件工具 | `inapp_mutate` | 改动只落在软件里，可以删掉重来，覆盖之后自动模式直接通过 |

这张表在判断顺序里优先于内置分级表，所以既能给未分级工具定级，也能改内置工具的级别。把 `run_code` 改成 `read` 会让代码执行在自动模式下不再过判官直接放行，改动前想清楚后果。

### 保存在哪里

五个标量（默认模式、审批超时、手动模式附加开关、判官模型、判官超时）存在 `agent-config.json` 的 `permission` 分组里。路径规则、危险模式和分级覆盖存在另一个文件 `agent-permissions.json`，位置是配置目录（`DADir::getConfigPath()` 返回的目录）。

三样东西都在点设置页的 OK 或 Apply 时落盘，并向正在运行的智能体发一条重配置消息，立即生效。改完模式之后，正在跑的会话下一轮就按新模式判断，不需要重启软件。

## 子智能体与权限

子智能体调用的工具走同一套判断，用的也是同一份模式、规则和分级。它比主智能体多一重限制：子智能体没有提问工具，不能向用户发问题卡片；遇到需要用户拿主意的情况，它只能在总结里说明。

子智能体发起的需要确认的调用，审批卡片弹在主智能体的对话里，标题旁边带「From subagent: %1」的标记。批准或拒绝的效果与主智能体发起的调用一致，同样受审批超时约束。子智能体侧等待批复的时间算进它自己的墙钟限制，审批排队久了子任务会因为超时结束，任务行显示超时。

派发的具体机制见[子智能体](subagent.md)。

## 常见问题

**只想让插件工具少弹几次卡片，改哪里？**

用工具分级覆盖表。先确认这些工具确实可逆（比如只改图表样式、只读图表内容），再把它们归入 `inapp_mutate` 或 `read`。不要用把手动模式改成自动模式的办法解决个别工具的问题，那会一并放宽文件写入和代码执行。

**审批卡片一直没有出现，任务却停在那里。**

看标签页状态图标，处于等待输入的会话一定有卡片。颜色变暗、停在原地的旧会话可能是连接已经被回收，从会话管理器切走再切回可以重新建立，卡片会重新发出来；已经错过答复窗口的调用需要重新发起。

**把审批超时改小有什么后果？**

超时按未批准处理，调用被放弃，智能体收到拒绝结果之后通常会换个做法再试一次。改小到几十秒时，临时离开座位就会打断正在跑的长任务；改大则一次没答复的调用会占用更久。在多人共用的机器上可以调小，单机使用保留默认。

**全自动模式下还会出现审批卡片吗？**

工具审批卡片不会出现，所有调用直接执行。唯一可能出现的是启动时那张确认卡片，而且只在之前明确选择过全自动时才有。系统目录里的写入被硬性拒绝，卡片上显示失败和原因，除此之外不会停下来等答复。

**判官模型会看到我的数据吗？**

判官收到的是一段代码文本，不是数据集内容；代码里写死的常量、列名和路径会随代码一起送过去。送进判官的代码超过约两万四千个字符时先截断，特别长的脚本可能因此判断得不完整，这种情况会落到需要确认上。

**切换模式会影响正在跑的那一轮吗？**

不会中途换掉。新的一档在下一轮开始生效，正在等待回复或正在执行工具的那一轮按切之前的模式走完。同一条规则适用于所有会话：模式是全局的，切换之后所有会话一起换。

**文件路径规则里的变量写错了会怎样？**

不认识的变量名被整段去掉，剩下什么就按什么匹配。去掉之后范围是空的，这条规则永远不命中；还剩下半截路径时，规则可能匹配到意料之外的目录，`deny` 写错尤其要留意。`${workspace}` 在没有保存过的工程时也是空的，工作区放行规则在这种情况下不生效，导出文件会走征求确认。

范围里的 `**` 跨目录层级匹配，`*` 只在同一层内匹配，`?` 匹配单个字符，字母不区分大小写。规则里写 `C:/Users/...` 和 `c:/users/...` 效果一样。改完规则之后用一次导出试一下，比对着路径猜更快。

## 三种配置

按使用习惯给出三份完整的配置，主要的差别在这几项上：

| | 谨慎 | 均衡 | 快速 |
|---|---|---|---|
| 默认模式 | Manual | Auto | Full Auto |
| 应用内图表改动 | 每次问 | 放行 | 放行 |
| 代码执行 | 每次都问 | 判官过滤灰区 | 放行 |
| 工程内文件写入 | 每次都问 | 放行 | 放行 |
| 工程外文件写入 | 每次都问 | 征求确认 | 放行 |
| 判官 | 不启用 | 填一个快模型 | 不启用 |

**谨慎使用**，默认模式选「Manual (ask every write/code)」，勾上「In manual mode, also ask before in-app chart edits」，审批超时保留 600 秒，判官留空。路径规则里保留预置的两组，可以再加一条 `${home}` 下的 `deny`，阻止写入个人目录。危险模式列表保持预置内容。这样配置下，任何落盘和任何代码都会先问，图表改动也会问，读取类直接过。

**均衡使用**，默认模式选「Auto (rules + judge)」，判官模型填一个响应快的模型标识，判官超时保留 30 秒；路径规则里再加一条 `write_file` + `${project}/**` + `allow`，让工程内的正常产出不问，工程外的写入仍然征求确认；危险模式列表保留预置内容。代码执行由判官过滤灰区，绝大多数分析脚本不会打断。

**快速使用**，默认模式保持「Full Auto (yolo)」，接受启动时那张确认卡片，按「Keep Full Auto」继续。文件路径规则和危险模式都不起作用；如果插件工具经常被未分级规则拦住，在分级覆盖表里把已知可逆的那些工具归入 `inapp_mutate`。系统目录的拒绝仍然生效，试跑陌生脚本时再切回自动或每次询问。
