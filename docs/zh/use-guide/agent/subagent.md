# 子智能体

一个宽泛的问题往往能拆成几件互不依赖的事，比如十几个数据集的概况、若干个字段的统计、几份文档的核对。让主智能体一件一件做完再回答，中间要等好几轮；把这几件事同时交给几个专注的小助手去做，主智能体只负责汇总结论，时间就省下来了。

子智能体就是这种小助手：一段写好的角色说明，加上一份允许使用的工具清单。主智能体在大任务里决定派发，每个子智能体在自己的对话里独立完成一件事，最后把结构化的总结交回来。这一章讲怎么定义它们、怎么管理，以及派发在对话里长什么样。

## 子智能体是什么

一个子智能体是一份定义文件。文件里写三样东西：叫什么名字、负责什么、可以用哪些工具。另外还有一段系统提示词，告诉它怎么工作、按什么格式交结果。

运行时，每派发一个任务就起一份独立的对话。子智能体看不到主会话里的聊天记录，只看得到派给它的那条任务说明，因此任务说明要写完整、自包含。工具清单是白名单：清单外的工具它看不到，也调不到。

子智能体和主智能体共用同一份权限规则。它调用的工具需要批准时，审批卡片弹在主会话里，标题旁边标着来自哪个子智能体，见[权限控制](permission.md)。

## 子智能体的对话不会显示出来

子智能体在自己的上下文里工作，它的中间过程不渲染在主会话的对话区里。会话里能看到的是那张进度卡片，以及派发结束时返回的结果。结果以工具返回值的形式交回主智能体，主智能体拿它继续写结论。

这样设计的后果要清楚：想追查某个子智能体具体做了什么，不能展开它自己的对话，只能看主智能体写在结论里的引用，或者把同一个问题在主会话里直接问一遍。任务说明写得越具体，交回来的总结越接近需要的内容。

## 结果怎么汇回来

一批任务的总结都到齐之后，主智能体才继续往下写。它看到的是每个任务的状态和总结文本，可以按需要取舍。

同一批里的任务互不等待：一个失败或超时，其余照常跑完。总结里通常会标注哪些部分来自子智能体的调研，遇到失败任务时主智能体会说明缺了哪一块。

子智能体一次只做一件事，任务说明里不要塞进两个目标。需要两件事各自做透时，派两个任务，让它们并行。

## 一次派发的完整过程

用户提出一句宽泛的话，比如「这批数据里有哪些问题，顺便核对一下 city 列的写法」。

主智能体先看一遍数据结构，判断这句话里有几件可以并行的事：一批数据集的概况，一件 city 列的一致性核对。它调用派发工具，一次交出两个任务，任务说明分别写清数据集范围和要核对的那一列。

对话里随即出现一张进度卡片，标题写着两个任务，下面两行分别是 `data_profile #1` 和 `check_consistency #1`，状态从排队中变成运行中，再变成完成。两行最后的圆点都变绿之后，卡片右侧显示完成标记。

两份总结回到主智能体手里，它据此写结论：哪些数据集有缺失值，city 列有几种写法，建议统一成哪一种。用户看到的是一段完整的回答，中间的过程留在卡片里，需要时展开核对。

如果其中一个任务失败，主智能体会在结论里写明哪一部分没有拿到结果，其余部分照常给出。想重试那一个任务，接着说一句让它再派一次即可。

## 派发由主智能体决定

用户不直接调用子智能体。是不是拆任务、拆几个、每个任务说明怎么写，都由主智能体在对话里自行判断，它决定之后调用一个派发工具，把若干任务一次性交出去。

主智能体看到的可用清单里，每个子智能体只有名字和一句描述，它按这两项挑人。想让它在某种任务里使用某个子智能体，有两个办法：

- 在提示词条目里点名，比如写「数据集概况交给 `explore`」，条目的正文就是给主智能体的指令，见[提示词库](prompt-library.md)。
- 把描述写具体，让主智能体在需要这类工作时能自己联想到它。

描述写得太含糊时，主智能体可能自己动手做，也可能派给不合适的角色。

## 定义文件放在哪里

定义文件放在软件可执行文件目录下的 `daAgent/subagents` 文件夹里，扩展名 `.md`，只扫描这一层。文件夹不存在时软件会自己建。文件按文件名排序载入，文件名由名称字段决定：保存之后，文件就叫 `<名称>.md`。

这个文件夹里的文件是纯文本，可以整体备份，也可以拷给同事放进同样位置的文件夹里。定义属于这套安装，不属于某个工程；工程文件里不含子智能体定义，把工程拷到别的机器上时不会带走它们。文件在管理对话框里保存时会按固定格式重写，手工编排的缩进和注释保留不下来。

文件由一段前置信息和一段 Markdown 正文组成。前置信息用 YAML 写法，夹在两行 `---` 之间，字段是 `name`、`description` 和 `tools`；正文就是系统提示词。下面是一份最小的样子，用来展示结构，实际内容按任务写。

```markdown
---
name: my_helper
description: One sentence telling the main agent what this subagent is for
tools: [list_data, get_data_info, read_file]
---

正文写这个子智能体的工作方式、限制和输出格式。
```

前置信息里的 `name` 是派发时引用的标识，用小写字母加下划线，不与其它子智能体重复，也不随界面语言翻译。`description` 是给主智能体看的一句话，出现在可用清单里。`tools` 是工具名的数组，决定白名单。两行 `---` 之后的所有内容都算系统提示词正文。

手工编辑时有三条写法上的注意：

- `tools` 除了上面那种行内写法，也可以写成块级列表，一行一个 `- 工具名`。
- 文件开头没有 `---` 时，整个文件被当作正文，名称回退取文件名，工具白名单为空。这样的定义能出现在列表里，但什么工具都调不到。
- 用编辑器保存会按固定格式重写前置信息：`description` 里的换行合并成空格，前置信息里自己加的注释和自定义字段丢掉。

定义文件里还有一个 `permissions` 字段会被解析，当前不生效，编辑器里也没有它的入口；手工写进去不会影响权限判断，不要依赖它。用编辑器保存时这个字段如果原来有内容会被保留下来。

## 内置的 explore

随软件发布一个子智能体，名字是 `explore`，描述是只读的数据探索：查看数据集、列、统计和文件，然后交回结构化总结。它的白名单是 `list_data`、`get_data_info`、`query_data`、`get_column_stats`、`read_file`、`list_figures`，正好是六个读取类工具。

正文要求它自主完成任务、不做任何写入、控制工具调用次数、所有数字都来自工具返回结果，并按固定的四段格式总结：数据集概览、字段说明、数据质量发现、后续分析建议。

这个文件只在缺失时写入。可以改它，也可以删掉，删掉之后下一次启动软件会重新写回原始版本。改过之后升级不会覆盖改动过的内容。

## 管理对话框

入口是 Ribbon「AI Agent / AI智能体」标签页上的「Agent Manager / agent管理」按钮，窗口标题是「Agent Manager」。第二个标签页是「Subagents / 子 Agent」，列出所有定义：一行一个名字，后面跟着描述的前 80 个字符，更长的部分用省略号收尾。列表的提示气泡写着这个清单的用途：可供派发的子智能体定义。

列表下方的三个按钮是 `Add` / 添加、`Edit` / 修改、`Delete` / 删除，与提示词库那一页一致。没有选中行时修改和删除不可用。保存和删除之后列表立即刷新。

列表按文件名的顺序排列，改名之后位置会变。列表只显示名字和描述片段，要看完整内容用编辑对话框打开；描述留空的定义在这里只剩一个名字，挑选时不好判断，这也是建议把四部分都写全的原因。

## 编辑一个子智能体

新增和编辑用同一个对话框，窗口标题分别是「New Subagent / 新增子 Agent」和「Edit Subagent / 编辑子 Agent」，四个部分：

| 字段 | 作用 | 占位文字 |
|---|---|---|
| `Name:` / 名称： | 派发时引用的标识 | `snake_case name used by dispatch` |
| `Description:` / 描述： | 给主智能体看的一句话 | `Short description shown to the main agent` |
| `Allowed tools:` / 工具白名单： | 勾选这个子智能体可以调用的工具 | 无 |
| `System prompt:` / 系统提示词： | 正文说明，带 Markdown 高亮 | `Write the subagent instructions here (Markdown supported). It should finish autonomously and end with a structured summary.` |

名称在编辑模式下只读。要换名字，用「新建一个同名新文件、删掉旧文件」的办法：先新建一个改好名字的定义，再把旧定义删掉。直接改定义文件里的 `name` 字段也可以，改完在管理对话框里重新载入。

工具白名单是一个复选框列表，候选来自软件当前注册的全部工具，再加上定义里已经写着的工具名。列表有两条提示：

- 鼠标停在「Allowed tools:」标签上，提示写着「Only checked tools can be called by this subagent. Permission rules still apply on every call.」，意思是白名单限制能调什么，白名单之外还有权限规则，勾上不等于放行。
- 定义里引用了某个已经不可用的工具时（对应插件被停用之类），那一行显示为禁用且已勾选，提示写着「Unregistered tool (kept in definition) / 未注册的工具（保留在定义中）」。这样的行改不动，也不会被静默丢掉，插件恢复之后自动回到可用状态。

系统提示词区域是一块等宽字体的编辑器，带 Markdown 高亮。一段好的正文通常写清四件事：

1. 角色和任务边界，说明它负责哪一类工作、不负责什么。
2. 工作方法，先看什么、再用什么、应当避免哪些动作。
3. 限制条件，比如只读、控制调用次数、数据缺失时怎么处理。
4. 输出格式，说明最后要交回什么结构，包含哪几段。

运行程序在正文前面还会自动加一段固定的前导说明，要求子智能体自主完成、不能向用户提问、不越出任务范围、不重复调用同一个工具，并在结束时交一份结构化的 Markdown 总结，总结要覆盖做了什么、发现了什么、数据质量方面的问题、以及可选的后续建议。正文里再写「必须自主完成、最后给结构化总结」这类要求与它一致，方向不会冲突。

白名单里含有画图或数据类工具时，运行程序另附一段引用说明，教它用 `da-figure:` 和 `da-data:` 链接指向自己碰过的对象；含有文件写入或代码执行类工具时，附一段权限说明，告诉它等待批准是正常情况，被拒绝时不要绕路重试。

保存时的校验只有两条：名称不能为空，空时提示「Name cannot be empty / 名称不能为空」；名称不能与已有定义重复，重复时提示「A subagent named \"%1\" already exists, please choose another name」，意思是同名子智能体已经存在，需要换一个名称。描述、工具和正文都允许留空，留空的子智能体派发出去做不了实事，建议四项都写。

删除时先确认，内容是「Are you sure to delete subagent \"%1\"?」，意思是确认是否删除这个子智能体。

## 保存立即生效

保存一个定义之后，软件把最新的定义集推给所有正在运行的会话，不需要重启，也不需要重开会话。正在进行中的派发不受影响：一次派发开始时会把当时的定义集取一份快照，已经派出去的任务按快照跑完；下一次派发才用新定义。

删掉一个定义之后，主智能体看到的可用清单里就没有它了。已经跑过和正在跑的任务不受影响。

## 一次派发在对话里是什么样

主智能体决定派发时，对话里出现一张可折叠的进度卡片，与工具调用卡片同一类。

卡片标题写着这一批有几个任务，比如「%1 subagent task(s)」；标题右边显示进度，进行中是「%1/%2 done」，全部到达终态之后显示「· completed」，卡片左侧的圆点变成绿色。

卡片主体是一行一个任务，行名由子智能体名加序号组成，比如 `explore #1`。每个任务行有三部分：状态圆点、任务名、状态文字。状态文字有六个取值：

| 状态 | 含义 |
|---|---|
| `queued` / 排队中 | 已列入这一批，还没轮到执行 |
| `running` / 运行中 | 正在执行 |
| `done` / 完成 | 正常结束，总结交回来了 |
| `failed` / 失败 | 执行中出错 |
| `timeout` / 超时 | 超过墙钟上限被结束 |
| `stopped` / 已停止 | 用户停止这一轮时被结束 |

鼠标停在任务行上，提示气泡里显示这条任务的说明全文（开头二百个字符，过长时截断）。任务说明是主智能体写的，从气泡里能看出它给每个子智能体派了什么活。

派发期间卡片不会因为长时间没有新消息而中断：子进程每 30 秒发一次心跳，把主进程的无活动看门狗顶住。

## 权限与限制

子智能体调用的工具走[权限控制](permission.md)里的同一套判断，模式、路径规则、危险模式都一致。它的审批卡片出现在主会话里，标题旁边标着「From subagent: %1」。等批准的时间算进子任务的墙钟上限，审批排队久了，子任务会以超时结束，任务行显示超时。

子智能体没有提问工具，不能向用户抛问题卡片。信息不足时它只能做合理假设，并在总结里写明假设。需要用户拿主意的地方应当留给主智能体，主智能体有提问卡片可用。

两个设置管着子智能体，都在模型设置页的「Agent Settings / Agent 设置」标签页里：

| 设置 | 取值范围 | 默认值 |
|---|---|---|
| `Subagent Timeout` / 子 Agent 超时 | 60 到 3600 秒 | 600 |
| `Subagent Reasoning Limit` / 子 Agent 推理上限 | −1 到 1000000，有 `No limit` 特殊值 | 60 |

超时按墙钟算，包括等待用户批准的时间。推理上限按步数算，选 `No limit` 时不设上限，新定义默认按 60 步执行，复杂任务可以调大。

子智能体的并发数和单批任务上限在配置文件里，分别是 1 到 2（默认 1）与 1 到 4（默认 2），设置页上没有控件。一批派出去的任务数超过单批上限时，主智能体会收到一条错误说明，它会拆成几批再发。并发数决定同时跑几个，默认一次跑一个，任务之间按顺序进入执行。

## 两个完整定义

下面两份定义可以直接抄进 `daAgent/subagents` 文件夹，也可以照着在编辑器里填写。第一份做只读的数据概况，第二份核对一列文本的格式一致性。

### 数据概况

这份相当于内置 `explore` 的精简版，把范围收窄到概况和字段，不碰文件读取，适合把一句「先摸一下这批数据」交给它。

```markdown
---
name: data_profile
description: Read-only dataset profiling: dataset list, column types, basic quality findings, and a short summary
tools: [list_data, get_data_info, query_data, get_column_stats]
---

任务是给指定数据集出一份概况，只读，不做任何写入。

工作方法：
- 先用 `list_data` 确认数据集名称，名称对不上时在总结里说明实际用的是哪一个。
- 用 `get_data_info` 取列名和类型，用 `get_column_stats` 对数值列取统计量。
- 需要判断缺失情况时用 `query_data` 抽样，调用次数控制在十次以内。

限制：
- 不写文件、不改图表、不执行代码。
- 所有数值必须来自工具返回结果，注明数据集名和列名。
- 信息不足时做合理假设，并在总结里写明假设。

输出一份 Markdown 总结，包含四段：数据集概览、字段说明、数据质量发现、后续分析建议。
```

前置信息三行分别对应名字、描述和工具白名单。名字 `data_profile` 是派发时用的标识，小写加下划线；描述写给主智能体看，一句话说清它是只读的概况工具；白名单只勾了四个读取类工具，即使正文写漏了「只读」，它也调不到写入类工具。描述写成中文也可以，主智能体按语义挑选，不受语言限制。

正文第一句划定了任务和性质。工作方法一节给出顺序和调用次数上限，避免它在宽表上反复抽样；顺序本身也有讲究，先确认数据集名再取列信息，名称对不上时能尽早发现。限制一节重复了只读要求，并把「数值必须有出处」写死。输出格式一节与内置 `explore` 的四段结构保持一致，主智能体对不同子智能体交回的总结可以按同一套结构读。

### 文本一致性核对

这份核对一列文本的格式是否统一，比如城市名有没有混用大小写、日期有没有两种写法、编号有没有多一位少一位。核对需要做字符串统计，白名单里加上了 `run_code`，代价是这个子智能体在执行代码时会走代码执行的权限判定。

```markdown
---
name: check_consistency
description: Check whether the values in one text column keep a consistent format, and list every inconsistent group
tools: [list_data, get_data_info, query_data, get_column_stats, run_code]
---

任务是核对一个文本列的格式一致性，报告不一致的取值，不做修正。

工作方法：
- 用 `get_data_info` 确认列名和类型，用 `query_data` 抽样看清取值的样子。
- 用 `run_code` 统计每种取值的出现次数，按去掉首尾空格后的写法归类。
- 需要时用 `run_code` 统计大小写差异和多余空格的占比。

限制：
- 只写入脚本工作区里的临时文件，别的路径不写。
- 不改动数据集，不修改任何图表。
- 取值种类很多时只报告前二十组，并注明总数。

输出一份 Markdown 总结，包含三段：列的取值概况、不一致分组（每组给出原值、次数、建议统一成什么）、需要人工确认的疑点。
```

描述里写明它负责什么、产出什么，主智能体在需要核对文本字段时会按这句挑它。白名单里的前四项用于确认列和抽样，`run_code` 承担统计，因为按写法归类需要字符串处理。代码执行在自动模式下要过判官或征求确认，一份含代码执行白名单的定义在多任务派发里可能因此停留更久；把核对范围写窄、说明只做只读统计，能减少被拦下的次数。

正文的限制一节把写入限定在脚本工作区的临时文件，与默认路径规则里工作区放行的设置对得上，正常情况下不会频繁弹审批卡片。输出格式一节要求给出原值、次数和建议值三列，主智能体拿到之后可以直接把「建议统一成什么」写进结论。最后要求列出需要人工确认的疑点，是因为格式不一致里总有一部分是业务上有意为之，交给用户判断比让子智能体猜更稳。

### 两份定义的共同点

两份定义都遵循同一套写法：描述一句话说清适用范围，正文先划边界再给方法，最后规定输出结构；限制一节里重复一遍关键约束，防止模型在长任务里跑偏；输出结构保持段落化的 Markdown，便于汇总。白名单只勾真正需要的工具，勾得越少，能造成的意外改动越少。

两份定义都用「先确认列、再抽样、最后统计」的顺序安排步骤，这个顺序在数据类任务里通用：列名和类型确认得越早，后面用错列的可能性越小。输出结构都固定成三段或四段，主智能体汇总时不必区分每个子智能体的风格。

定义写完先手工试跑一次再交给主智能体长期使用：在主会话里直接说「派发给 `data_profile`，看 sales 数据集」，看它交回来的总结是否符合预期，不符合就改定义正文，改完立即生效。

## 用量怎么算

子任务用掉的词元计入发起派发的那个会话，状态栏的计量和会话详情里的累计都包含它们，一条派发的用量会另外标注来源为 `subagents`。派发几个任务是这一轮里成本最高的部分之一，因为每个子智能体都带着自己的完整上下文从头开始。

控制用量的办法是收窄任务：一条任务说明只覆盖一件事，输出结构固定成几段，子智能体就不容易来回探索。反过来，把整个数据集丢给一个子智能体让它「随便看看」，它会反复抽样、反复统计，用掉的词元比拆成三条明确的任务更多。

## 与提示词条目的分工

提示词条目由用户运行，正文直接成为用户消息，主智能体按它工作；子智能体由主智能体派发，用户看不到它的对话，只看到进度卡片和总结。前者的作用是固定流程，后者的作用是并行拆分。

一段任务里既有固定流程又有可并行的部分时，把流程写进提示词，把可并行的部分交给子智能体。两者用名字关联：提示词正文里写「需要并行核对时，派发给 `check_consistency`」，名字与定义的 `name` 字段一致才有效。

## 常见问题

**派发一次要等多久？**

取决于任务的规模。一次派发里所有任务都跑完之后主智能体才继续，单个任务的墙钟上限默认 600 秒，一批里最慢的那个决定整体等待时间。想缩短等待，把任务说明写窄一些，让每个子智能体只做一件事。

**子智能体能在总结里直接引用绘图或数据集吗？**

可以。白名单里含有画图或数据类工具时，运行程序会给它附加一段引用说明，教它用 `da-figure:` 和 `da-data:` 链接指向自己碰过的对象，这些链接在主会话里可以点开，与主智能体写出的链接一致，见[会话与对话](session.md)。

**为什么派出去的子智能体没有用我定义的工具？**

先确认定义里勾选了工具并保存成功，再从管理对话框看一眼列表里的定义还在不在。定义集在派发开始时取快照，改完定义之前已经开始的那一批照旧跑，下一次派发才用新定义。还有一种情况是白名单写对了，但工具被权限规则拦下，任务行会以失败或超时结束，需要看主会话里的审批卡片。

**子智能体删掉之后会回来吗？**

自己新建的不会。内置的 `explore` 会：它在下一次启动软件时被重新写回来，和提示词库里的内置条目一样。

**一份定义能给好几个任务用吗？**

能。同一个子智能体可以在一次派发里出现多次，比如一次派两个 `data_profile` 任务，各看一个数据集；任务行会显示成 `data_profile #1`、`data_profile #2`，各自在自己的上下文里工作，互不影响。

**定义写多长合适？**

参考内置 `explore` 的长度，一段边界说明加一份输出格式，二十来行。写得太短，子智能体只能凭常识工作，容易越界；写得太长，每次派发都要带上全部内容，占用词元也占用它的注意力。复杂任务拆成两个子智能体比写一份很长的定义更可控。

**子智能体还能再派子智能体吗？**

不能。子智能体只有一层，它看到的工具清单里没有派发工具，任务只能自己完成。需要多层拆分时，把任务拆细一些直接派给合适的角色。

**超时或失败的任务能续跑吗？**

不能，终态就是终态。任务列表里的行不会回到运行中，主智能体拿到失败状态后可以在同一轮里重新派一次，或者改小任务范围再派。已经跑过的部分不会浪费，总结里凡是已经交回的内容都在。

**派发会改动我的数据吗？**

取决于白名单。只勾读取类工具的子智能体改不了任何东西；勾了画图工具会新建绘图；勾了文件写入或代码执行会在权限规则下落到磁盘。想让某个子智能体绝对只读，白名单里只留 `read` 级的六个工具，正文里再写一遍只读要求。
