# 配置模型

智能体自己不含模型。它把对话内容发给一个外部大语言模型服务，再把返回的文字显示在对话里。供应商、服务地址、密钥、模型名都要在设置里填好，软件不预置任何一项。这一章讲设置对话框里「Agent LLM Settings / Agent LLM 设置」这一页的用法：添加供应商、拉取模型列表、手工录入模型，以及另一组运行参数各自管什么。

填完这一页智能体才能开始工作。工具执行前是否询问由另一页管理，见[权限控制](permission.md)。

## 几个名词

供应商指一个大语言模型服务的接入点，登记时保存的是名称、接口根地址和密钥三项。基础地址是这个服务对外提供的接口根路径，软件把对话内容发到这条路径下的接口上。模型标识是服务商给每个模型起的名字，比如 `gpt-4o`，调用里用它指定用哪一个。词元（token）是模型计量长度的单位，界面上仍写作 token，状态栏和参数名里的 token 字样都指这个词元。

软件按 OpenAI 兼容接口的约定与服务商通信，模型清单和对话都走这套约定。凡是提供 OpenAI 兼容接口的服务都能登记进来，不需要额外安装组件。

上下文窗口指模型一次能接收和生成的总长度，历史越长、带进去的数据越多，占用的窗口越大。窗口快满时软件会把早期对话压缩成摘要，给后面的内容腾位置，压缩的时机由这一页的参数控制。最大输出 token 是另一回事，它只限制某一次回复的长度，不影响能收进去多少历史。

## 没配置模型时会看到什么

供应商、基础地址、密钥、模型名四项里有任何一项为空，智能体就起不来，具体表现有两种。

在会话里发一条消息，对话区出现一条警告：「LLM is not configured. Please configure LLM in settings first.」。这条消息的意思是当前连接信息不完整，需要先到设置页把模型配好；消息出现在对话流里，被记进会话记录，后面的对话不启动。

从 Ribbon 的「AI Agent / AI智能体」标签页点「Run Agent / 执行agent」，出现的是同一条提示，选中的提示词内容不会被发送。浏览设置里的供应商列表不受影响，那些操作不连服务。

这类提示按广播处理：面板里打开着几个会话，几个会话的对话流里就各出现一条，还没有发过消息的草稿会话同样会收到。面板停在占位页、一个会话视图也没有时，提示没有可显示的位置，此时先新建一个会话再重试。

配置不完整和配置填错是两种不同的失败。前者在本地就被拦住，对话不启动；后者要等调用发到服务商那里才知道，表现为错误卡片，处理见[会话与对话](session.md)。

## 第一次配置的完整步骤

1. 打开主页「Main / 主页」的「Config / 配置」面板，点「Setting / 设置」。
2. 在设置对话框左侧选中「Agent LLM Settings / Agent LLM 设置」，停到「Model Providers / 模型供应商」标签页。
3. 点 `Add Provider`，在对话框里填供应商名称；基础地址填服务商的接口根地址，通常以版本段结尾；密钥粘贴进去。
4. 点 `Fetch Available Models`，等状态区给出结果。服务商不支持模型清单接口时跳过这一步。
5. 在「Available Models」对话框里去掉不需要的模型，确认后它们进入表格。
6. 服务商不支持清单接口时改用 `+ Add Model`，模型标识照服务商文档逐字填。
7. 核对每个模型的上下文窗口和最大输出 token，与服务商文档不符的改掉。
8. 点设置对话框的 OK 或 Apply 落盘。
9. 打开「Agent Assistant / Agent 助手」面板，点「New Session / 新建会话」，在输入框里提一个问题，确认能收到回复。

第 8 步之后配置就位，第 9 步的会话里状态栏中间会显示刚配好的模型名。收到回复说明地址、密钥、模型标识三项都对；收到错误卡片则按卡片上的说明逐项回查。

第 4 步是整个流程里最容易卡住的一步。它要求服务商开放模型清单接口，并且返回 OpenAI 兼容格式的数据；不满足时状态区给出明确的失败文字，按「拉取可用模型」一节里的对照表处理。

第 6 步适合服务商文档齐全的情况：文档里每个模型的名称、上下文长度和输出上限通常都写清楚了，三项照着填。模型标识写错时本地看不出来，直到第一次对话才以 `Request was rejected by the LLM service` 的形式暴露。

## 打开设置页

设置对话框从主页「Main / 主页」的「Config / 配置」面板进入，点「Setting / 设置」。对话框左侧列出所有设置页，智能体占两页，这一页标题是「Agent LLM Settings / Agent LLM 设置」，图标是一个设置符号。页面内部又分两个标签页，默认停在「Model Providers / 模型供应商」。

设置对话框底部的三个按钮是「OK」「Cancel」「Apply」。供应商和运行参数的改动先存在于内存里，点 OK 或 Apply 之后写进磁盘。改完直接关窗口而不点这两个按钮，改动丢失；从上次应用之后新改的项在关闭时不会被询问。设置对话框可以随时重新打开，排查问题的过程中反复调整不需要重启软件。

智能体在设置对话框里占两页，紧挨着的另一页「Agent Permission Settings / Agent 权限设置」管工具执行的审批，见[权限控制](permission.md)。两页都填完之后智能体才能完整使用。

这一页里的按钮、字段和状态文字在源码里都是英文，中文界面按这一章给出的对应关系显示。填地址和密钥的地方只有这一页，别的设置页里没有第二处入口。

## 模型供应商标签页

标签页分成左右两半。左半是已配置的供应商列表，加三个按钮：`Add Provider` / 新增供应商、`Edit Provider` / 修改供应商、`Remove Provider` / 删除供应商。列表本身只能选中，不能双击改名，所有增删改都在弹出的对话框里做。列表的提示气泡写着「Configured LLM providers. Select to view details; edit via the buttons above. / 已配置的 LLM 供应商，选中查看详情，通过上方按钮编辑」。

右半显示选中供应商的详情，四个字段加一张表：

| 字段 | 内容 |
|---|---|
| `Name` / 名称 | 供应商的显示名 |
| `Base URL` / 基础地址 | 服务接口的根地址 |
| `API Key` / API 密钥 | 显示为 `not set` / 未设置 或 `set (hidden)` / 已设置（隐藏），不回显明文 |
| `Models` / 模型 | 一张表，三列：`Model Name` / 模型名、`Context Size` / 上下文大小、`Max Output Tokens` / 最大输出 token |

列表为空时右半边没有可显示的内容，模型表也是空的。第一次使用时先按下一节加一个供应商。

在列表里换一个供应商，右半边的详情跟着换。详情区的字段是只读的，要改就点 `Edit Provider`。修改对话框和新增对话框是同一个，反填原来的值；把名称改成另一个已有供应商的名字会被同名校验拦下，改成全新的名字则原样保存。供应商重命名之后，对话状态栏选择器里的名字同步更新，已保存的会话记录不受影响。

模型表里的三个值各有用途。`Model Name` 是发给服务商的模型标识，也是选择器里显示的名字；`Context Size` 记下这个模型的上下文窗口，软件用它在对话状态栏显示窗口占用，并计算上下文压缩的触发点；`Max Output Tokens` 是该模型单次回复的长度上限，用来限制每次调用里的输出上限参数。这些值不会去服务商那边校验，填错只会体现在运行结果上。

拉回来的清单里常有几十个模型，其中一部分是不适合对话的（嵌入模型、语音模型之类），勾选时按服务商文档挑出真正要用的几个即可，多余的留在清单外面不影响使用。需要时随时可以再拉一次补进来。

同一个供应商下面可以放多个模型。登记多个供应商时，软件同一时刻只用一个，选用哪一个在对话状态栏的模型选择器里切换，见[会话与对话](session.md)。列表里的顺序只影响显示，不影响选用结果。切换是全局的：选好之后，所有正在运行的会话在各自下一轮一起换用新模型，不是每个会话各记一个。

## 添加供应商

点 `Add Provider` 打开对话框，窗口标题是「Provider / 供应商」，三个输入框：

- `Name`，占位文字「provider name, e.g. OpenAI」。供应商的显示名，在模型列表和状态栏里都用它标识。
- `Base URL`，占位文字 `https://api.openai.com/v1`。服务接口的根地址，末尾的斜杠会被自动去掉。
- `API Key`，输入时以圆点回显。填好之后详情区只显示 `set (hidden)`。

对话框下半部分是模型列表，列名同样是 `Model Name`、`Context Size`、`Max Output Tokens`，上面一排按钮：`Fetch Available Models` / 获取可用模型、`+ Add Model` / 新增模型、`- Remove` / 删除行。双击一行可以修改它，选中一行再点 `- Remove` 删掉这一行。整个对话框的确定按钮是「OK」，取消是「Cancel」。

按 OK 时做两条校验：

- 名称不能为空，也不能与已有的供应商重名。重名时对话框不关闭，状态区显示「Provider name already exists / 供应商名称已存在」。
- `Base URL` 不能为空。

名称或地址留空时确认没有反应，光标停在那个输入框上，不弹提示框。这两个空值检查之外没有别的格式检查，地址里写没写协议头、带没带版本段都不在本地拦截的范围里。密钥不在校验范围内，可以留空保存；这样的供应商能出现在列表里，但发消息时会因为缺少密钥而启动失败，收到与未配置模型相同的提示。

新增一个供应商之后，列表自动选中它，模型表是空的。此时供应商能保存，但在状态栏的选择器里没有可选项，至少加一个模型才用得起来。对话框按取消时，输入的内容整份丢弃，列表里不会多出条目。

编辑已有供应商时，模型表里原有的行原样带进来，可以继续增删改。供应商名称改掉之后，配置文件里的记录跟着改名，状态栏和会话记录里显示的名字一起更新。

## 拉取可用模型

`Fetch Available Models` 向供应商索取模型清单，做法是发一个 `GET {base_url}/models` 调用，调用头带 `Authorization: Bearer <API Key>`。密钥留空时不带这个头。整个调用超时 15 秒，超时按失败处理。返回内容按 OpenAI 兼容格式解析，取每一项的 `id`，去重并排序。

按钮下方的状态区依次可能出现这些文字：

| 状态文字 | 含义 |
|---|---|
| `Base URL is required to fetch models` / 获取模型需要先填写基础地址 | 基础地址为空，调用没有发出 |
| `Fetching...` / 获取中... | 调用已发出，等待返回 |
| `%1 models fetched` / 获取到 %1 个模型 | 返回成功，条数是去重排序后的数量 |
| `Fetch failed: %1` / 获取失败: %1 | 调用失败，冒号后面是网络层给出的原因 |
| `No models returned` / 未返回任何模型 | 调用成功，但清单里没有可用的模型标识 |
| `Added %1 models` / 已添加 %1 个模型 | 勾选完成后实际新增了几个 |

成功的一条前面带一个勾号图标，失败的两条前面带一个叉号图标。获取期间按钮变灰，返回后恢复可点，可以连续重试。

拉到清单后弹出「Available Models / 可用模型」对话框，提示文字是「Select models to add: / 选择要添加的模型：」，每个模型一行复选框，默认全部勾选，另有两个按钮 `Select All` / 全选和 `Deselect All` / 全不选。按 OK 把勾中的模型加进表格，按 Cancel 一个也不加。加进来的模型用一组固定默认值补全：上下文窗口 262144，最大输出 8192。

勾选对话框里已经存在于表格的模型同样会列出来，确认之后被跳过，不会重复添加。已经在表格里的模型不会再被加一遍，所以同一个清单拉两次不会出现重复行。这两个默认值只是起点，模型的真实上限要看服务商文档，不对就按下一节的方法改。

有些服务商不开放模型清单接口，或者返回的数据里没有 `id` 字段，这两种情况都会得到 `No models returned`。这时用 `+ Add Model` 从服务商文档里抄模型标识，效果和拉取回来的一样。

拉取动作按一次点一次，不受这一页的运行参数影响，失败的等待时间最长就是那 15 秒。清单只在按了对话框的 OK 之后才进入表格，按取消退出不会留下任何改动。

## 手工录入和修改模型

`+ Add Model` 弹出「Model / 模型」对话框，三个字段：

| 字段 | 取值范围 | 步长 | 默认值 |
|---|---|---|---|
| `Model Id` / 模型标识 | 文本 | | 空，占位文字「model id, e.g. gpt-4o」 |
| `Context Window` / 上下文窗口 | 1024 到 2097152 | 1024 | 262144 |
| `Max Output Tokens` / 最大输出 token | 1 到 1048576 | 128 | 8192 |

两个数字框都带后缀 ` tokens`。`Model Id` 要填服务商接口里使用的模型标识原文，比如 `gpt-4o` 或 `deepseek-chat`，大小写和连字符都要与服务商文档一致。`Model Id` 不能为空，也不能和同一供应商下的其它模型重名，否则对话框不关闭，光标回到该输入框。

上下文窗口要给够整个对话的容量：系统提示词、历史消息、工具结果和这次的回复都算在里面。填得比模型真实窗口大，压缩就不会及时触发，调用可能被服务商以超长拒绝；填得太小，压缩频繁触发，早期对话内容被摘要替换得更早。最大输出 token 决定一次回复最长能写多少，写长报告或长代码时如果回复在中途被截断，先查这个值是不是小于需要。

双击表格里的模型行打开同一个对话框，用来修改已有的行；修改时排除自身，改回原来的标识不会触发重名。改完之后行里的三个值立即更新，点设置页的 OK 或 Apply 落盘。删除模型用 `- Remove` 删掉选中的行，没有二次确认。表格里至少留一个模型，否则该供应商没有可选项。

读配置时另有一层回退：某个模型的上下文窗口或最大输出 token 缺失或不是正数，上下文窗口按 262144 补齐，最大输出 token 按 131072 补齐。手工填进去的值不会走到这条回退，只有手改配置文件才会遇到。

手改配置文件时，一行模型只写标识也可以，两个数字会按上面的规则补上。界面上的模型对话框两边相反：标识不能留空，数字框始终有值。

## 删除供应商

在列表里选中一个供应商，点 `Remove Provider`，它就从列表里消失，没有确认对话框。删除只影响内存里的这一条记录，磁盘上的配置文件要等设置页的 OK 或 Apply 才更新。删掉当前正在用的供应商之后，软件会自动从剩下的供应商里取一个接上；一个都没有时，对话状态栏的模型选择器显示「No model / 无模型」，发消息会收到未配置模型的提示。

删除是不可撤销的，重新添加要再填一遍密钥。只想临时停用某个供应商时，可以保留它，改用状态栏切换模型。把供应商全部删光也不会报错，只是智能体回到没配置的状态，重新添加一条即可恢复。

同一个模型标识注册在两个供应商下时，选择器里会出现两条同名项，分别挂在各自的供应商下面，选哪一条就用哪一条的连接信息。这种情况多出现在把一个服务同时按两个接入点登记时，比如本机代理和直连各配一份。

每个供应商下的模型不必求全，选择器里列的是全部供应商的全部模型，条数多了以后切换时要翻几层。常用的三五个留在表里即可，需要别的模型时再补。

## 在对话里切换供应商和模型

设置页只负责登记供应商和模型。实际使用哪一个，在对话状态栏中间的模型选择器里切换：点开之后先列供应商，选一个进去，再列该供应商下的模型，当前使用的一项带勾。选择器上有返回上一层的入口，整体提示文字是「Select LLM model / 选择 LLM 模型」。没有可用的模型时这一栏显示「No model / 无模型」。

选择器给出的这类改动立即生效并立即写盘，正在运行的会话在下一轮换用新模型，不会丢掉已经积累的对话内容。

登记两个供应商的常见用法是给快模型和慢模型各留一条：日常问答用响应快的那个，遇到长文档分析时切到上下文窗口更大的那个。两个供应商的密钥分别保存，切换时不重填。

## 配置保存在哪里

供应商清单、激活的供应商与模型、运行参数都写在同一个文件里：`agent-config.json`，位置是配置目录（`DADir::getConfigPath()` 返回的目录）。软件启动时读这个文件；如果发现旧版留下的 `agent-config.ini`，会把里面的内容迁移过来，迁移之后以 JSON 为准。

文件里按用途分成几组：`llm` 存激活供应商派生出来的连接信息，`execution` 存这一页的运行参数，`subagent` 存两个子 Agent 上限，`permission` 存权限相关的标量。权限页自己的规则表另存一个文件，见[权限控制](permission.md)。

密钥在内存里是明文，写进文件之前会加密。Windows 上用的是系统自带的数据保护接口（`CryptProtectData`），加密结果与当前用户账号绑定；其它平台上退化为 Base64 编码，拿到文件就能还原出密钥。把配置文件拷到另一台机器或另一个 Windows 账号下，密钥解不开，需要重新填写，其余设置照常可用。

文件内容被改坏时，软件读不出配置，日志里记一条解析失败，界面按空配置显示，重新填写即可恢复。旧版留下的 `agent-config.ini` 会被读出来合并进 JSON，合并完成后改名为 `.bak` 保留在原处。

## 改动什么时候生效

供应商的增删改、运行参数的修改，在设置页点 OK 或 Apply 的那一刻写盘，并即时同步给正在运行的会话：软件把新配置通过一条重配置消息发给智能体子进程，子进程在当前这一轮跑完之后处理，下一轮对话开始用新值。正在等待回复的那一轮不会被中途换掉配置，已经积累的会话内容也不会因此丢失。

模型切换走的是同一条通道，在对话状态栏里选好模型之后立即生效。修改 `Auto prestart on launch` 这类启动相关的开关不影响已经跑着的子进程，下次启动软件时按新值执行。会话留存的两个参数在启动时清理，改完之后这次运行不动磁盘上已有的会话。

## Agent 设置标签页

第二个标签页「Agent Settings / Agent 设置」是一张按行排列的参数表。字段分为数字框、双精度数字框和复选框三种，数字框带单位后缀（秒、天、次），输入超出范围的数字时值被钳到边界，不会报错。

点 OK 或 Apply 之前，改动的值只存在这一页的控件里；把某个字段改回默认值不需要额外操作，直接填回去即可。每个字段的提示气泡里写着一句用途说明和一个建议值，拿不准时按建议值填。

| 字段 | 取值范围 | 默认值 |
|---|---|---|
| `Ready Timeout` / 就绪超时 | 5 到 300 秒 | 60 |
| `Stop Timeout` / 停止超时 | 1 到 60 秒 | 5 |
| `Compaction Threshold` / 压缩阈值 | 0.50 到 1.0，步长 0.05 | 0.85 |
| `Max Recent Messages` / 保留最近消息数 | 4 到 50 | 10 |
| `Tool Result Max Chars` / 工具结果截断阈值 | 1000 到 500000 | 20000 |
| `Tool Result Preview Chars` / 工具结果预览长度 | 100 到 10000 | 2000 |
| `Max Sessions` / 最大会话数 | 5 到 200 | 20 |
| `Session Retention Days` / 会话保留天数 | 1 到 365 天 | 30 |
| `Max retries` / 最大重试次数 | 0 到 20 | 5 |
| `Retry interval` / 重试间隔 | 0 到 300 秒 | 5 |
| `Retry interval increment` / 重试间隔递增 | 0 到 60 秒 | 1 |
| `Request timeout` / 单次调用超时 | 10 到 600 秒 | 120 |
| `Inactivity timeout` / 无活动超时 | 60 到 600 秒 | 240 |
| `Max process restarts` / 最大进程重启次数 | 0 到 10 | 3 |
| `Reasoning iteration limit` / 推理迭代上限 | −1 到 1000000，勾选 `No limit` / 不限制 时禁用数字框 | 勾选不限制 |
| `Subagent Timeout` / 子 Agent 超时 | 60 到 3600 秒 | 600 |
| `Subagent Reasoning Limit` / 子 Agent 推理上限 | −1 到 1000000，有 `No limit` 特殊值 | 60 |
| `Auto prestart on launch` / 启动时自动预热 | 复选框 | 勾选 |

这些参数按用途分成五组。

**超时**，`Ready Timeout` 是启动后等待智能体子进程就绪的时间，机器慢或首次加载 Python 环境较久时可以适当加大，建议值 60 秒写在提示气泡里。`Stop Timeout` 是点停止后等待子进程退出的时间，一般不动；停止很慢时调大这个值也不会让停止变快，它只是一个等待上限。`Request timeout` 管单次模型调用，回答很长的模型容易接近这个上限，网络慢时加大。`Inactivity timeout` 是看门狗：这么久没有收到子进程的任何消息就把它停掉，界面卡住不动时最终由它结束这次等待，把它调小会让偶发的长时间等待更容易被误判为卡死。`Subagent Timeout` 是单个子任务的墙钟上限，等待审批的时间也计入，派发出去的调研任务经常要跑几分钟。

**上下文与消息处理**，`Compaction Threshold` 是压缩触发比例，按当前模型的上下文窗口算，0.85 表示用到 85% 时触发压缩。`Max Recent Messages` 是压缩后仍然保留原文的最近消息条数，改大一些可以少丢细节，代价是每轮调用带着的内容更多。`Tool Result Max Chars` 是工具结果进对话前的截断阈值，超过就只留摘要和预览，预览长度由 `Tool Result Preview Chars` 决定；分析宽表时经常遇到结果被截断的标注，加大前者能留住更多列和行，两个值都调大时每轮消耗的词元随之增加。`Reasoning iteration limit` 是单回合的推理步数上限，每轮工具调用耗 3 步，勾选 `No limit` 表示不限制；即使不限制，连续重复同一个工具调用仍会被自动终止，这是另一层循环保护。这个字段默认就是不限制，正常使用不需要动。

**重试与重启**，服务返回限流、服务器错误、拒绝这次调用或网络错误时，`Max retries` 决定最多自动重试几次，0 表示不重试。`Retry interval` 是第一次重试前等待的秒数，`Retry interval increment` 是每次失败后多加的秒数，比如间隔 5、递增 1 时依次等待 5、6、7 秒。认证失败和配额耗尽不重试，直接报错，对应连接信息填错的情况。`Max process restarts` 管子进程崩溃后的自动重启次数，0 表示不重启；崩溃时正在进行的这一轮会失败，重启之后会话记录仍在，可以从对话历史继续。

**子智能体**，这一组是两个上限：`Subagent Timeout` 按墙钟计时，`Subagent Reasoning Limit` 按推理步数计，后者填 −1 表示不限制，界面上选择 `No limit` 时数字框显示为「不限制」。子智能体的并发数和单批任务上限另有两个值，分别是 1 到 2（默认 1）与 1 到 4（默认 2），设置页上没有对应控件，目前只能改配置文件。派发机制本身见[子智能体](subagent.md)。

**会话留存与启动**，`Max Sessions` 是保留的会话数量上限，`Session Retention Days` 是会话保留天数，早于这个天数的会话在启动时清理，上次活跃的那一个不受清理影响；两个值只在这一页改，清理动作发生在软件启动时，改小了不会立刻删掉刚超过数量的会话。`Auto prestart on launch` 决定启动时是否预先把智能体子进程拉起来：勾上时第一次对话的等待时间短，代价是常驻内存多一份；内存紧张就取消勾选，第一次对话前会多等几秒，这个开关在下次启动时生效。预启动发生在插件全部加载之后，子进程拿到的是完整的工具清单，第一次对话就能用上全部工具。

几组参数之间有牵连，改一个之前先看一眼另一个：

- `Tool Result Max Chars` 与 `Compaction Threshold` 一起决定对话能撑多久。把大量工具结果整段带进对话，等于每轮都多花词元，压缩会来得更早；数据表很宽时，把结果阈值调大和把压缩阈值调高往往要同时做。
- `Subagent Timeout` 允许子任务跑到 3600 秒，`Inactivity timeout` 的最小值只有 60 秒，两者看起来冲突。派发期间子进程每 30 秒发一次心跳，看门狗因此不会被触发，长任务可以放心设到十分钟。
- `Max retries` 与 `Retry interval`、`Retry interval increment` 一起决定最坏情况下的等待。按默认值算，五次重试依次等待 5、6、7、8、9 秒，合计 35 秒；服务端在返回里带了 `Retry-After` 时以它为准。

按常见的诉求，可以这样改：

| 现象或诉求 | 调整 |
|---|---|
| 工具结果经常被截断，看不到完整表格 | 把 `Tool Result Max Chars` 调大，比如 50000 或 100000 |
| 压缩之后丢掉了刚才的细节 | 把 `Compaction Threshold` 调到 0.9 以上，或把 `Max Recent Messages` 调大 |
| 长回答写一半就停 | 检查模型的 `Max Output Tokens`，同时把 `Request timeout` 调大 |
| 服务偶尔抖动就整轮失败 | 保持 `Max retries` 在 5 左右，`Retry interval` 不宜小于 3 秒 |
| 界面长时间无响应却看不出原因 | 把 `Inactivity timeout` 调小，让看门狗更早介入 |
| 第一次对话总要等几秒 | 勾选 `Auto prestart on launch` |
| 会话列表越积越多 | 把 `Max Sessions` 和 `Session Retention Days` 调小 |

改完这些值之后，如果问题照旧，多半不在这一页：回复内容被截断要看上下文设置和模型，连接失败要看地址和密钥，行为异常要看日志。

这一页没有温度、top-p、采样惩罚这类参数，软件里不存在相应的设置项。跟模型连接有关的参数只有基础地址、密钥、模型标识、上下文窗口和最大输出 token 五项，模型的行为由服务商和模型本身决定。

## 配置是全局的

这一页的所有值属于整个软件，不随工程保存，也不会在切换工程时变。工程文件里保存的是数据、工作流、绘图、脚本和属于该工程的会话记录，模型连接和运行参数不在其中。同一台机器上打开任何工程，用的都是这里的配置，见[会话与对话](session.md)。

在多台机器之间迁移时，把 `agent-config.json` 一起复制过去即可，密钥需要在新机器上重新填写。工程文件里不含密钥，把工程发给别人不会泄露密钥。

## 填完之后的检查

配置是否可用，按下面几项快速过一遍：

1. 供应商列表里选中的那条，`Base URL` 有值，密钥一栏显示 `set (hidden)`。
2. 模型表里至少有一行，`Model Name` 与服务商文档里的标识逐字一致。
3. 对话状态栏中间的一栏显示的是这个模型名；显示 `No model` 说明还没有可用的模型。
4. 发一条不需要工具的简单问题，比如「用一句话说明这份配置是否可用」，确认能收到流式回复。
5. 内容里出现错误卡片时，展开详情看原文，对照常见问题一节里的表格定位。

第 3 项显示 `No model` 时，问题通常出在模型表是空的，或者激活的供应商被删掉了。第 4 项失败而前三项都正常时，问题多在服务端，看错误卡片的类型。

## 常见问题

**兼容服务的基础地址怎么填？**

填到接口根路径，通常以版本段结尾，比如 `https://api.deepseek.com/v1`。本机运行的服务填 `http://127.0.0.1:<端口>/v1`，端口以服务自己的文档为准。软件在这个地址后面拼 `/models` 取模型清单，对话调用也发到同一层路径。填到某个具体接口会导致地址重复，末尾多写斜杠则被自动去掉。

地址填对但密钥不对时，拉取模型显示获取失败，原因里通常是 401。地址带了多余路径、服务没启动、端口写错时，原因里通常是连接被拒绝或域名解析失败。

**拉取模型列表失败怎么办？**

先看状态区的原文。提示 `Base URL is required to fetch models` 说明地址没填；获取失败后面跟的原因多来自网络层或服务端，依次检查网络能否到达该地址、密钥是否有效、地址里是不是少了版本段。返回成功但一个模型都没有时，换 `+ Add Model` 手工添加，模型标识照服务商文档的原文填。拉取失败不影响手工添加，两种方式最终写入的是同一张表。

**上下文窗口设置影响什么？**

它不改变模型本身的能力，只是告诉软件当前模型的窗口有多大。用到它的地方有两处：对话状态栏的 token 计量里，`window: %1` 一行的数字就是它；上下文压缩的触发点按它乘以 `Compaction Threshold` 算。填得比真实值小，压缩提前触发，对话会更早丢掉早期细节；填得比真实值大，压缩过晚，调用内容可能超过模型实际能收的长度而报错。服务商文档给出多少就填多少。

**配置填齐了，一问就报错怎么办？**

先看错误卡片上的第一句，软件按失败类型给出了不同的说明：

| 卡片上的一句话 | 指向的问题 |
|---|---|
| `API key invalid or expired, please check settings` | 密钥无效或已过期，回设置页重填 |
| `API quota exhausted, please check account balance or change API key` | 账号额度用尽，换密钥或充值，重试无用 |
| `Failed after repeated retries: rate limited` | 触发限流，等一段时间再试或降低使用频率 |
| `Failed after repeated retries: network error` | 网络不通，检查代理和防火墙 |
| `Failed after repeated retries: server error` | 服务端持续报错，稍后再试 |
| `Request was rejected by the LLM service, see details for the original error` | 服务拒绝这次调用，展开详情看原文，常见原因是模型标识写错或参数不被该模型接受 |
| `Context window exceeded and compaction failed` | 上下文超限且压缩没有成功，核对上下文窗口设置或缩短单次输入 |

这些卡片都带一个详情展开入口和复制按钮，原文可以复制出来对照服务商文档排查。

**换个模型之后，正在进行的会话会怎样？**

会话历史完整保留，正在等待回复的那一轮继续用原来的模型跑完，下一轮开始用新模型。换到上下文窗口更小的模型时，同样的历史占用比例更高，压缩会比换之前更早触发；换到更慢或更快的模型只影响下一轮的速度，不影响已经写下的内容。会话记录里的历史消息不会因为换模型被删除。

配置改完之后建议回到会话里跑一轮简单问答确认，改动是否生效从第一次回复就能看出来。
