# 会话与对话

会话是智能体的一个对话标签页。每个会话有自己的一串消息，也有自己的一份 Python 运行空间：在 A 会话里定义的变量，B 会话里看不到。两个会话可以同时开着，一个在跑分析，另一个接着提问，互不干扰。

这一章从打开软件到拿到第一个有用的回答走一遍，然后拆开对话界面的每个部分：状态栏、输入区、工具调用卡片、提问卡片、错误卡片，以及标签页和会话管理器的全部操作。

## 走通一次对话

1. 启动软件。配置过模型之后，智能体子进程会在后台预先启动。
2. 在 Ribbon 的「View / 视图」标签页里点「Show Agent Area / Agent 助手」，把「Agent Assistant / Agent 助手」停靠面板显示出来。面板默认在右侧，可以拖动停靠到别处。
3. 面板里第一次显示的是占位页，点上面的「New Session / 新建会话」，或者点 Ribbon「AI Agent / AI智能体」标签页的「New Session」。
4. 面板里多出一个标签页，标题是「(untitled) / （未命名）」。标签页里是对话界面，底部有一个多行输入框。
5. 在输入框里用一句话描述任务，比如「列出当前所有数据集的名字和形状」。输入框不接受回车发送，点输入框右侧的「Send / 发送」按钮。
6. 第一句话发出后，这个会话才真正建立，标题会取第一句话里的几个字。对话区先是出现自己的消息，接着智能体的回复逐段出现。
7. 回复里通常会带一串工具调用卡片，比如先调 `list_data` 再调 `get_data_info`。卡片按分组折叠显示，点开可以看到每一次调用的参数和返回的内容。
8. 如果智能体需要确认某件事，它会抛出一张提问卡片，点选项或者填一段自己的回答再提交。
9. 拿到结果后可以继续追问，比如「把第一个数据集的前 100 行导出成 CSV，放到工作区」。同一会话里的上下文和变量一直保留。
10. 不需要这个会话时，右键点它的标签页选「Delete Session / 删除会话」，或者留着给下次用。

第 5 步里的措辞值得多花一点心思：说清要什么结果、用哪份数据、要不要出图。描述得越具体，智能体越少来回确认。写好的描述可以存成提示词库里的条目反复使用，见[提示词库](prompt-library.md)。

## 会话是什么

一个会话对应「Agent Assistant / Agent 助手」面板里的一个标签页。标签页可以并排分屏摆在面板里，可以互相拖动换位，不能拖出去变成独立窗口。

会话之间的隔离有两层。对话历史各自一份，A 会话看不到 B 会话聊过什么；Python 运行空间也各自一份，工具里用到的数据集对象、中间变量、导入的模块都按会话分开。两个会话同时问同一个问题也不会互相覆盖结果。

智能体面板同一时间只显示一个标签页，别的会话可以在后台继续跑。标题栏上的状态图标和提示会告诉每个会话处在什么状态。

## 打开一个会话

打开新会话的入口有三个，行为相同：

- Ribbon「AI Agent / AI智能体」标签页的「New Session / 新建会话」按钮。
- 面板标题栏上插在系统按钮旁边的加号按钮。
- 没有打开任何会话时，占位页上的「New Session / 新建会话」按钮。

面板里没有打开任何会话时显示的是占位页：一个图标、一行文字「No agent session is open / 没有打开的 Agent 会话」，加那个新建按钮。关掉最后一个会话之后回到这个页面。

新建出来的是一个草稿标签页，标题显示「(untitled) / （未命名）」。草稿不写进磁盘：不发消息就关掉，磁盘上不会留下记录。发出第一条消息的那一刻会话才真正创建，消息落盘，标题按内容自动命名。已经有一个没有发过消息的草稿时，再点新建会把它抬到前面，而不是多开一个空标签页。

标签页可以拆分和并排停靠，操作方式和绘图、数据表这些内层标签页一致，见[主界面](../getting-started/main-window.md)。

新建出来的标签页自动成为当前会话，面板切到它。原来正在跑的会话不受影响，留在后台继续跑，标签页状态相应变化。一个面板里可以同时开着多个会话，没有数量上限，会话文件本身的留存数量另有规则，见本章末尾的存储一节。

## 对话界面的组成

标签页从上到下分成三块：消息区、状态栏、输入区。

消息区从上往下按时间排列，包含自己的消息、智能体的回复、工具调用卡片、提问卡片、审批卡片和错误卡片。智能体的回复是流式出现的，边生成边追加到同一个气泡里，界面最多每 50 毫秒重绘一次，长回复不会把界面拖卡。回复按 Markdown 渲染：标题、列表、表格、引用都能正常显示，代码块带语法高亮，数学公式按 KaTeX 渲染，写成 `$...$` 或 `$$...$$` 都能显示。

在消息区点右键只有三项：复制、粘贴、全选。软件关掉了浏览器控件自带的右键菜单。

## 状态栏

状态栏在输入框上方，从左到右有四组内容。

最左边是状态文字，跟着当前这一轮的状态变化：空闲没有提示，正在启动显示「Agent starting... / Agent 启动中...」，等待回复显示「Agent thinking... / Agent 思考中...」，可以输入时显示「Ready / 就绪」。

中间是模型选择器，分两级：点开先列供应商，选一个进去再列该供应商下的模型，当前使用的一项带勾，提示文字是「Select LLM model / 选择 LLM 模型」。没有可用模型时显示「No model / 无模型」。切换立即生效并写进配置，所有会话在下一轮一起换用新模型，设置方法见[配置模型](model-config.md)。

再往右是权限模式选择器，三个选项分别显示为「Full Auto / 全自动」「Auto / 自动」「Ask Every Time / 每次询问」，鼠标停在上面会给出这一档放行什么、询问什么的提示。切换行为和确认卡片见[权限控制](permission.md)。这个选择器和模型选择器一样是全局的，改了之后所有会话一起用新的一档。

最右边是词元计量，空闲时显示「tokens: -」。跑过一轮之后变成一个数字，点开有五行的明细：

| 行 | 内容 |
|---|---|
| `input: %1` | 这一轮送进模型的词元数，包含系统提示词、历史消息和工具结果 |
| `output: %1` | 这一轮模型生成的词元数 |
| `total: %1` | 输入加输出 |
| `window: %1` | 当前模型的上下文窗口大小 |
| `source: %1` | 这组数字的来源标识 |

流式生成过程中数字是按已收到的片段估算的，状态栏上的数字带一个波浪号前缀；一轮结束后换成服务端返回的用量。`source` 一行的取值就是来源标识，比如流式阶段的 `streaming_estimate`。

读这一组数字的方法：`total` 是这一轮开始前的历史加上这一轮本身的量，拿它除以 `window` 就是当前占用的比例。比如输入 48000、输出 1200、窗口 262144，占用接近两成。占用比例接近压缩阈值时，下一轮就会触发压缩，`total` 随之回落。数字偏大先看工具结果，宽表返回一行几十列时，一次调用的结果就能占掉几万词元。

## 输入区

输入区是一个多行文本框加一个按钮。文本框的占位文字是「Type a message... / 输入消息...」，按回车只是换行，发送要靠点右边的按钮。这个设计让多行任务描述可以放心排版。

按钮的文案随状态变化：

- 空闲时是「Send / 发送」。
- 智能体忙的时候变成「Stop / 终止」，点它就是停止这一轮。
- 停止过程中显示「Stopping... / 终止中...」，这一轮收尾之后回到「Send」。

在别的会话里点了新建会话、切了模型、关了面板，都不影响这个输入框里的草稿内容。

## 工具调用卡片

智能体不直接操作软件，它通过工具来做事情。每调一次工具，对话里就多一张卡片；同一次回复里的多次调用归在一个可折叠的分组里，分组标题是「N tool calls / N 个工具调用」。

卡片上显示工具名和参数，展开后能看到返回结果的 JSON。几张卡片上会出现这些标注：

| 标注 | 含义 |
|---|---|
| `queued` / 排队中 | 这次调用已经排出去了，还没轮到执行 |
| `running` / 运行中 | 正在执行 |
| `result truncated` / 结果已截断 | 返回内容超过阈值，只带回了摘要和预览 |
| 分组标题上的状态圆点 | 这次回复里的全部调用是否都已收尾 |

工具结果截断阈值在设置页里改，改大之后同一轮带回来的内容更多，占用窗口也更多，见[配置模型](model-config.md)。每个工具要什么参数、做哪些改动，见[内置工具](tools.md)。

分组展开状态在会话里保留，翻回去看之前那几轮时不用重新展开一次。同一轮里的调用顺序就是执行顺序，从上往下读能还原智能体的思路：先看数据、再取数、再画图。

## 一次分析在界面上是什么样

提一个带明确目标的问题，比如「看看 sales 这个数据集里每个月的销售额总和，画成折线图」，界面会按下面的顺序长出内容。

1. 自己的消息出现在消息区，气泡样式与智能体的回复不同。
2. 智能体先流式吐出一小段说明，比如准备先确认数据集和列名。
3. 出现一个折叠的工具调用分组，标题写着这一批调了几次工具。展开可以看到 `list_data`、`get_data_info`、`query_data` 依次排队执行，每张卡片带工具名、参数和结果。
4. 说明文字继续，接着出现 `create_chart` 的卡片，参数里能看出用的是哪两列、画的是折线还是散点。
5. 回复末尾是一段结论，通常带一个 `da-figure:` 链接，点它把刚画好的绘图抬到前面。
6. 状态栏里的词元数字上涨，`input` 一行比上一轮大，因为历史里多了刚才的工具结果。

任何一步卡住都能从卡片上看出来：某张卡片长时间停在 `queued`，说明它前面的调用还没结束，或者在等一张审批卡片；卡片红点说明这一步失败了，错误卡片里给出原因。参数不对时不必重新描述整个任务，接着说话即可，比如「月销售额那根曲线换成柱状图，x 轴标签写月份」。

挑错了列或者用错了数据集时，同样用一句话纠正，比开一个新会话从头说明省事：会话里的上下文还在，智能体知道自己刚才用的是哪一份数据、哪一个列名。改动落在哪个对象上，也可以在卡片参数里核对，比如 `create_chart` 的参数里写着 `data_name` 和两个列名。

## 提问卡片

智能体需要用户拿主意时会抛出一张提问卡片。卡片上是问题本身和一排可点的选项；需要从几个方向里选一个时是单选，需要多选时会标出来。选项下面有一个自由输入框，占位文字是「Type your own answer... / 输入自定义回答...」，答案不在选项里时在里面写一段，提交按钮是「Submit / 提交」。

提交之后答案回到智能体那里，它继续往下做。问题被撤回时，没有回答的卡片会从对话里消失。回答没有送出去时卡片上会给出一个重试提示，重新点一次提交即可。

## 长会话的分页

会话很长时，消息区分段加载：默认只渲染最近的一段，往顶部滚动会看到一个「Load earlier messages / 加载更早消息」的入口，点它再往前加载一段。每段按 150 条界面事件切分，滚动和搜索都不会因为历史太长而变慢，往前翻的内容和顺序与刚产生时一致。

入口只在这一段之前还有内容时出现。短会话看不到它，翻到最顶上就是第一条消息。分页只影响显示，不影响发给模型的上下文，也不影响记录文件。

## 错误卡片与重试

出错时对话里出现一张错误卡片，上面是一句人话描述，下面两个入口：「Details / 详细信息」展开原始错误，「Copy / 复制」把原文放进剪贴板，复制成功后按钮文字短暂变成「Copied / 已复制」。过长的原文在卡片里用「[truncated] / [已截断]」标出，展开详情能看到完整内容。

服务端偶发失败时软件会自己重试，重试期间对话里出现的重试提示会写明第几次、一共几次、等多久再试。重试的参数（次数、间隔、递增）在设置页里调。重试期间不要重复点发送，重复发送会排队，等到这一轮结束才轮到新的一句。

回复写到输出上限被硬截断时，软件会自己让模型接着上一句继续写，最多续两次，续写出来的文字与前面的部分接成一条消息，中间不会多出分隔标记。连续两次续写仍然被截断，这一轮就此结束，已经写出来的部分保留在对话里；要接着往下要，直接说「继续」即可。

错误卡片的文案按失败类型给出不同内容，常见类型和指向的问题列在[配置模型](model-config.md)的常见问题一节。

## 回复里的跳转链接

智能体的回复里可以带两种链接，点击后直接跳到对应的内容：

- `da-figure:` 链接跳到某个绘图。智能体画完图后通常会在回复里插入这样的链接，点一下把对应绘图标签页抬到前面。
- `da-data:` 链接打开某个数据集。点一下切到数据操作区并打开该数据集的表格视图。

这两类链接由随软件发布的工具插件通过系统提示词教给模型，模型只在有把握时才放。目标已经不在了时（绘图被关掉、数据集被移除），点击不会跳转，「Log / 消息」面板里出现一条未找到的提示，注明是哪一个名字没找到。

链接里的名字来自工具返回的结果。智能体建完图之后拿到的是绘图的标识和名字，数据集的名字来自数据管理面板里的实际名称，所以回复里链接指向的对象通常已经存在，不需要自己核对拼写。想确认某一轮都动过哪些对象，展开那一轮的工具调用卡片逐个看参数即可。

## 标签页标题与状态

标签页标题显示会话名，草稿状态显示「(untitled) / （未命名）」。会话名在第一条消息发出时自动生成：取这条消息第一行的前 20 个字符，超出部分省略，所以标题里看到的就是问题的开头几个字。自动生成的标题之后不会被改写；手动重命名过的会话保持手动起的名字。

标题旁边的状态图标和提示气泡给出四种状态：

| 状态 | 含义 |
|---|---|
| `Starting` / 启动中 | 这一轮已经发出，子进程正在启动 |
| `Running` / 运行中 | 正在生成回复或执行工具 |
| `Waiting for you` / 等待输入 | 有一张提问卡片或审批卡片等着回答 |
| `Error` / 出错 | 这一轮以错误结束 |

面板标题栏除了系统按钮，还有两个按钮：「New Session / 新建会话」和「Session Manager / 会话管理」，和 Ribbon 上的同名按钮是同一入口。

## 标签页右键菜单

在标签页上点右键有三项：

- 「Rename Session / 重命名会话」：弹出输入框，标题是「Rename Session」，字段标签是「Session name: / 会话名称：」，填新名字确认即可。
- 「Stop Session / 停止会话」：只对当前活动且正在运行的会话可用，作用与输入框旁边的 Stop 按钮相同。
- 「Delete Session / 删除会话」：先确认，内容是「Delete session \"%1\"? Its chat history will be removed. / 删除会话 \"%1\"？其聊天记录将被移除。」，确认之后磁盘上的记录一并删除。

## 停止一轮

停止正在跑的一轮有三条路：对话里的「Stop / 终止」按钮、标签页右键菜单的「Stop Session / 停止会话」、关闭标签页对话框里的「Stop Session and Close / 停止会话并关闭」。三条路都只停指定的那一个会话，别的会话不受影响。

停止时会一并撤掉这个会话里没有回答的提问卡片和没有处理的审批卡片，因为这两个卡片代表的动作已经没有执行者了。已经写进对话的内容保留：正在流式输出的那一段会就地收尾，成为一条完整的消息，不会出现半截消失的情况。接着往下说一句「继续」或者补一句新的要求，就能开新的一轮。

## 关闭会话标签页

点标签页上的关闭按钮时，软件先看这个会话在不在忙：

- 空闲或已经出错的会话直接关闭。记录留在磁盘上，可以从会话管理器重新打开。
- 正在运行或等待输入的会话弹出一个三选对话框，标题是「Close Session / 关闭会话」，提示是「Session \"%1\" is still running. What do you want to do?」（等待输入时换成「... is waiting for your input ...」），三个按钮：
  - 「Keep Running in Background / 后台继续运行」，默认项。标签页关掉，这一轮在后台继续跑，跑完的结果留在记录里，从会话管理器切回去就能看到。
  - 「Stop Session and Close / 停止会话并关闭」。先停掉这一轮，再关标签页。
  - 取消，什么都不做。

后台继续运行的会话仍然在消耗服务额度，也仍然会弹出需要回答的卡片，只是面板上看不到。要留意标题栏和会话管理器里的状态，或者直接用横幅把它们找出来。

关掉软件本身时，所有会话的子进程一起停掉，正在跑的那一轮不会继续跑完。已经写下的记录保留在磁盘上，下次打开软件可以从会话管理器切回这个会话，接着往下说。软件退出不会删除任何会话，删除只由标签页右键菜单和会话管理器里的删除按钮发起。

## 多个会话并行

面板里可以同时开着多个标签页，每个会话一个。多个会话可以一起运行，每个都有自己的子进程和 Python 运行空间，一个在等模型回复时另一个可以继续提问。

模型和权限模式是全局的，切换之后所有会话一起换，动作在各自下一轮生效。会话名、历史记录和词元计量各算各的，会话管理器里的累计用量是全部会话的和。

在后台运行的会话不需要有人盯着：它需要用户拿主意时会抛出提问卡片，标签页状态变成「Waiting for you / 等待输入」，切过去就能看到。切过去之前，这一轮一直停在那里等。

## 会话里保留什么

每条消息在产生时写进会话记录，一次写入一行，退出软件也不会丢。工具调用的参数和结果同样记进去，重新打开一个会话时，对话区按记录把消息、卡片和链接重新渲染出来，看起来和离开时一致。

发给模型的上下文和对话区看到的记录是两回事。对话越长，上下文越大；接近当前模型的窗口时，软件把早期内容压缩成摘要，给后面的内容腾位置，压缩的时机由配置里的压缩阈值决定。压缩不会删除对话记录里的内容，翻回上面的消息仍然看得到原文。

词元计量里的数字是这一轮实际用掉的量，`window` 一行给出当前模型的窗口大小。长任务里占用会一段段上涨，压缩之后回落。

## 会话管理器

会话管理器从 Ribbon「AI Agent / AI智能体」标签页的「Session Manager / 会话管理」按钮，或面板标题栏上的同名按钮打开。窗口标题是「Session Manager / 会话管理」，顶部提示「Double-click a session to switch: / 双击切换会话：」。

窗口顶部有一个复选框「Show sessions from all projects / 显示全部工程的会话」。这一项存在别的工程遗留的会话时，标签后面会带上「(N running in background)」的后缀，提示有几个还在后台运行。别的工程的会话不能切过去，切换按钮对它不可用；可以重命名、删除，也可以停止。

中间的表格四列：

| 列 | 内容 |
|---|---|
| `Title` / 标题 | 会话名，草稿显示「(untitled)」；别人的工程遗留的会话在名字后面附一个带工程名的方括号后缀，没有工程时写「no project」 |
| `State` / 状态 | 启动中、运行中、等待输入、出错四种，空闲的行留空 |
| `Messages` / 消息数 | 这个会话里已有的消息条数 |
| `Updated` / 更新时间 | 最后一次改动的时间 |

数字列按数值大小排序，当前会话所在的行整行加粗，默认按更新时间倒序排列，表头可以点，点一次换一种排序。

底部四个按钮：`Switch` / 切换（双击一行是同一件事）、`Rename` / 重命名、`Delete` / 删除、`Close` / 关闭。表格的右键菜单在四项之外多一个 `Stop` / 停止，只对运行中、启动中、等待输入的行可用。

右侧的详情区标题是「Session Details / 会话详情」，没有选中行时提示「Select a session to view details / 选中会话查看详情」。选中之后列出：`State`（空闲、启动中、运行中、等待输入、出错，带颜色）、`Messages`、`Input Tokens`、`Output Tokens`、`Total Tokens`、`Created`、`Updated`。

窗口最下面一行是汇总：「%1 sessions · %2 tokens total / 共 %1 个会话 · 累计 tokens %2」。重命名弹出的输入框字段提示是「New title: / 新标题：」；删除确认是「Delete session \"%1\"? This cannot be undone. / 删除会话 \"%1\"？此操作不可撤销。」。

## 会话存在哪里

会话记录放在应用数据目录下的 `sessions` 文件夹里（`DADir::getAppDataPath("sessions")`）。每个会话一个 `.jsonl` 文件，文件名是会话标识，一行一条记录；另外两个文件 `sessions_index.json` 和 `last_active.json`，前者是会话清单，后者记住上次用的那一个。

会话记录里带工程路径标记。在会话管理器里默认只列当前工程的会话，打开另一个工程之后，上一个工程的会话不再出现在列表里，勾上「Show sessions from all projects」才会看到，它们就是横幅提示的那一类。

保存工程时，属于这个工程的会话一起打包进工程文件：工程压缩包里有一个 `agent_sessions` 文件夹，里面每个会话一个文件。打开工程时会把这些会话导回来，带上工程路径标记，所以在另一台机器上打开同一个工程，对话记录跟着过来。打包有上限：数量上限取 `Max Sessions` 的值（默认 20 个），总体积上限 256 MB，超过时从最旧的开始剔除，当前会话始终保留。本地 `sessions` 文件夹里的记录不受这个上限影响，按 Agent 设置里的保留数量和天数清理，见[配置模型](model-config.md)。

## 会话能改动什么

对话过程中智能体通过工具改动项目里的东西：往数据管理面板里加数据集、在绘图区建图、改已有图表的样式、写文件、导出数据。这些改动的效果和手工操作一致，做完立刻反映在对应的面板里，见[内置工具](tools.md)。

每一次写文件或执行代码之前，软件会按权限设置决定是否先征求确认；被要求确认时对话里出现一张审批卡片，点批准才继续，见[权限控制](permission.md)。

隐藏「Agent Assistant / Agent 助手」面板不会停止会话：面板只是显示和隐藏，后台的会话照常运行，再点「Show Agent Area / Agent 助手」时原来打开的几个标签页还在。面板的显示状态随界面状态一起保存，下次打开软件时按上次的布局恢复，见[主界面](../getting-started/main-window.md)。

## 上一工程遗留的会话

打开一个工程时，如果上一次在这个软件里开着的会话属于另一个工程，并且还在后台跑着，面板顶部会出现一条横幅：「%1 session(s) from the previous project are still running in the background / %1 个上一工程的会话仍在后台运行」，提示文字是「Click to view and stop these sessions / 点击查看并停止这些会话」。点它打开会话管理器的全部工程视图，在那里可以停止或删除它们。

横幅只在确实有这类会话时出现，处理完之后消失。这类会话不会自动停，也不会因为打开了新工程而被打断；要清掉它们，用横幅进会话管理器逐个停止或删除。

## 常见问题

**关掉标签页之后，那一轮会停吗？**

只有选了「Stop Session and Close」才停。选「Keep Running in Background」的话，标签页消失，这一轮继续跑，跑完的回复和工具结果都记进这个会话的记录里，重新从会话管理器切回去就能看到。

**同一个问题在两个会话里各问一次，结果会互相影响吗？**

不会。两个会话的对话历史和 Python 运行空间都是各自一份，工具调用改的是同一份项目数据（比如都往数据管理面板里加数据集），但对话内容互不可见。

**在输入框里按回车没有反应，是坏了吗？**

按设计如此。输入框里的回车只是换行，发送统一用右边的按钮。多行任务描述可以放心分成几段写，不会中途被发出去半句。

**卡片上的按钮点了没反应。**

已经做过决定的提问卡片和审批卡片会禁用按钮，重复点击被忽略，卡片上会显示裁决结果。如果是卡片刚出现就点不动，多半是这一轮的连接已经结束（比如在另一个窗口点了停止），刷新会话的做法是从会话管理器切走再切回。

**在会话管理器里找不到刚才的会话。**

先看顶部「Show sessions from all projects」是否勾上。当前工程之外的会话默认不列出来；勾上之后会看到它们在标题后面带着工程名前缀，状态也可能显示为运行中。

**面板里能同时开几个会话？**

没有数量限制，开多少都行，每个会话一个子进程。磁盘上长期保留的数量另有参数控制，超过 `Max Sessions` 或旧于 `Session Retention Days` 的会话在软件启动时清理，上次活跃的那一个始终保留，见[配置模型](model-config.md)。

**第一条消息为什么比后面的慢？**

第一条消息要等智能体子进程起来，界面上先显示「Agent starting...」，就绪之后才开始生成。勾选了「Auto prestart on launch / 启动时自动预热」的话，这段等待挪到了软件启动阶段，第一条消息几乎没有额外停顿，设置见[配置模型](model-config.md)。

**能不能把两个会话的结论合在一起看？**

不能直接合并。会话之间的记录互不可见，要汇总就在一个会话里把两件事都问一遍，或者把一份的结论复制到另一份里接着问。想省掉这一步，用子智能体把两件事并行做完再让主智能体汇总，见[子智能体](subagent.md)。

**收到的回复比预期短很多。**

先看词元明细里的 `output` 是不是贴着模型的最大输出值。贴着上限时软件会自己续写两次，仍然不够就说一句「继续」，或者把模型的 `Max Output Tokens` 调大。如果 `output` 很小而回复本身看起来完整，那是模型自己决定说这么多，重新提问并写明要求更长的篇幅即可。
