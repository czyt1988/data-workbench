# 提示词库

提示词库放的是可重复使用的任务描述。一条提示词就是一个 Markdown 文件，正文写着要做的事；在 Ribbon 上选中它，点「Run Agent / 执行agent」，这段正文就作为一条用户消息发进当前会话，智能体照着它去执行。反复要做的分析写成一条提示词，比每次重新描述一遍省事，也更不容易漏掉步骤。

这一章讲提示词条目的存放方式、管理对话框的用法，以及怎么写一条能稳定跑出结果的提示词。

## 提示词条目是什么

一条提示词由两部分组成，都在磁盘上：

- 文件名就是条目标题。标题里的特殊字符会被替换成下划线，其余照写。所以文件叫 `月度销售概览.md`，条目就叫「月度销售概览」。
- 文件内容是提示词正文，纯 Markdown。正文里不支持元数据段，写什么就发什么。

条目按文件名排序显示。标题取文件名，内容取文件正文，界面上不另存一份副本，改条目就是改文件。

文件按 UTF-8 编码读取，正文里可以直接写中文。扩展名不是 `.md` 的文件被跳过，按 `*.md` 的规则匹配文件名。

新建条目时软件按标题生成文件名，标题里的 `\`、`/`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 九个字符替换成下划线，其余字符原样保留，包括中文和空格。所以标题是「月度销售概览」时，文件名就是 `月度销售概览.md`。

## 存在哪里

提示词文件放在软件可执行文件目录下的 `daAgent` 文件夹里，扩展名 `.md`。只扫描这一层，子文件夹里的文件不会被读进来。文件夹不存在时软件会自己建。

软件第一次启动时，如果这个文件夹里没有对应文件，会写入一条内置提示词「数据分析助手」。论文撰写插件启用时，还会写入一条「论文撰写助手」。两条都只在这个文件不存在时写入，不会覆盖改动过的内容。

这一点带来一个后果：手工删掉这两条之后，下一次启动软件或启用插件时，它们会被重新写回来。想停用内置条目而保留自己的修改，可以改标题或者改内容，也可以把文件移出这个文件夹。

这个文件夹可以整体备份。里面的文件是纯文本，随工程之外的配置一起拷到新机器上，条目照旧可用；与模型连接有关的信息不在这个文件夹里，见[配置模型](model-config.md)。

## 随软件发布的两条

「数据分析助手」是一条通用入口提示词。正文分三段：先列出手上可用的工具分组，接着给出工作流程，最后写输出规范。工作流程的大意是先看有哪些数据集、再看字段类型、取数做统计、需要时画图、用标注把关键点标出来、需要澄清时提问。输出规范要求用中文回复、引用数据和图表时给出数值和跳转链接、拿不准的假设要写明，不编造数据和工具。

「论文撰写助手」由论文撰写插件注册，正文是一条六阶段写作流程：数据理解、建模锁定、图表制作、文献大纲、写作、评审定稿。流程里带两道门禁：中间结果先打包锁定再往下走，需要用户拍板的地方用提问卡片等回答。这条提示词还配套两个文献工具，检索和核对 DOI 的用法见[内置工具](tools.md)。

两条都可以编辑。改过之后，软件的升级和插件的更新都不会覆盖改动过的文件；想拿到原始版本，把文件删掉再重启一次。

## 管理对话框

入口是 Ribbon「AI Agent / AI智能体」标签页上的「Agent Manager / agent管理」按钮，提示文字是「Manage agents: add, edit, delete prompts」。窗口标题是「Agent Manager / Agent 管理」，里面两个标签页，第一个是「Prompt Library / 提示词库」。

这一页是一张列表加三个按钮，底部一个「Close / 关闭」：

- `Add` / 添加：打开新增对话框。
- `Edit` / 修改：打开编辑对话框，反填选中条目的标题和正文。
- `Delete` / 删除：删除选中条目，先确认。

没有选中条目时编辑和删除不可用。保存和删除之后列表立即刷新，Ribbon 上的提示词画廊也跟着刷新。管理对话框是普通窗口，打开着它也能查看对话、运行别的条目；底部「Close / 关闭」只关窗口，不停止任何会话。

第二个标签页「Subagents」放子智能体定义，两个标签页共用一个窗口，用法见[子智能体](subagent.md)。

## 新建和编辑一条提示词

新增和编辑用同一个对话框，窗口标题分别是「New Agent / 新增 Agent」和「Edit Agent / 编辑 Agent」，两个字段：

| 字段 | 说明 |
|---|---|
| `Title:` / 标题： | 条目名称，占位文字「Enter agent title」。它同时决定文件名 |
| `Prompt content:` / 提示词内容： | 正文编辑器，带 Markdown 高亮，占位文字「Write prompt content here (Markdown supported)」。它就是要发送的提示词 |

正文编辑器用等宽字体，带 Markdown 高亮：标题、列表、代码块在编辑时就有颜色区分，写长条目时容易看清结构。编辑器窗口默认 640 乘 520，可以拉大。按钮是「Save / 保存」和「Cancel / 取消」，保存按钮始终可用，按下去才做校验。

正文留空时保存不被拦下，条目会出现在列表和画廊里，但运行它不会有任何反应，列表里也不加提示。写条目时正文至少要有一段话。

保存前做两条校验：

- 标题不能为空。空标题时弹出一个标题为「Tip / 提示」的提示框，内容是「Title cannot be empty / 标题不能为空」。
- 标题不能与已有条目重名。重名时提示内容是「An agent named \"%1\" already exists, please choose another title」，意思是同名条目已经存在，需要换一个标题。

保存失败时弹出「Tip」提示框，内容是「Save failed / 保存失败」，正文里的改动保留在编辑器里。编辑时改掉标题会连文件名一起改，旧文件被删除，正文不会丢。

## 删除一条提示词

选中条目点 `Delete`，先弹确认框，标题是「Confirm Delete / 确认删除」，内容是「Are you sure to delete agent \"%1\"?」，意思是确认是否删除这条提示词。确认之后文件从 `daAgent` 文件夹里删除，失败时提示「Delete failed / 删除失败」。

删除是直接删文件，没有回收站。内置的两条会在下次启动时重新写回来，自己新建的条目删掉就没了，需要重新写。

## 在 Ribbon 上运行

提示词在 Ribbon 上排成一个画廊，每条一项。鼠标停在某一项上时，提示气泡显示这条提示词的全文，排版按原文的换行展开，长条目也能在气泡里读完。

用法是先点选一条，再点旁边的「Run Agent / 执行agent」，提示文字是「Run AI analysis with the selected agent prompt」。没选条目就点运行时，弹出「Tip」提示框，英文内容是「Please select an agent in the gallery first」，中文界面对应显示为「先在 gallery 中选择一个 agent」。智能体模块不可用时弹出「Agent module is not ready / Agent 模块未就绪」。

运行的动作是把「Agent Assistant / Agent 助手」面板显示出来，再把这条提示词的正文作为一条用户消息发出去。当前没有打开会话时会先建一个，所以从 Ribbon 直接点运行也能跑起来。之后的事情与手工提问完全一样：消息出现在对话区，智能体开始回复，工具调用、审批卡片、错误卡片照常出现，见[会话与对话](session.md)。

模型没配好时运行，只会在会话里得到一条未配置提示，提示词正文已经落进记录，但不会启动对话，配置好之后再运行一次即可，见[配置模型](model-config.md)。

选中的条目在画廊刷新之后会尽量保留，改完标题再回到 Ribbon 上时，如果原来选的那条还在，选中状态跟着它走。换个意思运行另一条时重新点一下即可。

## 运行之后看什么

运行一条提示词之后，眼下要盯的位置和手工提问一样：对话区看智能体做到哪一步，工具调用卡片看它动了哪些数据和文件，状态栏看词元占用。提示词里要求出图、导出文件、写报告时，结果分别落在绘图管理面板、磁盘上的目标路径和查看器窗口里。

跑完之后往回改条目是常规做法：第一次运行暴露出来的问题，比如列名写错、步骤顺序不合适、产出要求没写清，改成新的正文再跑一次。改动只影响之后运行的结果，已经跑过的那一次记录留原样。

## 条目属于整台机器

提示词文件放在可执行文件目录下，属于这套安装，不属于某一个工程。打开任何工程，Ribbon 上的画廊内容都一样；工程文件里不含提示词，工程拷给别人时提示词不跟着走。

想把一条提示词带给同事，把 `daAgent` 文件夹里对应的 `.md` 文件拷过去即可，放到同样位置就能被扫描到。条目名是文件名，重名时后放进去的文件会覆盖前一个，拷贝前先确认目标目录里没有同名文件。

软件升级时 `daAgent` 文件夹原地保留，自己写的条目不受影响；内置的两条按「不存在才写入」的规则处理，改动过的版本留下来。

## 提示词正文就是用户消息

运行一条提示词，等同于把它的正文原样打进输入框再点发送。智能体不区分这是手工敲的还是从提示词库来的，也就没有额外的解析：正文里的 Markdown 标题、列表、数字编号都只是文本，靠内容本身指导模型怎么做。

因此提示词写得越具体，结果越稳定。一段含混的「帮我分析销售数据」会得到一次泛泛的问答；把数据集名字、要算的量、最终要什么形式的产出都写清楚，智能体就少绕弯路，也少来回确认。

发出去的那条消息在对话区里就是正文本身，标题行会按 Markdown 渲染成大一号的字，条目越长，气泡越高。回头看会话记录时，能从这条消息完整读出当时的任务是什么，这比只留一个条目名更好追溯。

## 怎么写一条好条目

一条能直接跑的条目通常包含五块内容：

1. 目标和对象：这一趟要回答什么问题，用哪个数据集。
2. 输入说明：数据集名字、关键列名、可能的替代名；名字不确定时给出查找办法。
3. 步骤：按顺序写清先做什么、再做什么，需要哪几步计算，需要出图时写明图的类型和横纵轴。
4. 工具偏好：指明用哪些工具，比如月度汇总用 `query_data`、出图用 `create_chart`、导出用 `save_chart_image`。智能体有二十多个工具可用，点名可以少走弯路。
5. 产出要求：最后要以什么形式收尾，结论里必须包含哪些数字，文件存到哪里，链接怎么给。

五块内容的顺序与执行顺序一致：说清目标和对象之后给输入，再给步骤，最后给产出要求。模型从上往下读，读到步骤时已经知道手上有哪些列可用，读到产出要求时已经知道前面算了什么，比把这些信息打散混写要稳。

反面写法是把这些留给模型自己猜：只写一句「看看数据有什么问题」，得到的结果随机性很大，换一个模型又变一次。

写的时候可以按下面的取舍过一遍：

| 值得写进去 | 不值得写进去 |
|---|---|
| 数据集名、列名、产出文件名 | 软件操作步骤，比如「点开数据管理面板」 |
| 每一步算什么、按什么顺序 | 模型的角色设定，比如「以资深分析师的口气写作」 |
| 用哪些工具、图的类型和轴 | 与本次任务无关的通用分析常识 |
| 结论必须包含哪些数字 | 要求它「尽可能全面」这类没有边界的描述 |
| 数据缺失或列名不符时的处理办法 | 排版、字号这类交给图表样式的细节 |

「尽可能全面」这类要求会把任务边界拉大，智能体为了覆盖更多方向，会多调几次工具、多花几轮推理，结论反而不聚焦。把要什么写死，比要求它多想更有效。

条目长度按任务的复杂度定。一条三十行上下的提示词通常能覆盖清楚一个固定任务；超过一百行之后，把其中可复用的部分拆成子智能体定义往往更合适，见[子智能体](subagent.md)。

## 一条完整示例

下面这条提示词做一次月度销售概览，含出图和导出图片。把它存成 `月度销售概览.md` 就能在 Ribbon 上运行。

```markdown
# 月度销售概览

## 目标

对数据集 `sales` 做一次月度销售概览，产出一张折线图和一段简短结论。

## 输入

- 数据集名：`sales`，包含 `date`（日期）、`region`（地区）、`amount`（金额）三列。
- 如果没有 `sales`，先用 `list_data` 列出全部数据集名，在结论里说明实际用的是哪一个。

## 步骤

1. 用 `get_data_info` 确认三列的类型，特别确认 `date` 是日期类型。
2. 用 `query_data` 抽样若干行，确认 `amount` 没有明显异常值。
3. 按月汇总 `amount` 的合计，用 `create_chart` 画折线图，横轴用 `date`、纵轴用月度合计，标题写「月度销售额」。
4. 找出合计最高和最低的月份，用 `add_annotation` 在这两个点上加文字标注，写清月份和数值。
5. 用 `save_chart_image` 把图导出到脚本工作区的 `output/monthly_sales.png`。

## 产出要求

- 回复开头给三行结论：全年总金额、最高月份、最低月份。
- 数值保留两位小数，写清单位。
- 回复末尾附上指向这张图的跳转链接。
- 数据集缺失或列名对不上时，直接说明缺什么，不要编造数值。
```

开头一段说清目标和对象：分析 `sales` 数据集，产出是一张图和一段结论。目标写得窄，智能体不会顺手多做别的事。

输入一节给出数据集名和三列的含义。三列名字都写出来，智能体不必先猜再问；末尾那句「没有 `sales` 时先列出全部数据集并在结论里说明用的是哪一个」给出了一条备用路径，数据改名之后这一趟不会直接失败，它会照实说明缺什么。

步骤一节把计算顺序固定下来，从确认类型、抽样、汇总、画图到标注、导出，每一步点名了使用的工具。`create_chart` 那一步写明图表类型、横轴和纵轴用哪一列，避免它把日期放到纵轴；`add_annotation` 那一步要求标注里写月份和数值，这样图上的标注不用回头再对一遍；导出那一步给出明确的工作区相对路径，智能体不需要回头确认存到哪里。

产出要求一节规定结论的格式、数值精度、单位、链接和缺失数据的处理办法。三行结论放在开头，读结果时第一眼就能看到关键数字；「不要编造数值」这一句能挡掉一部分凭空出现的数字，数据集列名对不上时它更可能如实说明。

把这条提示词存进库之后，换一份列名相同的月度销售数据，只要改输入一节里的数据集名，其余部分可以照用。列名不同时，改输入和步骤里出现的列名，产出要求不用动。

同一种结构可以套在别的任务上。做一份「数据质量体检」时，目标一节写「对数据集 `orders` 做一次质量检查」，输入一节列出关键列和业务上不允许为空的字段，步骤一节写「按顺序检查缺失值、重复行、数值列的取值范围」，产出要求一节规定「每条发现必须给出列名、影响的行数和一句话建议，没有问题的检查项也列出来并写通过」。结构不变，换的是内容。

运行这条示例时，界面上大致会出现这些内容：一句确认数据集存在的说明，几次数据相关的工具调用，一次 `create_chart`，若干次标注相关调用，一次导出图片，最后是三行结论加一个绘图链接。所有数据名称与实际不符的情况都会在第一次工具调用之后暴露出来，改正文里的名字再跑一次即可。

## 提示词的边界

提示词库没有参数机制，也没有条件分支。一段正文每次原样发送，不会替换变量，也不能按运行时的数据自动选步骤。需要按数据集不同而变化的写法有两种：一种是把可能的名字都写进「输入」一节，让智能体自己找；另一种是复制一条新的、改好名字另存。

正文每次都进上下文，长度直接算进词元。一条三十行的提示词大约占几百到一两千词元，跑十轮下来也是重复占用的；把显而易见的常识写进去只会让每轮都多花一点。反复用到的大块说明，放到子智能体定义里由主智能体按需派发，可以省下重复的部分，见[子智能体](subagent.md)。

提示词能约束流程，不能约束结果的数据内容。它要求「不要编造」时，模型会更谨慎，但最终的数值仍然来自工具返回；核对结论的办法是展开工具调用卡片，看数字是从哪一次调用里出来的。

## 与子智能体的区别

提示词条目是用户自己运行的：选中、点执行，正文变成用户消息，主智能体按它工作。子智能体是主智能体在干活过程中自己决定派发的：定义放在另一个文件夹，带名字、描述和工具白名单，主智能体看到的是「有一个叫某名字的子智能体，负责某件事」，需要拆并行任务时才会用上，见[子智能体](subagent.md)。

两者可以配合：提示词正文里写上「需要并行调研时，派发给 `explore` 子智能体」，等于把派发的时机交代给主智能体，比等它自己想起来更稳。子智能体的名字写在定义文件的 `name` 字段里，引用时必须与它一致；写错名字时主智能体收到的可用清单里没有这一项，这句话就不起作用，也不会报错。

一段任务里既有固定流程又有可并行的部分时，把固定流程写进提示词，把可并行的部分交给子智能体，是这两种机制配合的常规用法。

## 常见问题

**改完提示词，Ribbon 上的气泡没变。**

画廊在保存之后会刷新，如果看上去还是旧的，关掉管理对话框再打开一次。气泡里的内容来自文件正文，直接改 `daAgent` 文件夹里的文件也能生效，改动在下次载入时读到。

**新建的条目没有出现在画廊里。**

确认文件落在可执行文件目录下的 `daAgent` 文件夹顶层，扩展名是 `.md`。子文件夹里的文件不会被扫描。

**同一条提示词连跑两次，为什么要点两次运行？**

每次点运行都是把正文作为一条新的用户消息发出去，两次运行的记录都留在同一个会话里，第二次的上下文里带着第一次的过程。想从干净状态开始，先新建一个会话再运行。

**条目能自动挑数据集吗？**

不能按名字自动替换。数据集名写在正文里，换数据时要么改正文，要么把可能的名字都列进输入一节。智能体在正文允许的范围内可以先用 `list_data` 看有哪些数据集，再选一个匹配的，前提是正文里给了这条路径。

**正文里的 Markdown 格式有什么讲究？**

只有可读性上的讲究。标题、列表、编号都是纯文本，渲染在界面上更清楚，模型读起来也更容易分段。加粗、表格、代码块同样按文本处理，不会触发额外解析。

**删除条目会影响已经跑过的会话吗？**

不影响。会话记录里存的是当时发出去的消息和后续产生的内容，条目文件删掉之后历史照常查看，只是没法再运行和编辑这一条。

**运行一次之后想调整要求，是改条目还是接着对话说？**

小调整直接接着对话说，一句话就能纠正，会话里的上文还在。同样的调整如果每次都出现，说明条目该改：把要求补进正文，下一次运行就带上，不用每条会话重复交代。

**能直接编辑 `daAgent` 文件夹里的文件吗？**

可以。文件就是数据源，用文本编辑器改完保存，管理对话框和 Ribbon 画廊在下次载入时读到新内容。改文件名等于改标题，注意别与已有条目同名。

**条目和子智能体能不能共用一个文件？**

不能。两者放在不同文件夹，格式也不同：条目是一整段提示词正文，子智能体定义带名称、描述和工具白名单。名字取得一样也不会互相引用，它们各自独立，见[子智能体](subagent.md)。

**停用论文撰写插件之后，「论文撰写助手」还在画廊里。**

插件只在文件缺失时写入，停用插件不会删掉已经写入的文件，所以条目继续留在画廊里，配套的两个文献工具会随插件一起消失，运行时正文里提到的检索步骤会失败。不再需要这条提示词时，从管理对话框里删掉它；下次启用插件时它会被重新写回来。

画廊最宽 700 像素，条目多了以后一屏放不下，展开画廊可以看全，鼠标停在某一项上仍按该项显示全文。
