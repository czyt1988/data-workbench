# 复制与保存图表

画好的图要离开软件，只有有限的几条路：复制到剪贴板，或者让智能体把图表存成文件。这一章讲这几条路各自给出什么，以及图表在工程文件里到底存了什么，顺便说明为什么把源数据集删掉之后图还在。

## 复制到剪贴板

绘图操作上下文标签的「Chart Style」/ 图表样式 页里，「Figure Theme」/ 主题 面板上有一个「Copy To Clipboard」/ 复制到剪切板 按钮，复制的对象是当前绘图。

复制走的是一条最短的路径：软件把当前画布按屏幕上的显示尺寸截成一张位图，放进系统剪贴板。没有分辨率对话框，没有尺寸对话框，也没有格式选择。

用这个动作时有两件事值得知道：

- 拷进去是位图。粘到文档、演示文稿或者图片编辑器里得到的是一张光栅图片，放大会糊，不能像矢量图那样无损缩放。
- 像素数等于画布此刻在屏幕上的像素数。停靠区拉大、绘图窗口拉大之后画布会按新尺寸重画，再复制一次就得到更多像素；反过来，绘图标签页被别的标签挡住或者停在后台、窗口被缩小时复制，拿到的就少。想给文档配一张看得清的图，先把绘图标签页切到前面、把停靠区拉到合适的宽度，再复制。

### 复制之前值得确认的几件事

复制拿到的是当前画面的样子，和属性面板里的设定不一定一致。下面几项只在当前画面上生效，复制前先看一眼：

- 当前缩放范围。缩放过再复制，拷下来的是放大后的那一块。
- 隐藏的图元。用图例或者绘图管理树隐藏过的曲线不会出现在位图里。
- 图例的位置和内容。图例按当前设置绘制，位置改过就以改过的为准。
- 主题和字号。两者都随画面生效，屏幕上是什么样，拷下来就是什么样。

剪贴板里的内容是系统级的，粘到别的程序里即可，软件这边不需要另存一次。

主页 Ribbon 的「Clipboard」/ 剪切板 面板里的「Copy」/ 复制 是同一个动作的第二个入口，但它按焦点决定复制什么：焦点在表格视图上时复制选中的单元格，在工作流画布上时复制选中的节点，在绘图区上时复制绘图。绘图区是最后一次操作的区域时，这个按钮的作用和「Copy To Clipboard」/ 复制到剪切板 完全一样。

## 没有导出成图片或者矢量文件的功能

软件当前没有把一幅绘图导出成图片文件或者矢量文件的界面入口。绘图相关的菜单、按钮和「Charts Manager」/ 绘图管理 面板里都找不到「导出图片」「另存为图片」这类命令，也没有输出 PDF、SVG 或者 EMF 的菜单项。绘图本身也没有按厘米或英寸设定物理尺寸的地方，能调的只有绘图的宽高上下限和坐标系的位置比例。文件输出只能借智能体的 `save_chart_image` 工具完成，见下一节。

要用到图片文件时，可行的办法是下面三条。

### 先复制到剪贴板，再在别的程序里保存

复制之后粘到画图、Word、PowerPoint 或者任意图片编辑器，在那里存成文件。得到的像素数就是复制那一刻画布在屏幕上的像素数。这条路最快，分辨率受屏幕限制。

### 让智能体把图表保存成文件

智能体有一个 `save_chart_image` 工具，把指定的图表渲染成 PNG、PDF 或 SVG 文件。这是软件里唯一一条能把图表输出成文件的路，也是唯一一条能拿到矢量图的路。

用法是在对话里描述要保存哪一块、存到哪里、要什么格式。比如「把当前绘图里的第一个坐标系存成 `D:\figures\curve.pdf`，宽 800 高 600」。工具接受五个参数：

| 参数 | 含义 | 说明 |
|---|---|---|
| `chart_id` | 图表标识 | 留空或者填 `current` 表示当前活动的坐标系 |
| `figure_name` | 绘图名称 | 指定要操作哪个绘图，留空表示当前活动绘图 |
| `file_path` | 输出文件路径 | 必填 |
| `format` | 输出格式 | `png`、`pdf`、`svg`，默认 `png` |
| `width`、`height` | 输出尺寸 | PNG 按像素，PDF 和 SVG 按点；两个都要填才生效 |

三种格式的输出方式不一样，选格式前先明白差别。PDF 和 SVG 走的是绘制路径：软件把坐标系按给定尺寸重新画一遍到矢量设备上，轴、文字、曲线都是矢量元素，放大不会糊，尺寸也按给定的点值来，适合放进论文或排版文件。PNG 走的是截图路径：软件按画布此刻的屏幕样子抓一张位图，给了宽高就按比例缩放到那个尺寸，缩放是平滑插值而不是重新渲染，所以放大之后仍然会有位图的模糊。需要大尺寸的位图时，先在界面上把停靠区拉宽、让画布按更大的尺寸重画一次，再让智能体保存。

尺寸留空时，PDF 和 SVG 按坐标系当前的屏幕尺寸出图，PNG 直接就是屏幕尺寸。

这件事也可以让智能体写在报告里一起完成：`save_report` 工具可以把 Markdown 报告存成 md、html、pdf 或 docx，然后在查看器里打开。两个工具的完整说明和权限要求见[内置工具](../agent/tools.md)。

### 用工作流画布的 PNG 导出

Ribbon 的工作流页面里有导出 PNG 的动作，它弹出「Export PNG」/ 导出PNG 对话框，点保存前可以选择 DPI 档位：「custom」/ 自定义、「screen」/ 屏幕、「print」/ 打印，另有「DPI」数字框可以填具体数值，导出的文件过滤器是 `*.png`。

这个对话框只作用于工作流画布，画的是工作流那张节点图，绘图标签页里的图表用不上它。工作流画布的视图、背景和导出见[编辑器功能](../workflow/editor.md)。

### 三条路的对照

| 做法 | 得到什么 | 适合 |
|---|---|---|
| 复制到剪贴板 | 屏幕尺寸的位图 | 随手贴进文档、邮件、聊天 |
| 智能体保存图表 | PNG、PDF 或 SVG 文件，尺寸可选 | 要交付的成品图，尤其是要矢量图的场合 |
| 工作流画布导出 PNG | 带 DPI 选择的 PNG 文件 | 导出工作流那张节点图 |

## 图表在工程里的位置

图表是工程的一部分，不单独存成文件。一个工程里除了图表，还有数据管理面板里的数据集、工作流画布和节点参数、表格样式、脚本工作区的内容，以及界面布局。图表相关的部分占 `charts.xml` 和 `chart-data/` 两块，其余内容的组织方式见[工程文件](../getting-started/project.md)。

由此带来两个使用上的习惯：

- 想保留一张图，保存工程即可，不用把图单独存成文件。把工程拷到另一台机器，图表跟着过去，数据是否也跟着过去取决于保存时数据管理面板里有什么。
- 想把图交给别人看，工程文件偏大，里面还有数据和工作流。只交一张图更常用剪贴板，或者让智能体把图存成图片文件。

## 一个例子：把一张图放进文档

下面按顺序走一遍把图放进文档的完整流程，从摆好图到确认清晰度。

1. 先把图画完、把坐标系摆好。放文档里的图通常只要一块坐标系，位置比例调成上下留白小一些的矩形，横向拉宽。
2. 调字号和线宽。文档里图会被缩到一栏宽，轴标题、刻度数字、图例文字要比按屏幕判断的大小再大一号。这些设置在图元和坐标轴面板里逐个改，见[二维图表设置](./settings-2d.md)。
3. 选一个配色主题。主题是绘图级的，一次改全部图元的颜色，选择见[绘图与坐标系](./figure.md)。
4. 把绘图标签页切到前面，把停靠区拉到准备发表时的宽度。复制取的是屏幕尺寸的位图，这一步决定分辨率。
5. 点「Copy To Clipboard」/ 复制到剪切板，到文档里粘贴。
6. 贴在文档里缩放到最终宽度，看文字是否还认得清、线是否还分得开。屏幕按每英寸 96 点上下显示，打印输出的点密度高得多，同一张位图放到纸上像素会显得更粗，缩到一栏宽之后发虚就换下一条路。
7. 需要更高清晰度或者要交排版的图，改用矢量格式：让智能体把这块坐标系存成 PDF 或 SVG，尺寸按栏宽换算成点值填进去。矢量文件放大不会糊，插入排版软件后还能继续调字号。两条路的分工见前面的对照表。

## 把图交给别人

交给别人的方式决定了对方拿到什么，按需要挑一种。

| 方式 | 对方拿到 | 对方需要 |
|---|---|---|
| 工程文件 | 图、数据、工作流和全部设置 | 装上同一份软件，打开工程 |
| 智能体存出的图片文件 | PNG、PDF 或 SVG 文件，尺寸可选 | 任何能看图片或 PDF 的程序，不需要软件 |
| 剪贴板里的图片 | 一张屏幕尺寸的位图 | 任何能看图片的程序 |

工程文件是唯一能把图连同全部参数还原给对方的形式。它的代价是体积大、里面有数据和工作流，而且对方必须装软件。只想让对方看到结果，用图片更省事。

从工程里单独抽出图表需要自己动手：图表在工程压缩包里分成 XML 和二进制两块，只复制其中一半还原不了图。确实需要单独传图表时，把工程另存为一份副本，在副本里删掉不需要的数据集和其他绘图，再传这一份。

## 图上数据的三个出口

图存的是采样点，界面上不提供把图导回数据集的动作。要把数值带走，按用途选下面三种。

| 出口 | 拿到什么 | 适合 |
|---|---|---|
| 数据探针加数据联动表 | 指定横坐标位置上各条曲线的取值，表格形式 | 快速核对几个位置的数值，只看不改 |
| 导出数据集 | 原始数据表的内容，CSV、Excel 等文件 | 需要完整的数值，后续在别的工具里算 |
| 脚本工作区 | 内存里的数据框，以及自己算出来的结果 | 需要重新计算、重新出图 |

三条路都不经过图元本身，读的都是原始数据或者自己重算的结果。图上重采样、插值之后的数字拿不到，见[交互与取值](./interaction.md)里界面上取不出图上的数值那一节。

## 三维图表的保存

三维图元有自己的存储格式，除了采样点还带上视角的旋转、平移和缩放，以及投影和纵横比的设置。工程存下来之后重新打开，三维图的观察角度和关闭时一致，不需要重新转到那个角度。

三维图元的样式参数，比如曲面的绘制方式、色图、等值线条数，柱体的柱宽和柱深，线图的线型和点形状，也都在工程里。这些数据的格式带版本号，读取时按版本判断哪些字段存在，因此早先保存的工程在新版本里仍然打得开，缺的字段用默认值补齐。

三维图表在工程里同样按绘图归属，绘图停了靠布局恢复，坐标系和图元按比例和编号恢复。

## 图表和其他内容一起保存

保存工程时软件按固定顺序生成一批内容，图表只是其中一项。顺序和内容大致如下，知道这些有助于判断某个东西是不是跟着工程走。

| 顺序 | 内容 |
|---|---|
| 1 | 系统信息，只写不读 |
| 2 | 工作流的节点拓扑、参数值和连接关系 |
| 3 | 工作流画布的界面信息 |
| 4 | 数据管理面板里的数据集 |
| 5 | 表格样式 |
| 6 | 数据操作窗口的标签页和布局 |
| 7 | 图表信息与图元数据 |
| 8 | 智能体会话记录 |
| 9 | 脚本工作区 |
| 10 | 各插件自带的数据 |

图表排在第 7 位，在数据之后。也就是说工程里的数据集先落盘，图表随后写自己的采样点拷贝，两者互不引用。

## 图表在工程里怎么保存

工程是一个压缩包，图表分别落在两类内容里。

一部分是界面结构。所有绘图的名称、坐标系在绘图里的位置比例、坐标系里的坐标轴和标题、每个图元的类型和各项参数，都序列化成一份 XML，文件名是 `charts.xml`。XML 里记录的是结构参数和图元的编号，不包含曲线上的具体数值。

另一部分是图元的采样数据。每个图元的采样点单独以二进制块写进工程的 `chart-data/` 目录，另有一份 `chart-items.xml` 把每个编号对应的图元类型登记下来。两部分靠编号对上：读取工程时先按登记表把图元连同数据一起重建出来，再读 XML 把图元挂回各自的坐标系。

三维图元有自己的二进制格式，除了数据还带上视角的旋转、平移、缩放和纵横比，所以工程存下来之后重新打开，三维图的观察角度和关闭时一致。

### 保存时发生什么

保存工程的动作把图表拆成两项任务执行：

| 任务 | 做什么 |
|---|---|
| 保存绘图的基本信息 | 把绘图的名称和组织形式收集成 XML，这一项必须在主线程完成，因为界面对象不能带到别的线程里碰 |
| 保存绘图元素的基本信息 | 把每个图元的采样点写成二进制块，这一项由压缩包任务在后台线程里写 |

界面的部分先整理完，数据的部分随后写盘，因此工程里图表很多、曲线很长时，保存的最后一段时间花在第二个任务上。

### 存下来的参数

图表不只有数据，设置也在里面。下面按层次列出工程会保留的内容。

| 层次 | 随工程保存的内容 |
|---|---|
| 绘图 | 名称、配色主题 |
| 坐标系 | 在绘图里的位置比例、是否显示、标题和脚注的文字与格式、画布背景和边框、四条坐标轴各自的启用状态、当前范围、刻度方向和样式、刻度字体与标题 |
| 数据拾取器 | 拾取模式、是否显示 X 值、文字位置、插值方式、是否画特征点、特征点大小、搜索窗口大小、文字偏移和背景画刷 |
| 图元 | 类型、各项样式参数、标题，以及采样数据 |
| 停靠布局 | 绘图标签页的拆分、顺序和位置 |

坐标轴的当前范围也在其中，因此缩放之后的视野会跟着工程一起存下来。关掉工程再打开，看到的是关闭时的范围，软件不会按数据重新算一遍。

### 两类布局分别由谁负责

界面上的布局分两层，保存的地方也不一样：

- 外层是各停靠面板的位置，比如数据管理面板在左、属性面板在右、绘图操作区在中间。这一层由界面状态的保存与恢复负责，跟着窗口走，见[工程文件](../getting-started/project.md)。
- 内层是绘图操作区里标签页的拆分和顺序。这一层嵌在外层里面，外层的保存不覆盖它，它随工程文件里的图表布局节点一起存取。

因此发现「面板位置恢复了但绘图标签的顺序不对」，或者反过来，都属于正常，两层各管一段。

### 工程里和图表有关的文件

图表相关的内容在工程压缩包里占下面几项，排查问题时按名字找。

| 名字 | 内容 |
|---|---|
| `charts.xml` | 绘图的名称、坐标系的位置比例、坐标轴和标题、图元的编号，以及绘图停靠布局的编码 |
| `chart-data/chart-items.xml` | 图元编号和类型的登记表 |
| `chart-data/` 下的图元二进制块 | 每个图元的采样点数据，三维图元还带视角的旋转和纵横比 |

XML 里只放编号，采样点一律走二进制块。这个分工让采样点的写入可以放到后台线程完成，同时 XML 保持纯文本，便于出问题时直接打开看结构。

### 图和数据是分开的

数据写成二进制块意味着图上画的是它自己的采样点拷贝，和数据管理面板里那份数据集彼此独立。由此产生几个直接可见的后果：

- 工程保存后把源数据集删掉，图照样在，重新打开工程仍然显示原来的形状。
- 源数据集改数值、改列名，已画出来的图不会跟着变。想让图反映新数据，重新走一遍建图向导。
- 工程换一台机器打开，图不依赖任何外部数据文件。

拷贝是按图元算的。同一列数据画在三块坐标系上，工程里存的是三份采样点，不是一个共享的引用；反过来，绘图管理树里删掉一个图元，保存之后它的那份数据也从工程里消失，工程文件相应变小。图表多、曲线长时这一点直接反映在工程文件的大小上。

### 绘图停靠布局单独保存

绘图标签页怎么拆分、怎么排序、哪几个并排在一起，属于停靠布局，不写在图元数据里。这部分内容也放在 `charts.xml` 里，用一个单独的节点保存，内容是停靠布局状态的编码。重新打开工程时，软件先按 XML 建出所有绘图，再按每个绘图的编号把布局恢复上去，标签页回到关闭时的位置和先后顺序。

### 重新打开工程时

加载的顺序和保存相反：先把图元的采样数据读回内存并登记，再读 XML 把结构和参数还原，最后恢复停靠布局。因此图表在工程一打开时就是完整的样子，不需要逐个刷新。

有三件事在换机器或者换窗口尺寸之后看起来会变：

- 坐标系的位置按比例存，恢复时按当前窗口的尺寸换算像素位置。窗口比保存时窄，四块小图看起来会挤在一起或者更小，比例本身没有变，把窗口调回接近的尺寸就恢复原样。
- 绘图标签页的编号和名称会还原，但如果布局节点读不出来，标签页会按默认顺序以标签形式排开，位置关系丢失。
- 图上的数据是采样点的拷贝，和数据管理面板里的数据集没有对应关系，面板是空的也可能图上什么都有。

### 数据联动表会自己重建

数据联动表的内容来自图上的数据探针，探针本身作为图元随图表一起序列化。工程加载完成、每个绘图重建出来之后，联动表按这个绘图里的探针重建自己的列，不需要手工点刷新，也没有需要重新建一遍的步骤。关掉工程再打开，之前建的探针和它在表里的列都还在。

数据联动表是只读视图，见[数据探针与数据联动表](./data-probe.md)。

## 一次保存与恢复的核对

图表在工程里的存取涉及好几块内容，做完一个阶段的图之后按下面的顺序核对一遍，能早点发现哪一块没存上。

1. 把图摆好、参数调完，然后保存工程。
2. 关掉工程再重新打开。图还在、位置还对，说明结构、位置比例和图元的采样数据都存上了。
3. 看坐标轴范围。关掉工程之前如果是放大状态，重新打开应该还是那个范围，没有自动回到全览。
4. 看数据管理面板。面板里的数据集可能已经没了，图上仍然有内容，说明图存的是采样点。
5. 看数据联动表。如果图上有数据探针，联动表应该已经有对应的列，不需要手工刷新。
6. 看绘图标签页。拆分成两块停靠区的绘图应该还是拆分的，标签顺序不变。
7. 换一台机器或者换一个窗口尺寸再打开一次。坐标系按比例恢复，窗口尺寸不同时布局的像素位置会变，比例不变。

哪一步对不上，就能定位到对应的那一块内容：第 2 步对不上说明采样数据没写进工程，第 3 步对不上说明坐标轴参数没存，第 5 步对不上说明探针没有跟着图元走。

## 常见问题

复制出来的图粘到文档里很糊。复制走的是屏幕尺寸的位图。把绘图标签页切到前面、把停靠区拉大，等画布重画完再复制；需要更大尺寸或者要放进排版文件的图，让智能体把这块坐标系存成 PDF 或 SVG。

点「Copy」/ 复制 之后粘贴出来是别的东西。主页剪切板的「Copy」/ 复制 按当前焦点决定复制什么，焦点在表格视图或者工作流上时复制的是单元格或节点。先在绘图区点一下，让绘图区成为最后操作的区域，或者直接用「Copy To Clipboard」/ 复制到剪切板。

打开别人发来的工程，图都在但数据管理面板是空的。这是正常状态。图存的是采样点，数据集要单独导入，见[导入数据](../data/import.md)。

想改图上的数值。图上画的是采样点，界面不提供编辑点上数值的功能。改数据要到表格视图或者数据清洗里改源数据集，再重新建图。

想拿到图上某个位置的读数。在图上用数据探针取值，读数进入数据联动表查看，见[数据探针与数据联动表](./data-probe.md)；也可以从源数据集导出后自己算，见[导出数据](../data/export.md)。

工程文件里多了一堆图，想删掉几张。图在工程里的单位是绘图，删一个绘图就把它里面的坐标系和全部图元一起去掉，删完保存一次工程才会变小。只删某几条曲线时用绘图管理树的「Delete」/ 删除，删完同样要保存。

同一列数据画了四张图，工程文件比预期大。图上的采样点按图元各存一份，四张图就有四份拷贝。不需要的小图删掉，工程会相应变小。

换了一台屏幕尺寸不同的机器打开工程，四块小图的间距看起来不对。坐标系的位置按比例恢复，像素位置随窗口尺寸换算。把窗口调到和保存时接近的尺寸，或者用「Resize Chart」/ 绘图尺寸 重新摆一次。

关掉工程之前忘了保存，最近摆好的位置没留下来。图随工程一起写盘，只有保存动作执行过才会落到文件里。自动保存的间隔在设置里，见[设置项说明](../reference/settings.md)。

想导出矢量图。界面上没有这个入口。让智能体把图表存成 PDF 或 SVG 即可，这两个格式是矢量输出；软件自身存进工程的内容不包含矢量输出路径。

复制出来的图和预期的不一样。复制的是当前画面，屏幕上隐藏的图元、当前的缩放范围、图例的位置都会一起带进去。先把画面整理成要交付的样子再复制。

工程文件越存越大。图表多、曲线长、同一列数据在多张图上重复出现，都会让采样数据的份数增加。删掉用不到的绘图图元，再保存一次，文件会跟着变小。

复制出来的图上带了一条读数框或一根标记线。复制截的是当前画面，临时出现的读数和十字线、以及自己画上去的标记都会一起进去。复制前先把鼠标移出画布、把不需要的标记隐藏或删掉。

工程里的图在，但数据管理面板里的数据集改了名。图和数据集各存各的，改名不会让图消失，也不会让图跟着变成新数据。图的名字里存的是建图当时的列名。

在脚本里调 `da_pyplot` 的 `savefig` 没有写出文件。这条路当前走不通。`savefig` 需要一个带整块绘图画布的对象，而 `da_pyplot.gca()` 给出的是单个坐标系形式的对象，调用时返回假值，日志文件里留下 `QwtPyPlot::savefig: no figure available for saving`。脚本里要出图片文件，改用智能体的 `save_chart_image` 工具，它按坐标系控件渲染，PNG、PDF、SVG 都能出。

想在别的软件里重新画同一张图。图上只有采样点，想让别的软件画出同样的图，需要把原始数据导出成文件再导入那个软件，见[导出数据](../data/export.md)。

工程里删掉的绘图能找回来吗。不能。绘图关闭之后撤销栈和它的图元一起消失，工程保存之后也没法从文件里取出单个绘图。删之前先另存一份工程副本。

工程文件打不开或者提示损坏。图表数据写在工程的 `chart-data/` 目录里，保存过程被打断时工程可能不完整。从备份或者上一版工程继续，别在损坏的文件上反复保存。

想把工程里的图转到另一台机器上接着调。拷工程文件即可，图、参数、布局都跟着走，数据也在里面。对方需要装上同一份软件，插件相关的内容需要对方也装了对应的插件。

复制之前想确认复制的是哪一块。复制取的是当前绘图，它里面的所有坐标系会一起进剪贴板。只想要其中一块，先把它单独放进一个绘图标签页再复制。

切到别的标签页再切回来，画面看起来变了。绘图窗口尺寸变化之后画布会按新尺寸重画，停靠区的宽度不同，画布的比例和之前不一样。要交给别人的图，把停靠区调到目标宽度再复制。

工程里同时有多个绘图，只想留其中一个。把不用的绘图标签页逐个关闭，关闭时确认框里选是，保存一次工程即可。留下绘图里的坐标系和图元不受影响。

保存之后想把图从工程里单独取出来给同事。工程里的图表分成结构 XML 和二进制数据两部分，缺任何一半都还原不了，需要单独传时用图片，或者另存一份只留这一张图的工程副本。
