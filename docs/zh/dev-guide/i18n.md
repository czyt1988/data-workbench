# 国际化（i18n）规范

data-workbench 项目统一采用**英文源文本 + 行内中文注释**的国际化模式。本文档定义 C++/Qt 和 Python 的 i18n 实施标准。

> **强制规则**：所有显示到用户界面的字符串必须使用英文源文本，翻译通过 `.ts`（C++/Qt）或 `.po`（Python/gettext）文件提供。源码中**禁止**直接写中文作为 UI 显示文本。

---

## 源文本方向

项目统一采用**英文源文本 + 行内中文注释**的模式：

| 语言 | 代码写法 | 翻译文件 |
|------|---------|---------|
| C++ (Qt) | `tr("English text")  //cn:中文文本` | `.ts` → `.qm` |
| Python | `_("English text")  # cn:中文文本` | `.po` → `.mo` |

**❌ 错误写法**（源码直接写中文）：

```cpp
// C++ — 禁止
label->setText("数据分析");
label->setText(tr("数据分析"));  // 即使加 tr 也禁止，源文本必须是英文
```

```python
# Python — 禁止
label.setText("数据分析")
print(_("数据分析"))
```

**✅ 正确写法**：

```cpp
// C++
label->setText(tr("Data Analysis"));  //cn:数据分析
```

```python
# Python
label.setText(_("Data Analysis"))  # cn:数据分析
```

## C++ / Qt i18n 规则

1. **UI 文本必须用 `tr()` 包裹**：按钮文本、菜单项、工具提示、对话框标题、撤销命令名、状态栏消息等
2. **非 QObject 子类用显式上下文**：`QCoreApplication::translate("ClassName", "English")  //cn:中文`
3. **日志消息不翻译**：`daInfo` / `daWarning` / `daCritical` / `qWarning` 等日志输出保持纯英文，便于跨语言环境检索
4. **序列化键名不翻译**：XML/JSON 键名、配置键名保持英文
5. **`retranslate()` / `retranslateUi()`**：插件和 UI 类应实现此方法，集中更新所有 UI 文本

### C++ retranslate 标杆实现

参考 `plugins/DataAnalysis/DataAnalysisUI.cpp::retranslateUi()`（第 136-205 行），集中翻译所有 Ribbon Panel 的 Action 文本和工具提示。

## Python i18n 规则

1. **使用 GNU gettext**：`_("English")  # cn:中文` 模式，详见 [python-i18n.md](./python-i18n.md)
2. **`setup_i18n()` 在包 `__init__.py` 顶部调用**：在导入业务模块之前调用，确保 `_()` 可用
3. **i18n 目录结构**：每个 Python 包维护自己的 `i18n/` 子模块（`core.py` + `locale/{lang}/LC_MESSAGES/{DOMAIN}.{po,mo}`）
4. **DOMAIN 用包名**：如 `DADataAnalysisGui`、`DASystemNodes`、`DADataAnalysisNodes`

### Python i18n 标杆实现

参考 `plugins/DataAnalysis/PyScripts/DADataAnalysisGui/i18n/`，包含：
- `core.py`：语言检测与 gettext 加载
- `update_po.py`：从 `# cn:` 注释自动填充 `.po` 翻译
- `generate_i18n.py`：纯 Python 翻译文件生成器（无需 gettext 工具）
- `update-i18n.sh`：一键生成脚本

## Python 工作流节点（@NodeDef）i18n 规则

> ⚠️ **节点包 i18n 有特殊约束**，详见 [python-i18n.md](./python-i18n.md#节点包-nodedef-i18n) 的"节点包 i18n"章节

| 字段 | 是否翻译 | 原因 |
|------|---------|------|
| `@NodeDef(name=...)` | ❌ **不翻译** | `name` 参与 `qualified_name`（如 `DASystemNodes.Delay`）构成，翻译会破坏已存工程的节点匹配和序列化 |
| `@NodeDef(category=...)` | ✅ 翻译 | `category` 仅用于节点工具箱分类显示，不参与序列化 |
| `Parameter(description=...)` | ✅ 翻译 | 显示在属性面板 |
| `Input/Output(description=...)` | ✅ 翻译 | 显示在端口悬停提示 |
| 类 docstring | 改为英文 | docstring 作为 tooltip 显示，改为英文源文本（框架层翻译为后续改进） |
| `paint()` 中的硬编码文本 | ✅ 翻译 | 直接绘制到节点画面，用户可见 |
| `execute()` 中的错误消息 | ✅ 翻译 | 若显示给用户（如通过日志面板） |
| `execute()` 中的日志 | ❌ 不翻译 | 日志保持英文便于检索 |

**节点文件改写示例**：

```python
# -*- coding: utf-8 -*-
"""Delay for a specified number of seconds before passing data downstream."""  # docstring 改英文

import time
from DAWorkbench.DAWorkFlowPy import NodeDef, Input, Output, Parameter


@NodeDef(
    name="Delay",                            # name 保持英文，不翻译
    category=_("System / Flow Control"),     # cn:系统 / 流程控制
    icon="",
)
class DelayNode:
    """Delay for a specified number of seconds before passing data downstream."""

    seconds = Parameter(
        float,
        default=1.0,
        min=0.0,
        step=0.1,
        decimals=2,
        description=_("Delay in seconds"),   # cn:延迟秒数
    )

    class Inputs:
        trigger = Input("any", required=True, description=_("Trigger signal"))  # cn:触发信号

    class Outputs:
        done = Output("any", description=_("Output after delay, forwards trigger as-is"))  # cn:延迟完成后的输出，原样转发 trigger
```

### setup_i18n() 调用时机

`@NodeDef` 装饰器在模块导入时执行，若 `category` 参数使用 `_()`，则 `setup_i18n()` **必须在节点模块导入之前**调用：

```python
# DASystemNodes/__init__.py
# -*- coding: utf-8 -*-
"""DASystemNodes - System-level workflow node package."""

# ⚠️ 必须在节点模块导入之前调用 setup_i18n()
from .i18n.core import setup_i18n
setup_i18n()

# 之后才能导入节点模块（节点模块中使用了 _()）
from .nodes.data_to_manager import DataToManagerNode
from .nodes.text_viewer import TextViewerNode
# ...
```

## 不应翻译的内容

- **日志消息**（`daInfo`/`daWarning`/`daCritical`/`qWarning`/`logger.info`/`print` 调试输出）
- **序列化键名**（XML 标签名、JSON 键名、配置键名）
- **内部标识符**（枚举字符串值、注册键名、qualified_name）
- **`@NodeDef(name=...)`**（参与序列化，见上表）
- **代码注释**（Doxygen 注释保持中文，见 [coding-standard.md](./coding-standard.md) 注释规范）

## 翻译占位符安全（重要）

> ⚠️ **翻译文件中的占位符和文件过滤器通配符必须原样保留，不能丢失。**

Qt 的 `tr()` 支持 `%1`/`%2`/`%n` 等占位符，运行时通过 `.arg()` 替换。如果翻译文本丢失了这些占位符，`.arg()` 会静默失败，导致显示内容缺失或错误。同理，文件过滤器中的 `(*.ext)` 通配符如果被翻译丢弃，`QFileDialog` 将无法匹配对应文件。

**❌ 错误**（占位符丢失，曾导致 .dapro 文件无法在打开对话框显示）：

```xml
<source>Project File (*.%1)</source>
<translation>工程文件</translation>   <!-- 丢失了 (*.%1) -->
```

**✅ 正确**：

```xml
<source>Project File</source>
<translation>工程文件</translation>
<!-- C++ 中通配符不经过 tr()，见下文"文件过滤器写法" -->
```

### 文件过滤器写法（防御性）

文件对话框的过滤器通配符 `(*.ext)` **不要放进 `tr()`**，只翻译标签文本，通配符在 `tr()` 外部拼接：

```cpp
// ✅ 正确：通配符硬编码在 tr() 外部，翻译无法破坏
filters << tr("Project File") + QString(" (*.%1)").arg(DAAppProject::getProjectFileSuffix());
// cn:工程文件

// ❌ 错误：通配符在 tr() 内部，翻译若丢弃 (*.%1) 则过滤器失效
filters << tr("Project File (*.%1)").arg(DAAppProject::getProjectFileSuffix());
```

### 多 tr() 单行注释写法

一行中有多个 `tr()` 调用时，`// cn:` 注释用 `,cn:` 分隔，每个 `cn:` 对应一个 `tr()`（按源码顺序）：

```cpp
// ✅ 正确：两个 cn: 分别对应两个 tr()
QMessageBox::question(nullptr,
    tr("Warning"),                              // cn:警告
    tr("Whether to overwrite the file: %1")     // cn:是否覆盖文件:%1
);

// ❌ 错误：单行多 tr + cn 注释容易解析出错
QMessageBox::question(nullptr, tr("Warning"), tr("Whether to overwrite..."));  // cn:警告,cn:是否覆盖文件:%1
```

CI 会自动校验翻译文件的占位符匹配（见下文"翻译校验"），但最佳实践是在源头避免风险。

## 翻译工具链（`scripts/`）

> ⚠️ 本节内容**未在 i18n 基础设施对照表中体现**——`scripts/` 下的翻译辅助脚本是独立的一次性批量工具，不参与构建流程，但它们产出的翻译结果已提交到 `.ts` 文件。新贡献者需了解这套工具链的存在。

### `// cn:` 注释如何进入 .ts 文件

Qt 的 `lupdate` **不读取** `// cn:` 注释——它只提取 `tr()` 的 `<source>` 文本。`// cn:` 注释通过自定义脚本桥接到 `.ts` 文件：

```
C++ 源码 tr("English") // cn:中文
        │
        ├─[lupdate]──────────→ 提取 <source> 到 .ts（不读取 cn: 注释）
        │
        ├─[extract_cn_comments.py]→ 解析 cn: 注释 → _cn_map.json
        ├─[apply_cn_to_ts.py]────→ 用 _cn_map.json 填充 .ts 中 unfinished 条目
        ├─[apply_manual_translations.py]→ 用手工表填充剩余 unfinished
        ├─[merge_translations.py]→ 从 backup-da_zh_CN.ts 补充
        └─[lrelease]──────────→ .ts 编译为 .qm（构建时自动，CMake 目标 da_translations）
```

### 脚本说明

| 脚本 | 作用 |
|------|------|
| `scripts/extract_cn_comments.py` | 扫描 C++ 源码，提取 `// cn:` 注释，生成 `_cn_map.json` |
| `scripts/apply_cn_to_ts.py` | 用 `_cn_map.json` 填充 `.ts` 中的 unfinished 翻译（含占位符校验） |
| `scripts/apply_manual_translations.py` | 用手工翻译表 `_manual_translations.py` 填充剩余 unfinished |
| `scripts/dump_unfinished.py` | 导出未翻译条目，辅助手工填写 |
| `scripts/check_translations.py` | **翻译校验脚本**（CI 使用），检查占位符/cn:泄漏 |
| `scripts/translation_validate.py` | 共享校验模块（占位符/glob 匹配） |
| `src/i18n/merge_translations.py` | 从 `backup-da_zh_CN.ts` 合并翻译到当前 `.ts` |

### CMake 翻译构建目标

翻译的编译（`.ts` → `.qm`）和部署由根 `CMakeLists.txt` 的 `DA_ENABLE_AUTO_TRANSLATE` 选项控制（默认 ON）。统一使用显式 `lrelease` / `lupdate` 流程，兼容 Qt5 和 Qt6。

| CMake 目标 | 触发方式 | 作用 |
|------------|---------|------|
| `da_translations`（ALL） | 每次构建自动执行 | `lrelease` 编译 `.ts` → `.qm`，并复制到 `${CMAKE_BINARY_DIR}/bin/translations/`（从 build 目录运行程序时加载翻译的位置）；同时绑定到 App 目标（`add_dependencies`），构建 App 时也会触发 |
| `update_translations` | 手动触发 | `lupdate` 从 C++ 源码提取 `tr()` 字符串到 `.ts` 文件。不加入 ALL，避免每次构建重写 `.ts` |

**日常开发流程**：

1. **修改/新增 `tr()` 字符串** → 运行 `cmake --build <build-dir> --target update_translations` 更新 `.ts`
2. **编辑 `.ts` 添加翻译**（用 Linguist 或 `apply_cn_to_ts.py` 脚本）
3. **普通构建** `cmake --build <build-dir>` → 自动检测 `.ts` 变化，重新编译 `.qm` 并部署到 `bin/translations/`
4. **安装** `cmake --install <build-dir>` → `.qm` 安装到 `<prefix>/bin/translations/`

> ⚠️ `lupdate` 不会自动运行——新增 `tr()` 字符串后必须手动执行 `update_translations` 目标，否则新字符串不会出现在 `.ts` 中。这是有意设计，避免每次构建重写 `.ts` 产生噪音 diff。

### 翻译校验

CI（`.github/workflows/build.yml`）在编译前自动运行 `scripts/check_translations.py`，检查：

1. **占位符匹配**：`%1`/`%n` 等 Qt 占位符在 source 和 translation 中的数量必须一致
2. **通配符匹配**：`(*.ext)` 文件过滤器通配符不能在翻译中丢失
3. **cn: 泄漏检测**：翻译文本中不能包含字面 `cn:` 标记

本地可手动运行：`python scripts/check_translations.py`

## i18n 基础设施对照

| 组件 | C++ / Qt | Python |
|------|---------|--------|
| 翻译工具 | Qt Linguist (`lupdate` / `lrelease`) | GNU gettext (`xgettext` / `msgmerge` / `msgfmt`) |
| 源文件 | `.ts` (XML) | `.po` (文本) |
| 编译文件 | `.qm` (二进制) | `.mo` (二进制) |
| CMake 集成 | `DA_ENABLE_AUTO_TRANSLATE` (主程序)、`da_translations` / `update_translations` 目标 | 无 CMake 集成，`.mo` 作为普通文件随包安装 |
| 运行时加载 | `QTranslator` + `DATranslatorManeger` | `gettext.translation()` + `trans.install()` |
| 参考实现 | `src/APP/` (主程序)、`plugins/DataAnalysis/` C++ 部分 | `plugins/DataAnalysis/PyScripts/DADataAnalysisGui/i18n/` |
