## 一、NeoGraph 构建集成

### 1.1 引入方式

NeoGraph 位于仓库外（`C:\src\Qt\3rdparty\NeoGraph`），不是本仓库 submodule。采用**缓存变量 + `add_subdirectory`** 方式引入（不使用 `find_package`，保持源码级集成与调试能力）：

```cmake
# 顶层 CMakeLists.txt（在 add_subdirectory(src) 之前，约 :90 附近）
# NeoGraph 路径可被 -DNEOGRAPH_PATH=... 覆盖，便于 worktree/CI 定制
set(NEOGRAPH_PATH "" CACHE PATH "Path to NeoGraph sources")
if(NOT NEOGRAPH_PATH)
    set(NEOGRAPH_PATH "C:/src/Qt/3rdparty/NeoGraph")
endif()

# 必须在 DAAgent target 定义前，使 neograph::core/llm 目标可见
if(EXISTS "${NEOGRAPH_PATH}/CMakeLists.txt")
    set(NEOGRAPH_BUILD_EXAMPLES OFF CACHE BOOL "" FORCE)
    set(NEOGRAPH_BUILD_TESTS OFF CACHE BOOL "" FORCE)      # 默认即 OFF，显式钉死
    set(NEOGRAPH_BUILD_POSTGRES OFF CACHE BOOL "" FORCE)   # 关键：默认 ON 且 find_package(PostgreSQL REQUIRED)
    set(NEOGRAPH_BUILD_SQLITE OFF CACHE BOOL "" FORCE)     # 关键：默认 ON 且 find_package(SQLite3 REQUIRED)
    set(NEOGRAPH_BUILD_PYBIND OFF CACHE BOOL "" FORCE)
    set(NEOGRAPH_BUILD_PROGRAM OFF CACHE BOOL "" FORCE)    # 默认 OFF，显式声明
    set(NEOGRAPH_INSTALL_EXPORT OFF CACHE BOOL "" FORCE)   # 避免 NeoGraph install 规则注入本工程（默认 ON，见其 CMakeLists:2313-2321）
    add_subdirectory("${NEOGRAPH_PATH}" "${CMAKE_BINARY_DIR}/_neograph")
endif()
```

!!! warning "CMake 选项以源码为准"
    上列选项名与默认值基于 NeoGraph v0.12.1 的 `CMakeLists.txt` 核实（`NEOGRAPH_BUILD_TESTS :2175`、`EXAMPLES :140` 默认 ON、`POSTGRES :138`+find_package 门 `:456-463`、`SQLITE :139`+find_package 门 `:452-454`，即 option 默认值与 REQUIRED 检查处不同）。**实施时先打开 `${NEOGRAPH_PATH}/CMakeLists.txt` 的 option 区逐项确认**，若存在 gRPC/protobuf 等其它 `find_package(REQUIRED)` 选项一并 OFF。配置阶段输出（CMakeCache）是最终裁判：不得出现 `Could NOT find PostgreSQL` 之类错误。

### 1.2 DAAgent 链接

在 `src/DAAgent/CMakeLists.txt` 增加（保持既有 PUBLIC 依赖不变）：

```cmake
target_link_libraries(DAAgent
    PRIVATE
        neograph::core      # 图引擎：yyjson、asio（均为 PUBLIC 传递）
        neograph::llm       # OpenAIProvider/Agent（内部 PRIVATE httplib/OpenSSL）
)
# DAAgent 内部源码以 C++20 编译（neograph_core PUBLIC cxx_std_20 亦会强制传播）
target_compile_features(DAAgent PRIVATE cxx_std_20)
```

要点：

- `neograph::llm` 内部以 **PRIVATE** 链接 OpenSSL（`CMakeLists:889-892`，仅链接期传播）——本机若缺 OpenSSL，阶段 0 首个任务就是确认 `neograph_llm` target 能否配置（NeoGraph 用 `find_package(OpenSSL)`，缺库则配置失败；备选：先只链接 `neograph::core`，LLM 能力推迟到阶段 3 前解决——**但阶段 0 spike 需要真实 LLM 时才需要 llm**，Mock Provider spike 只需 `core`）。
- 生成器必须是 Visual Studio（项目铁律：Windows 禁用 Ninja）。
- 首次配置若报 NeoGraph 内部错误，先单独验证：`cmake -S <NEOGRAPH_PATH> -B build-ng-check -G "Visual Studio 16 2019" -A x64 -DNEOGRAPH_BUILD_EXAMPLES=OFF -DNEOGRAPH_BUILD_POSTGRES=OFF -DNEOGRAPH_BUILD_SQLITE=OFF`。

### 1.3 双轨开关

```cmake
# 顶层 CMakeLists.txt
option(DA_AGENT_NATIVE "Use native NeoGraph agent runtime (replaces Python langgraph)" ON)
if(DA_AGENT_NATIVE)
    add_compile_definitions(DA_AGENT_NATIVE_RUNTIME)
endif()
```

- 阶段 1-4 期间该宏控制新旧运行时择一编译（旧路径保持可回退）。
- 阶段 5 删除旧路径后，**连同本 option 一并删除**（终态不留双轨）。
- 单测/CI 可用 `-DDA_AGENT_NATIVE=OFF` 回退旧实现做对照。

## 二、C++20 策略落地与污染检查（决策 A4）

### 2.1 原则

- 根 `CMakeLists.txt:94` 的 `CMAKE_CXX_STANDARD 17` **不改**；APP、DAGui、插件、DAPyWorkFlow 等全部维持 C++17。
- 仅 `DAAgent` target 升 C++20。MSVC 下标准是 per-TU 编译选项，混用安全。
- **NeoGraph 头文件白名单**：只允许出现在 `src/DAAgent/*.cpp` 与 `src/DAAgent/*Private*.h`。以下公共头**绝对禁止** include `neograph/*` 或出现 C++20 语法（`requires`/`concept`/`<ranges>`/结构化绑定进宏等）：
  - `DAAgentInterface.h`、`DAAgentAPI.h`、`DAAbstractAgentTool.h`、`DAAgentToolSpec.h`、`DAAgentConfig.h`、`DAAgentProvider.h`、`DAAgentPermissionConfig.h`、`DAAgentPrompt.h`、`DAAgentPromptOps.h`、`DAAgentSubagentDef.h`、`DAAgentSubagentManager.h`、`DAAgentPermissionManager.h`、`DAAgentToolExecutor.h`、`DAAgentSessionStore.h` 等**已导出头**。

### 2.2 污染检查清单（阶段 0 执行一次并记录结果）

1. `grep -r "neograph" src/DAAgent/*.h` —— 允许命中的只有未来新增的私有实现头（文件名含 `Private` 或位于 `src/DAAgent/runtime/` 子目录且不被公共头 include）。
2. 编译 APP target：`.\scripts\build.ps1 -Target APP`（保持 C++17）通过。
3. 编译一个插件 target（如 `DAAgentTools`）通过。

!!! warning "Qt5 moc 与 C++20"
    DAAgent 的 `Q_OBJECT` 头以 C++20 编译通常无问题，但若 moc 生成代码在 `/std:c++20` 下报错（罕见），备选方案：把新运行时拆成独立静态库 `DAAgentRuntime`（C++20、无 Qt 公共头），DAAgent 链接它且公共头仍零污染。**阶段 0 spike 若遇到此类错误立即切换该备选**，不要在 moc 问题上纠缠。

## 三、Spike 验证（新增临时目标 `DAAgentNeoSpike`）

在 `src/tst/` 下新建 `DAAgentNeoSpike/`（Qt Test 或普通可执行均可，参照 `src/tst/CMakeLists.txt` 注册），集中验证 9 项关键假设（V1-V9；V7-V9 是 02/03/04 标注的"阶段 0 补验"项，必须有结论）。**spike 代码即阶段 1-2 的雏形，允许直接演化为正式代码，但阶段 0 期间不得接入 DAAgentModule。**

### V1：图构建 + interrupt/resume（对应 ask_user）

用 `examples/04_checkpoint_hitl.cpp` 的模式：Mock Provider（首响应返回 tool_call、次响应返回文本）+ JSON 图（`channels: {messages: {reducer:"append"}}`、节点 `llm` + `tools`、`interrupt_before` 或节点内 `throw NodeInterrupt`）+ `InMemoryCheckpointStore`。断言：

1. 首次 `engine->run(config)` 返回 `result.interrupted == true`，`interrupt_node` 正确；
2. `engine->resume(thread_id, json("answer"))` 恢复执行到底；
3. **验证 resume value 的双重去向**：NeoGraph 会把 resume value 同时放进 `RunContext::resume_value` **且**（图有 `messages` channel 时）作为 `{"role":"user"}` 追加（`graph_engine.cpp:1299-1311`）——记录实际行为，决定阶段 2 的 ask_user 节点是否需要避免重复 user 消息（当前 Python 实现中答案只进 interrupt value，不重复追加为 user 消息，T8 语义）。

### V2：流式 token 事件与回调线程

`run_stream` + `GraphStreamCallback`，Mock Provider 经 `complete_stream` 多次回调 chunk。断言：

1. 收到 `GraphEvent{Type::LLM_TOKEN}` 且 token 序列完整（**data 是 token 字符串**：`event.data.is_string()` 为真、`event.data.get<std::string>()` 逐条累积，不是 `data["token"]` 对象取键）；
2. **回调线程 == 调用 `run_stream` 的线程**（在池线程调用则回调在池线程）——这是"池线程内经 `QMetaObject::invokeMethod` 投递主线程 emit `agentToken`"设计的前提。

### V3：多 thread_id 并发（多会话模型）

`QThreadPool` 起 2-3 个任务，各自 `engine->run()` 不同 `thread_id`（Mock Provider 延迟 200ms）。断言：全部完成、互不串扰（读回各自 `get_state(thread_id)` 比对 messages）。

### V4：`update_state` 注入历史（等价 `load_session`）

构造历史 messages 数组，`engine->update_state(thread_id, {{"messages", ...}})` 后 `run(resume_if_exists=true)` 断言 LLM 收到的 `CompletionParams.messages` 包含历史——这是"切换会话无需重建"的基础。

### V5：阻塞等待-唤醒（工具 RPC 桥可行性）

模拟工具执行：主线程 `QTimer`/`invokeMethod` 处理一个请求，池线程等待结果。验证无死锁、可被 stop 中断（`QWaitCondition + QMutex` 或 `std::promise/future` + `wait_for`）。这是决策 A2 的技术前提：**池线程阻塞收 `tool_result`，主线程执行工具**。

### V6：真实 LLM 冒烟（可选，有 key 时）

`OpenAIProvider::create({api_key, base_url, default_model})` + `run_stream` 打一句真实请求，确认：流式 chunk、末 chunk `usage`（`stream_options.include_usage` 自动注入）、超时行为。可用项目现有 `agent-config.json` 的配置读取（只读测试，不落日志明文 key）。

### V7：工具集 run 前注入方式（02 §二"工具集热更新"的前置结论）

验证 build 之后工具集能否热更：`EngineResources.tools`/`NodeContext` 是否可在每次 `run` 前修改生效，还是 `GraphEngine::build` 后固定。断言给出唯一结论（"可热更"→02 选型 1；"必须重建"→02 选型 2 惰性重建），并把结论回填到 `02-阶段1` §二"工具集热更新注意点"。

### V8：`CompletionParams::cancel_token` 类型与语义（04 §1.3 的前置结论）

查 `include/neograph/provider.h:76` 确认 cancel_token 的确切类型（回调 / `shared_ptr<atomic<bool>>` / 其它）与置位后 `complete_stream` 的中断表现（立即终止、抛错还是自然收尾）。结论回填 `04-阶段3` §1.3。

### V9：递归步数限制字段（03 §四的前置结论）

确认 `RunConfig` 步数限制字段（`engine.h:147` 附近 `max_steps`）与图级 `retry_policy` 的计数语义是否等价 langgraph `recursion_limit`（单回合内计数、超限报错）。结论决定 `03-阶段2` §四该行走"首选内建"还是"节点内计数"分支。

## 五、风险与回退

| 现象 | 处理 |
|------|------|
| PostgreSQL/SQLite find_package 失败 | 检查 options 是否 FORCE 生效（CMakeCache），选项名以 NeoGraph 源码为准 |
| OpenSSL 缺失导致 `neograph::llm` 配置失败 | 阶段 0 spike 仅用 `neograph::core`（Mock Provider）；阶段 3 前解决 OpenSSL（vcpkg/官方预编译），这是**硬依赖**不可绕过（httplib TLS） |
| C++20 与 Qt5 moc 冲突 | 启用 2.1 备选：`DAAgentRuntime` 独立 C++20 静态库 |
| asio 链接错误（ws2_32 未解析） | 检查 NeoGraph 的 asio INTERFACE target 是否带 `WIN32_LEAN_AND_MEAN`/`ws2_32`；缺则在 DAAgent 补 `target_link_libraries(DAAgent PRIVATE ws2_32 mswsock)`（仅 WIN32） |
| NeoGraph configure 慢/生成过大 | 确认 EXAMPLES/TESTS 均 OFF；`add_subdirectory` 用独立 binary dir（本文已指定） |

回退：本阶段全部改动可通过还原 3 个 CMakeLists 修改 + 删除 spike 目录撤销，不影响现有任何运行时行为。
